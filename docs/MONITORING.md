# MES 异常监控(监控中心 · 画布归因 · 执行轨迹)

产线出异常时,监控体系回答四个问题:**哪里有异常 → 卡在哪个节点 → 为什么卡 → 刚才发生了什么**。

## 入口

- **监控中心**(导航「监控中心」,`/#/monitor`):常驻页,可挂大屏。顶部通道健康色块,下方异常工作队列。
- **MES 画布**:节点按异常着色;右上角「⚠ N 异常」徽章点击在异常节点间循环跳转;选中异常节点右侧自动展开归因面板;工具栏「时间线」开关执行轨迹。
- 监控中心条目点「定位画布」→ 自动切到对应任务画布并把肇事节点居中、展开归因。

## 颜色语义(全站统一,ISA-18.2 精神)

| 颜色 | 含义 | 出现条件 |
|---|---|---|
| 🔴 红 | 失败 / 根因离线 | 节点执行失败(含重试中)、设备连接中断。**红=需要现在处理** |
| 🟠 橙 | 卡住 | 等待/执行超过判定阈值(见下) |
| 🟡 黄 | 慢于基线 | 超过历史 P95 基线但未到卡住阈值(预警) |
| 🟢 绿 | 正常 | — |

## 卡住判定规则

**核心语义:等待不是异常,永不报警。** 触发节点在等条件(等来料、等完成标志)、条件节点在等复位,都是产线常态——无论等多久都不判"卡住"、不进异常中心;画布上只给灰色信息标注(在等什么、差哪个条件),让你看得到但不被打扰。

- **只有"执行停滞"才判卡**(run 状态:上报/回写/延时执行中挂住):引擎在线学习每节点"单次执行耗时"P95(P² 算法,零额外内存),**执行超过 P95 × 3 判卡住**;超过 P95 未到 3 倍显示黄色"慢于基线"。
- **手工阈值**(可选,仅作用于执行状态):给节点配 `卡住阈值(ms)`(工程字段 `stuckThresholdMs`)后优先于自动基线。
- **冷启动保护**:执行耗时样本不足 20 个不启用自动判定(刚启动/极稀疏任务不误报)。
- **重试中 = 仍在失败**:节点连续失败后进入重试窗口(run)期间,异常条目与红色保持,不闪烁。
- 执行完成(成功或失败落定)后,卡住标记自动解除。

## 等待条件的表达(触发/条件节点)

条件操作符除 `= ≠ > ≥ < ≤ 正则` 外,另有两个面向多变工况的:

- **∈任一(In)**:期望值填逗号分隔列表(如 `2,5,7`,中英文逗号均可)——同一点位不同工况等不同目标值时,值命中任一即满足;数值按数值比较(5.0 命中 "5")。
- **变化(Changed)**:不填期望值,点位值发生变化即满足。锁存语义:启动首见只记基准不触发;变化发生时即使同组其他条件未就绪也不丢,等就绪后照常触发;整组触发后才更新基准。

触发节点的条件可直接在画布右侧配置面板编辑(不填条件 = 按采集周期定时触发)。条件节点当所有分支都不满足且「默认」口未接线时,视为"在等分支条件",画布标 wait 并逐分支给出"期望 vs 实际"。

## 归因面板(为什么卡住)

按异常类型给出结构化"期望 vs 实际":

- **等待触发/条件**:逐条件列出 点位、期望值、当前实际值、是否命中——未命中的就是卡住原因;点位质量异常(设备断连)会标明"(质量 Bad)"而不是展示陈旧值。
- **HTTP 上报失败**:HTTP 状态码(0=网络层失败)、目标地址、已重试次数、响应/错误片段(截断 512 字符)。
- **回写失败**:逐点列出 下发值 vs 读回值、重试次数。

## 监控中心规则

- **排序** = 严重度(设备离线 > 失败 > 卡住 > 慢于基线)→ 波及任务数 → 持续时长;不按时间流水刷屏。
- **根因折叠**:设备离线时,能归属到该设备的任务/节点异常自动折叠为其子项(依据:任务引用点位的 `通道.设备` 前缀与任务的 DeviceRef);归属不明的异常独立展示,宁可不折叠也不折错。
- **搜索**:按 设备名 / 任务名 / 节点标题 / 点位路径 子串过滤。
- **通道色块**:取块内最严重级别着色 + 异常计数;点击按通道过滤下方清单。

## 执行轨迹(时间线)

画布工具栏「时间线」打开侧栏:按轮次(一次触发到下一次触发前)分组展示节点流转——时刻、节点、结果、耗时;失败行红色;点击行聚焦画布节点。

- 数据为每任务内存环形缓冲,**最近 256 条、服务重启清空**(界面已注明)。

## REST 端点

| 端点 | 说明 |
|---|---|
| `GET /api/v1/anomalies?q=` | 异常中心聚合(根因折叠 + 排序 + 通道色块数据) |
| `GET /api/v1/mes` | 任务/节点状态快照(节点含 `stuck`/`baselineMs`/`failStreak`/`detail` 归因) |
| `GET /api/v1/mes/timeline?task=任务名` | 节点流转事件(时间正序) |

兼容性:以上均为增量字段/新端点,旧客户端不受影响;旧 `.igwproj` 无需修改即可加载。

## 百万点工程存储基准

SQLite 工程仓储的独立基准用于验证大点表导入、分页查询、单点事务更新和一致性导出准备。默认生成 1,000,000 个点，不连接 PLC，也不把结果冒充现场周期性能。

```powershell
dotnet run --project benchmarks/IGW.ProjectStorage.Performance -c Release -- --points 1000000 --output artifacts/project-storage-million.json
```

输出 JSON 记录 `points`、导入耗时、分页 P50/P95、单点更新耗时、导出准备耗时、进程峰值工作集、数据库字节数和最终修订号。验收时点数必须精确一致、修订号必须递增、各大小和耗时指标必须为实测非零值；不同硬件只比较相同环境下的趋势，不使用未经现场验证的固定毫秒 SLA。
