# 采集性能与标签扫描耗时

打开顶部导航“采集性能”，查看各设备的速度概览。选择一台设备后可以按标签路径筛选最近的采集批次，并展开一行查看这一批实际包含的标签。

## 时间口径

| 指标 | 含义 |
| --- | --- |
| 设定周期 | 活动轮询使用扫描计划的有效需求周期；待机或纯订阅显示标签配置。混合模式的范围只包含轮询周期。 |
| 平均完成间隔 | 最近 60 秒内同一采集块两次完成之间的平均时间；不同采集块分别计算后汇总。 |
| P95 完成间隔 | 最近 60 秒的间隔直方图估计上界，页面标“约”。 |
| 实际开始间隔 | 这一采集块本次开始减去上次开始；首次采集没有可比较的上次时间。 |
| 驱动读取耗时 | 从调用驱动读取到它返回或抛出异常的时间，包含驱动内部等待、请求拆包、网络通信及重试。 |
| OPC UA 请求数 | 本批周期读取实际发出的 SDK 请求数量；逻辑读取可能拆成多次请求。 |
| 协议请求累计 / 最大耗时 | SDK 请求从调用到完成、失败或取消的累计与最长耗时；并发请求累计值可能大于本批墙钟耗时。 |
| 排队耗时 | 等待共享连接请求名额、驱动内部并发名额的累计时间，与实际 SDK 请求耗时分别统计。 |
| 失败 / 取消请求数 | 本批协议请求的失败及取消次数；收到响应但部分点质量差不等于整次请求失败。 |
| 本地处理耗时 | 驱动返回后，网关发布数据与更新诊断的时间。 |
| 总耗时 | 从批次开始到本地处理结束的墙钟耗时，按整数毫秒显示；在正常计时取整范围内，`总耗时 = 驱动读取耗时 + 本地处理耗时`。重连、日志输出和等待下一次调度不计入其中。 |
| 队列 P95 | 最近最多 200 个保留批次中共享队列等待时间的 P95。没有协议计时的批次不提供该值。 |
| 协议请求 P95 / 最大 | `ProtocolRequestP95Ms` 是最近最多 200 个保留批次各自 `RequestMaxMs` 的 P95，不是把每个原始协议请求汇总后计算的 P95；“最大”是这些批次中最大的 `RequestMaxMs`。 |
| 网络 RTT P95 / 丢包 | 只取最新批次所关联网络窗口的 ICMP 统计；最新批次没有网络窗口或最新 RTT 为空时保持“不可用”，不会沿用较旧值或补零。 |
| 本地处理 P95 | 最近最多 200 个保留批次本地处理耗时的 P95。 |
| 超期 / 漏期 | 读取完成时已经跨过的计划周期数量。既可能是读取耗时过长，也可能是该批开始前已经排队延迟。 |
| 轮询吞吐 | 最近窗口内收到的轮询样本数/秒，包括质量差的样本；不包含订阅变化通知。 |

计时使用网关的单调时钟，列表开始时间使用网关系统时间，显示到毫秒。它衡量 IGW 的采集过程，不代表 PLC 程序的 OB1 扫描周期。

一次驱动调用可能读取多个标签，也可能在内部拆成多个协议请求。同一批标签共享本批耗时；按某个标签筛选后仍保留原批次时间，不将时间除以标签数量作为“单标签耗时”。

驱动读取耗时是 IGW 调用驱动到驱动返回或抛错的外层时间。它可能包含共享队列等待、一个或多个协议调用、拆批/降批、同会话重试和驱动自身处理。队列时间与协议请求时间是驱动耗时内部的分层证据，不能再次相加到总耗时；并发请求的累计耗时也可能超过驱动墙钟耗时。

OPC UA 单次请求耗时覆盖客户端调用、网络往返、PLC 或 OPC UA 服务器排队与处理以及响应返回。客户端没有服务器内部时间戳，不能把它拆成“纯网络耗时”和“PLC/服务器处理耗时”，也不能当作 PLC 程序执行或 OB1 扫描时间。ICMP RTT 只测辅助的 IP 可达性和往返延迟，不等于 OPC UA TCP 请求耗时。

批次点数、成员和坏点数按本次实际请求统计。连续无效点进入低频复查后，不再计入正常批次；例如 59 点中隔离 13 点，正常批次显示实际请求的 46 点。低频复查发生时，参与本次周期读取的复查点才重新计入。非 OPC UA 驱动没有协议级计时时显示“—”。

订阅由服务器推送变化，没有每次主动 Read 的往返时间。通知间隔不能替代 PLC 实际采样周期；纯订阅设备会明确显示无主动轮询。这份历史只记录周期轮询，订阅初始化读取、恢复探测以及写入校验不在本列表内。

## 存储与负载

每台设备保留最近 200 条已结束的周期轮询记录，包含正常、部分失败、质量差和读取异常。取消及为写入让出的未完成读取不作为完整批次记录。历史仅保存在内存中，重启或重建运行引擎后清空；它不是长期归档日志。

页面每 2 秒读取诊断缓存；收起面板、隐藏浏览器页面或离开页面时停止刷新。查看性能不会激活待机 PLC、增加 PLC 请求，也不会逐批写磁盘日志。

网络探测按活动物理端点 `(远程 IPv4, 本地源 IPv4)` 共享，同一端点的逻辑设备复用一个后台任务。默认每 5 秒一次、单次超时 1 秒，整个宿主最多并发 8 个 ICMP，且每个活动端点只保留最近 120 个样本。探测器不进入 OPC UA 会话、共享请求调度器或 PLC 点位读写路径。

Windows 且明确绑定源 IPv4 时会验证探测路由；平台或路由条件不能保证源地址时显示“路由未验证”。ICMP 被禁、目标不响应、地址无法解析、权限不足或探测取消时显示“不可用”。这两种状态都不能支持网络或 PLC/OPC UA 服务器归因。批次只关联完成时刻之前 30 秒的探测样本，不使用完成后的未来样本。

## 分层归因

归因只使用已经完成并保留的采集批次和网络样本。协议基线先从当前批次之前的保留记录中取每批 `RequestMaxMs`，再计算 P95；当前批次不参与自己的基线。协议最大请求耗时必须同时达到基线的 1.5 倍并至少增加 20 ms，才算相对基线变慢。没有先前基线时保留测量值，但不判断“网络链路疑似”或“PLC/OPC UA服务器疑似”。

- 本地处理至少 50 ms 且占总耗时至少 20%：`IGW本地处理`，直接计时证据。
- 共享队列至少 100 ms 且占驱动耗时至少 40%：`IGW共享队列`，直接计时证据。
- 网络窗口至少有 6 个有效样本并且路由已验证；出现丢包，或最新 RTT 同时达到此前网络 P95 的 3 倍并至少增加 20 ms，且协议请求也相对基线变慢：`网络链路疑似`。
- 网络窗口至少有 6 个成功样本、无丢包、RTT 稳定且路由已验证；队列和本地处理未达到阈值，协议请求相对基线变慢，且 `RequestMaxMs` 至少占总耗时 70%：`PLC/OPC UA服务器疑似`。
- 请求数大于 1、请求失败/取消、同会话重试或批量降级：增加 `请求拆分或重试` 因素。

直接计时的 IGW 本地处理和共享队列优先于疑似结论，其他同时命中的项仍保留为因素。缺少协议计时、缺少先前协议基线、网络少于 6 个有效样本、样本计数不完整、路由未验证、网络不可用，或缺少 RTT/丢包指标时显示 `证据不足`。这些规则提供定位线索，不单独证明现场网络、PLC 程序或 OPC UA 服务器是根因。

## 导出诊断包并对照 KEP

在“采集性能”页选择“导出性能诊断”。ZIP 固定包含以下 5 个条目：

- `summary.json`：抓取时间、构建/工程标识、保留批次的 `from`/`to` UTC 范围、设备概览、缺失源和截断标记。
- `batches.csv`：批次、IGW 路径、编译后的 PLC 地址/NodeId、各层耗时、协议计数、网络窗口、归因、证据和因素。
- `network.csv`：导出时仍活动的端点所保留的 ICMP 样本。
- `connection-diagnostics.json`：当前及最近恢复的连接异常。
- `README.txt`：字段定义、容量限制、安全处理和归因限制。

导出复制内存快照，不读取或写入 PLC，不新建会话，不进入共享调度器，也不新建网络探测任务。`network.csv` 只收集导出时仍活动的探测工作器；端点租约已经释放时，其旧样本可能不在包内。任一数据源缺失仍生成 ZIP，并在 `summary.json.missingSources` 中列出；空数值和 JSON `null` 表示不可用，不表示 0。

CSV 使用 UTF-8、RFC 4180 转义和不变区域数字格式。为防止表格公式执行，文本原值以单引号开头，或第一个非空白/控制字符是 `=`、`+`、`-`、`@` 时，导出器会在单元格最前再加一个单引号。解析 RFC 4180 后，只移除文本单元格的第一个单引号即可还原；没有首单引号则原样保留。数值和时间不做该转换。

密码、授权头、Cookie、MES 请求/响应体、URL 用户信息及常见令牌尾部会在自由文本中替换为 `[redacted]`；未知结构化正文也会移除。自由文本最多保留 8192 个源字符，证据和因素列表最多 64 项（发生裁剪时最后一项为 `[truncated]`）。工程名、设备/IGW 路径、NodeId、源/远程地址属于定位标识，不按自由文本规则截短，但仍受 ZIP 总容量限制。

与 KEP 对照时先读取 `summary.json` 的 `from` 和 `to`，按 ISO 8601 UTC 在 KEP 日志中选择同一闭区间；如果 KEP 日志显示本地时间，先按现场时区换算成 UTC，并保留原始时区和偏移。再用 `batches.csv` 的 `StartedAt`、设备/IGW 路径和 NodeId 定位同一请求，比较 KEP 的请求/会话事件、错误码和耗时。`CapturedAt` 是诊断包生成时刻，不能代替批次范围；两侧没有覆盖同一 UTC 区间时，不作根因结论。

## 自动生成标签窗口

窗口分别显示连接并读取根节点、展开分支、扫描选中分支的经过时间，成功与失败均保留本次耗时。端到端时间包含连接/会话等待与浏览响应传输；服务器扫描耗时和扫描节点数只有服务端提供时才展示。

普通 UDT 父节点不能整体解码时，浏览继续导入其成员；DTL 保持整体类型识别。现场 PLC 尚需用新版核对具体数据，模拟测试中的延迟不是现场性能结果。

## QC 点位监控

QC 的值列后新增“最近批次耗时”。它显示该标签最近一次参与的周期采集批次总耗时，悬停可看批次开始时间、驱动/本地耗时、设定周期/实际开始间隔和该批点数。批量读取中的标签共享批次时间，不能把它解释为当前 SSE 值单独读取的时间。

订阅点显示“订阅推送”，没有历史显示“—”；停止轮询的点可查看历史批次，悬停会明确注明。无效点被隔离后仍保留它最后实际参与的批次时间，不套用正常点后续批次；记录超出内存保留范围后显示“—”。

每个 QC 窗口只为当前虚拟表可视行及少量相邻行查询缓存，每次最多 200 点，上一请求完成后约 2 秒再刷新。滚动合并请求，切组、最小化、隐藏页面或关闭窗口时取消并停止；查询失败清理显示并提示暂不可用。整个过程不激活额外点位、不新增 PLC Read。
