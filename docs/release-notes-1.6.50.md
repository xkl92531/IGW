# IGW 1.6.50 发布说明

> 此安装包已由 1.6.51 替代。1.6.51 修复了大型工程分页树中标记组拖动失效，并在移动时迁移 MES 任务引用。

发布日期：2026-09-13

## 日志内容改造

- 所有新写入 OpenObserve 的 IGW 运行日志都带有模块、功能、事件类型和日志来源；已有结构化业务字段优先，不会被默认值覆盖。
- PLC 采集批次会显示通道、设备、数据块、采集来源以及对应的采集任务名称和 ID。多个任务复用同一物理读取批次时只记录一次，并保存有界的任务列表。
- MES HTTP 上报会记录采集任务、流程节点、请求方向、协议、方法、目标接口、HTTP 结果、业务判定和耗时。
- IGW REST 与 SignalR 调用会记录稳定路由、实际目标、操作、方向、协议、结果和耗时，便于区分哪个功能调用了哪个接口。
- 日志内容不保存认证信息、密码、令牌、Cookie 或完整请求/响应正文。

## 日志中心界面

- 原先挤在同一行的筛选条件改为两层：常用区保留关键词、时间、级别和操作；高级区按需展开模块、功能、PLC 范围、任务、接口和 Trace ID。
- 日志列表无需打开详情即可看到模块、功能、任务、接口操作、PLC 范围和采集来源。
- 事件详情按固定顺序展示任务名称、节点名称、接口、方向、协议、路由、采集范围和耗时等结构化字段。
- 新增“系统运行”分类；升级前的旧日志缺少新字段时会显示“未知”，字段不存在时查询会自动使用兼容模式，不会让整个日志页失败。

## 性能与兼容性

- 日志上下文由统一日志提供器和已有采集需求快照补充，不增加 PLC 读取，不改变采集周期，也不为共享批次重复生成记录。
- 任务归属按任务紧凑保存，并在扫描计划变化时预计算到物理读取批次；采集热路径只读取批次缓存。界面字段最多列出 32 个任务，但真实任务总数和全部来源类型会单独保留，并标明列表是否截断。
- 保持 IGW Web/API 端口 `48020`；OpenObserve 仍优先使用本机 `28020/28021`，占用时自动选择下一组连续空闲端口。

## 验证边界

- 自动化验证使用 TestServer 和模拟数据完成，没有连接现场 PLC。
- 升级前已经存入 OpenObserve 的历史记录不会被反向补写模块、任务和接口字段；缺失的模块和功能统一显示为“未知”。
