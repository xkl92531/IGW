# QuestDB 日志中心操作与验证

本功能在 `codex/questdb-logs` 分支开发。主仓库和 6.75 现场服务未更改。

## 现场怎么安装和使用

使用包含 QuestDB 的 IGW Windows 安装包，照常选择程序目录、工程数据目录和日志目录。安装包携带 QuestDB 10.0.1 及它需要的 Java，现场无需联网下载、另装 Java、启用 WSL 或安装 Docker。由 IGW 启动和监督自己的数据库进程；网页地址、登录、采集配置和日志中心的操作方式保持原样。

Linux 原生安装包同样捆绑数据库运行时，使用包内 `install.sh` 安装服务。Docker 部署包在 IGW 容器中捆绑同一版本，不另开外部数据库端口。当前实现针对 x86-64；本次原生实测系统为 Windows 10 22H2。Linux 已验证发布编译和运行包哈希/布局，尚未在 Linux 主机进行启动验收；旧 Windows Server 也需要按现场实际版本验收。

进入“日志中心”后，照常选择分类、时间、设备、任务、级别或关键词。查询保持区分大小写；工程配置的“查看日志”仍匹配该项及其下级，PLC6 不误匹配 PLC66。接口报文仍支持分页、发送/返回内容、完整下载及随日志导出。

1.7.20 更新“打包导出”：弹窗明确显示当前 QuestDB 数据来源，按时间和已应用的筛选导出数据库日志记录。默认 JSONL（`logs.jsonl`），一行一条，完整保留时间、级别、分类、消息、排障编号、报文编号和全部属性及其原始数据类型。可切换 CSV（`logs.csv`，attributes 列为完整 JSON）或可读文本（`logs.txt`）。ZIP 同时包含接口报文（可选）、`manifest.json` 和说明文件。清单注明数据来源 `questdb`、网关版本、格式、条数、范围和筛选；导出文件名带格式与本次生成时间，避免和前次导出混淆。

升级首次启动会静默后台读取旧 `.seg/.idx/.jsonl`，导入数据库，页面照常展示新日志和已经入库的旧日志；在“日志设置”里可查看后台进度。旧文件不会因导入立即删除；达到设置的保留期后，维护任务清理过期旧段。旧载荷文件继续兼容读取。历史未导完时导出仍等待历史就绪，避免产生看似完整的缺失历史包。不要在导入期间手动删除旧段或缓存。

2026-10-09 补充：继续使用“日志中心 → 日志设置 → 日志存储位置 → 浏览文件夹”的原入口。数据库、该目录里的旧分段和接口报文一起迁移；成功提示区分“已开始迁移”与“迁移完成”。迁移时禁用重复修改设置，失败显示原因并恢复原位置。

导入范围包括当前目录、配置记录的过去日志目录，以及工程数据目录 `logs` 下的 `igw-yyyyMMdd[.N].log` 文本日志。旧文本的多行异常和原 logger 名称保留，重启通过检查点续传和稳定 ID 去重。已处理文件数、总文件数在日志设置里查看，只有实际失败才提示。缺失、损坏或无法识别的文件不会标记成功；仍保留原文件并继续导入其它可读文件。

1.7.19 修复日志页面白屏：迁移状态兼容后端的数字枚举和字符串。历史按时间从旧到新导入，小文件合并成约 2 MiB 批次，检查点在缓存 fsync 后按批次保存；超过配置保留期的记录不发送到数据库，源文件不因此立即删除。数据库追赶历史时只暂缓历史批次，新日志优先，不将正常限流累计为“写入失败”。已有检查点和缓存会继续使用。

目录迁移或历史导入未完成时，“一键清理”会说明暂时不能清理的原因；仍作为读取回退的报文目录不会被列入清理项目。完成后，可通过原“一键清理”处理过往目录和旧文本；当前 QuestDB 数据目录始终受保护。按用户最终要求，OpenObserve 旧数据不做迁移，也不做自动清理，旧 `.parquet/.wal`、元数据、索引、缓存及 `telemetry-spool` 保持原样。

## 数据位置与保留

| 内容 | 位置 |
|---|---|
| 固定数据库程序及许可证 | 程序目录 `questdb` |
| 活跃数据库与 WAL | 日志目录 `igw-logs/questdb` |
| 故障期间的批次缓存 | 工程数据目录 `questdb-spool` |
| 旧段导入检查点 | 工程数据目录 `questdb-history.json` |
| 日志设置与受保护凭据 | 工程数据目录 `observability.json` |

新日志和报文进入不同 WAL 表，按 UTC 小时分区。默认保留 30 天；在日志中心调整保留期后，表的 TTL 随之修改。按完整分区删除，可能多保留一个小时。缩短保留期会删除过期日志：QuestDB 不提供跨表 TTL 事务；失败时恢复旧设置和 TTL，但已经删除的数据不能靠调回天数恢复。

接口报文沿用 `payloadMaxMegabytes` 容量设置，默认 2048 MB。数据库报文按旧小时分区清理到约 80%，保留最新分区；最新分区本身很大时可暂时超出上限。此容量只限制报文，不限制正常日志表。日志总容量需按每天实际新增量和 30 天保留期预留。

“已用空间”包含数据库和旧段，后台约每分钟更新一次。它是文件逻辑大小；预分配及稀疏文件使其不一定等于磁盘实际占用，不能将小测试的文件大小直接乘到 9 亿条。

## 数据库故障时

日志调用只入有界内存队列，不等待数据库和磁盘。后台约 100ms 合并成批次，落入缓存后再发送；数据库退出会重启，写入失败会退避重试。每条日志使用稳定 UUID，同一缓存重发不会产生重复。一个非法记录会拆分隔离，其余记录继续发送。

队列最多 2 万项并限制约 128 MiB 预估内存；批次缓存默认上限 2 GiB。旧历史导入只使用部分缓存额度，优先发送新日志。缓存不可写、队列/容量已满、非法批次都会反映到 `failed` / `dropped`。报文入队被拒绝时会报告未保存，不会返回假的成功引用。异常批次留为 `.rejected` 供排查，仍计入缓存容量。

启动恢复完整原子写临时批次，截断的批次隔离并计入丢弃。内存队列尚未落盘的尾部在强制结束或断电时仍可能丢失；批次 fsync、同步 WAL 和重试去重并不构成整机断电无损承诺。

系统检查 WAL 是否暂停或落后。落后过大时先存到缓存，避免继续放大数据库 WAL；状态就绪并不只判断 HTTP 端口能否连接。诊断接口 `/api/v1/log-center/status` 增加 `engine=questdb`、`historyImported`、`historyError`、`walPendingTransactions`、`databaseError`，不返回密码。原日志中心仍显示积压、失败和丢弃计数。

数据库只监听 `127.0.0.1` 并使用随机本机凭据，网页仍走原 IGW 地址；无需用户配置 HTTPS 或证书指纹。不要直接将数据库端口暴露到现场网络。

## 更换目录和备份

通过日志中心更换存储位置，选择没有 QuestDB 数据的新目录。迁移会暂停数据库请求、停止自己的数据库进程，复制完整存储后再启动；期间采集日志继续进入独立缓存。页面查询可短暂显示不完整或积压。看到迁移完成并确认日志、报文可读之后，再决定是否清理旧目录。目标启动或配置保存失败，会恢复原目录；迁移与保留期设置串行执行。

升级或做完整备份前停止 IGW，确认它拥有的 Java 进程退出，再复制整个工程数据目录和日志目录。工程数据目录也要备份，因为缓存、导入检查点、配置和授权都在里面。不要复制运行中的 `db` 目录当作一致备份；QuestDB 的 CHECKPOINT 目前不支持 Windows。恢复前保留故障数据副本，恢复整套目录后启动 IGW，核对状态、数量、近期日志和报文。

## 本次验证

- Windows 原生真实数据库：UUID 重发去重、多行中文、长整数、大小写关键词、布尔字段文本、路径边界、趋势、分页与导出。
- 网关集成：旧段导入、报文分页/下载、新报文无小文件、改保留期、停止后搬迁、重启、配置无法替换时回滚。
- 故障注入：数据库不可用、有界丢弃、批次内坏记录、在途历史失败与新日志竞争、完整/截断临时缓存、缓存路径不可创建、导出取消传到在途 HTTP 请求。
- 旧日志回归测试 85 项通过；新增测试与打包检查结果见本次验证记录。
- 发布运行包固定为 10.0.1，两平台官方 SHA-256 存在 `installer/questdb-release.json`，构建时校验。Linux 包中的许可证链接在 Windows 构建机上安全展开为实际文件，保留许可证。

Windows 10 合成测试，10 万条、目标 5000 条/秒、同步落盘并同时按设备查询：实际约 **4898 条/秒**，零丢弃、零写入失败；90 次并发查询的中位数 **15ms**、P95 **32ms**；全量计数/分页 **124ms**。单次 Append 最大 **4.89ms**，包含线程调度影响。本结果只证明该测试负载，不能外推成 9 亿条查询性能或现场硬件保证。

3000 万条/天平均约 347 条/秒，但峰值、日志正文/点值长度、接口报文大小决定内存和磁盘。按设备/类别/时间过滤优先使用索引；长时间范围任意关键词或工程路径搜索仍需要扫描，单次查询约 8 秒预算，超时会标记不完整。上线前需在代表性机器验证实际峰值、至少一天真实数据的空间、30 天样本查询和恢复时间。

## 开发机验证命令

```powershell
# 快速单元测试（未指定原生运行包时原生测试明确跳过）
dotnet test tests/IGW.Observability.Tests

# 自建临时数据库的 Runtime 测试
$env:IGW_QUESTDB_TEST_RUNTIME='D:\sdk\questdb\10.0.1\questdb-10.0.1-rt-windows-x86-64'
dotnet test tests/IGW.Observability.Tests --filter FullyQualifiedName~QuestDbRuntime

# 基准程序拒绝覆盖已有目录；保持路径绝对，完成后保存 benchmark.json 再清理数据
dotnet run --project benchmarks/IGW.QuestDbBench -- `
  'D:\sdk\questdb\10.0.1\questdb-10.0.1-rt-windows-x86-64' `
  'D:\igw-questdb-bench-new' 100000 5000
```

直接 HTTP 集成测试另使用 `IGW_QUESTDB_TEST_URL` 指向**专用、可清理**的测试库，其 Basic 凭据为代码中的测试凭据；其中容量测试会删旧报文分区，禁止指向运行库。
