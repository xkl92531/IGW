# IGW 1.6.66 发布说明

打包日期：2026-09-17。平台：Windows x64，自包含 .NET 10 运行时。

本版针对 S7-1500（1515/1517）经 OPC UA 采集时“握手回写要几秒到十几秒”的问题。用现场工程在本机按 1515/1517 性能模拟验证（报告见 `docs/validation/2026-09-17-s7-1500-site-simulation.md`）。在现场节拍下：
- 小工位从请求到 MES 回写的中位数由 5–10 秒降到 0.5–0.65 秒。
- 确认回写的中位数约 0.25–0.3 秒。

**1.6.65 已安装的现场建议升级。**

## 只读流程需要的点

- MES 任务不再整组轮询或读取绑定组，只采集流程中实际用到的点：条件、字段、结构体成员、数据范围、回写。
- 分层采集只在上报、设备指令、带“复制点”的回写前读取；只写固定值的回写（握手确认、心跳）不再触发整包读取。
- 上报失败或回写失败时，握手未完成的重试在 2 秒内复用上次读取，不再每个周期重读上千点。

## 外部读取仍拿到最新值

- 以下接口读取到没有在采集中的点时，先从 PLC 读一次再返回（最长等 10 秒，超时返回缓存值）：
  - `GET /api/v1/tags/{id}/value`、`GET /api/v1/values`、`GET /api/v1/tags/{id}/array`
  - KEP 兼容 `GET /iotgateway/read`
  - DCS 兼容读取接口
- 读过的点进入 30 秒活动窗口，窗口内的后续读取直接用轮询值。
- QC 仍只在刷新、定时刷新或单点读取时读 PLC；写入不受影响。

## OPC UA 请求调度

- **单请求耗时预算（通道设置）：** 默认“自动”，也可填 0（不限，只追求吞吐）或固定毫秒数。
  - 自动模式：网关根据近期请求拟合“固定开销 + 每点耗时”，单个请求不超过约 10 倍固定开销（100 ms–2 s）。
  - 按模拟数据，S7-1500 上约 170–300 ms、100–150 点一批；响应快的服务器不受影响。
- **大读取按块准入：** 共享会话保留一个执行槽给写入和回读；小读取优先于大块读取，大块读取每让 8 次必得一次。上千点的按需拉取不再挡住同一 PLC 其他工位的握手。
- **状态显示：** 设备状态的详细信息中显示当前读/写批量、预算和实测开销，便于现场核对。

## 模拟工具（PlcSim）

- 导入多 PLC 工程时，每台 PLC 一个 OPC UA 端口；节点号使用现场西门子地址；点位类型取 IGW 层。
- 新增“性能档位”（如 `PLC7=1517,*=1515`），按西门子 OPC UA 容量上限和现场日志估算的处理速度模拟。

## 仍受 PLC 限制的部分

- 一次上报要读 2,000 多点的任务（如 BusbarWelding），在 1517 上仅读取就需约 3.7 秒。网关已保证它不拖慢其他工位，但它本身无法更快。
- 可选的进一步方案：把结构体数组配置为数组点位，或把上报点改为订阅。需要现场确认后再实施，见验收报告。
