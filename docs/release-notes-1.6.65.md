# IGW 1.6.65 发布说明

打包日期：2026-09-17。平台：Windows x64，自包含 .NET 10 运行时。

本版在 1.6.64 基础上继续处理现场（S7-1515，OPC UA）的卡顿问题，并修复“载入工程失败：timeout of 8000ms exceeded”和工程导出后无法再导入的问题。**1.6.64 已安装的现场建议升级**：1.6.64 中串口类协议的按需读取会与扫描并发，步骤模式的 MES 任务可能上报旧值，均已在本版修复。

## QC 不再拖慢采集

- 打开 QC 不再让点位进入轮询。只有点击“刷新”、开启“定时刷新”，或右键“从 PLC 读取此点”时才读取 PLC；单点写入照常直接下发。
- 定时刷新可选 1/2/5/10/30/60 秒，默认“不刷新”；上一次读取完成后才开始计时，页面隐藏时暂停。
- 新增 `POST /api/v1/values/read`（一次最多 10000 点，按用户分支权限校验，30 秒超时），QC 通过实时通道调用。

## 载入工程超时

- JSON 应答与前端静态资源启用 gzip（推送流 SSE/SignalR 不压缩）。现场 13,277 点的工程由 14.1 MB 降到 0.98 MB，前端主脚本由 800 KB 降到约 360 KB。
- 工程接口改为流式输出；前端载入工程的超时由 8 秒改为 120 秒。

## 工程导入

- 修复网关自己导出的工程无法再导入（`KEP and IGW values conflict … (address, type, array, or access)`）。DTL 等 KEP 无法表达的西门子类型在 KEP 层记为“默认”，导入时原样使用 IGW 层的类型；可表达类型之间的真实冲突仍会阻止导入。

## OPC UA 与分层采集

- OPC UA 会话内注册节点（RegisterNodes），订阅按采样周期分组，每个订阅最多 5000 个监视项，每次最多建 1000 个。
- 订阅建立后的首次读取走优先通道。
- 串口类协议的按需读取排入设备循环，不再与扫描并发。
- 只有设置了触发条件的 MES 任务才分层采集，步骤模式在第一步前先读取上报点。

## 验证

- 用现场工程（5 个 PLC、1418 个组、13,277 点、171 个 MES 任务）在独立数据目录中导入、载入、删除测试：删除一个含 275 个组、2730 点的分组后，数据库、运行时和状态计数一致，无残留。
- 本地载入现场工程耗时约 0.4 秒；远程访问时传输量是主要耗时，压缩后约为原来的 1/14。
- 后端测试 1716 项中 1714 项通过，另 2 项（MesWritebackCycleTests、AcquisitionDiagnosticsExportTests）在全量并发时偶发失败，单独运行通过；前端测试 355 项全部通过，类型检查通过。
- 安装包内的 Runtime 已单独启动，完成导入与压缩的冒烟测试。
- S7 Plus 原生组件沿用 SHA-256 `08DB184B2D71D2224488CB11E81FDF10D4DFAB6C6BF2FDFD1ED57EEBC9670B25`（原因见 1.6.64 说明）。
- 本版未在现场安装，也未连接真实 PLC。
