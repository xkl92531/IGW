# 自适应 PLC I/O 与故障隔离验证记录

日期：2026-08-29

## 已验证：合成环境与本机协议闭环

- 后端完整测试：461/461 通过，0 失败、0 跳过。
- 前端组件测试：31/31 通过；产品源码/安装脚本回归：189/189 通过；TypeScript 类型检查通过。
- 关键确定性回归：DeviceLoop、OPC UA 与高密度写入共 69 项，连续执行 3 次均通过。原生协议批量读写回归包含在 461 项完整测试中。
- 2,477 点压力链：初始读取块 512 点，模拟服务器容量失败后自动降至 256；2,477 个 TagId 均被读取，无遗漏、无重复丢失。
- 同一压力链中在首个大批次等待期间插入写请求，写入及回读验证成功；驱动 `DisconnectCalls == 0`。
- 永久点位拒绝：`BadNotWritable` 点不再重试 11 次，同批 Good 点继续写入并验证，连接保持在线。
- 西门子 Classic/S7 Plus：操作超时保持既有会话；传输异常仍按真实断线处理。
- EtherNet/IP：整批 Bad 只有在独立 TCP 探测也失败后才升级为传输故障。
- Modbus TCP 与 Mitsubishi MC：连续地址分别使用原生多寄存器/多线圈和 MC 连续帧；点位拒绝不关闭会话，传输关闭仍抛出通信异常。
- OPC UA：活动 QC 点采用 Subscription，MES/周期采集仍走批量 Read；订阅失败自动回退读取并按同一会话重试。服务端读写上限会学习、落盘并在重启后复用。
- OPC UA 证书：默认使用首次信任并固定证书指纹（TOFU），证书变更或其他验证错误不会被静默放行。
- 100 万元素、50 设备、4 个 10ms 快速任务与 46 个 200ms 普通任务同时运行 30 秒：读取成功 18,789 次；并行执行 1,001 次数组写入、回读验证和缓存发布，失败 0；运行中连接最少 50/50，异常断线 0；快速任务 P95 16ms/P99 32ms；写入闭环 P95 16.09ms/P99 17.42ms；QC 切片 P99 0.064ms；峰值 CPU 2.34%、工作集 77.31MB。
- 部分坏数据注入保持精确范围 `Device11 [100..119]`，其余 999,980 个元素和全部设备继续工作，未升级为设备离线。
- REST → 设备队列 → Modbus TCP 模拟 PLC → 回读验证完整闭环：`SetPoint` 从 0 写为 321，写结果 `Good/0x00000000`，随后读取为 321/Good，设备 1/1 在线。
- 最终安装包 1.6.6 中的 Runtime 实际启动后，对 Modbus TCP 测试点连续执行 100 次 REST 写入和紧随其后的立即读回：100/100 数值一致，写失败 0，设备全程 Connected，数据丢弃 0；整个“写入+立即 REST 读取”闭环 P50 15.51ms、P95 18.87ms、P99 24.71ms。
- Release 完整构建：`dotnet build IGW.slnx -c Release --no-restore -p:TreatWarningsAsErrors=true` 成功，0 警告、0 错误。
- NuGet 安全扫描：全解决方案直接与传递依赖均未发现已知漏洞；SQLite 原生包已升级到安全版本，OPC UA SDK 已升级至当前项目采用的新 API 版本。

以上协议闭环使用本机真实 Modbus TCP 报文，但 PLC 端是模拟服务；百万点结果为进程内合成驱动。它们不等同于现场 PLC 认证，也不证明任意型号 PLC、交换机和网络都能稳定达到 20ms。

## 依赖说明

- 解决方案没有安全公告包，Release 构建也没有编译告警。
- `IoTClient 1.0.48` 的依赖树仍携带仅面向非 Windows RID 的旧 `System.IO.Ports` 运行包元数据；IGW 的 `win-x64` 安装包不加载这些 Linux/macOS 资产。为了避免破坏现有 PLC 协议兼容性，本次没有用无关的顶级包强行覆盖它。

## 待现场验证

在真实 PLC 或现场 OPC UA Server 上采集以下证据后，才能标记“现场通过”：

1. 记录 PLC 型号、协议及脱敏后的端点；不得记录密码或证书私钥。
2. 记录服务器声明的 `MaxNodesPerRead/Write`、首批窗口和最终学习窗口。
3. 记录实际点数下的平均/P95/P99 扫描周期、样本吞吐及超期周期数。
4. 对一个可读写测试点执行 QC 写入，记录排队、协议响应、回读验证耗时与精确状态码。
5. 注入一次大批次超时，确认 SessionId 在降批前后连续且设备未离线。
6. 注入真实网线/服务端断开，确认只有此时触发连接重建，并能在网络恢复后自动恢复。
