# OPC UA 连接、异常点和浏览策略

1.6.36 将同一连接配置的运行设备放在一个共享 OPC UA 会话内。无需修改现有工程；启动、热重载时自动生效。共享条件包含端点、身份、安全配置、超时和来源网卡；账号、密码、安全或网卡配置不同的设备保持隔离。

## 会话与重连

- 逻辑设备各自持有会话租约和订阅，停止一个设备只清理自己的订阅，最后一个租约释放时关闭实际连接及网卡转发。
- 同一共享连接同时只执行一次建连。取消一个等待者不会取消其他设备的建连。
- 连续连接失败统一按约 1、2、4、8、16、30 秒退避，后续最多 30 秒；自动硬重建保留退避状态。不同 PLC 独立恢复。
- 手动重新连接可立即发起尝试。若多个通道共享同一实际连接，会一起重建这些逻辑设备，并在日志标明受影响数量；其他连接不受影响。
- 运行读写最多同时调度两个逻辑操作，队列最多 512 项。写入优先，连续处理最多八个优先项后给等待读取机会；超载明确返回错误，不无限堆积。
- 自动生成标签使用独立浏览会话，连续操作复用已有浏览连接。浏览会话不占采集会话的请求名额；首次连接、超时清理或连接失效后仍需要建连。

## 无效点

只有连续三次明确返回 `BadNodeIdUnknown` 的配置点才退出高频轮询，改为约 30 秒一次复查。正常点按原扫描计划继续采集；通信错误、普通坏质量和缺失响应不会被当作永久地址错误隔离。

复查收到有效响应后恢复原周期；写入后的校验读取确认成功也可恢复已有轮询计划。写入前启动、写入后才到达的旧读响应不会重新隔离点位。无效点保留真实坏质量，不把旧值显示为良好，也不自动修改 NodeId。

这会减少无效地址造成的请求负担，但地址最终仍需与 PLC 工程对应。纯订阅模式保持原有订阅语义，低频隔离针对周期轮询。

## 部分成功浏览

单个节点的类型无法解析时，正常节点仍可预览和导入。失败列表显示具体 NodeId、路径和原因，支持逐项重试，每页最多 50 项。断连和取消继续返回失败，不把未完成浏览当作成功。

## 诊断与日志

“采集性能”页面增加每批实际请求点数、OPC UA 请求数量、协议请求累计及最大耗时、排队时间、失败及取消次数。读取页面诊断只查询有界内存历史，不新增 PLC 请求。详细口径见 [采集性能说明](scan-performance.md)。

每次启动记录程序集版本、构建和模块标识、路径、进程 PID、启动 ID，以便判断现场运行的是哪个包。系统心跳成功日志保留首次和恢复提示，连续成功约每 30 秒汇总；故障日志及时保留。MES 业务回写、写入校验及 HTTP 行为保持原有语义。

QC 增加按可视行批量查询的“最近批次耗时”列。健康接口返回 `503 / reloading` 时，界面显示橙色“正在应用配置”，恢复后回到“已连接”。实时流 503 错误保留具体错误码并按原有退避恢复，健康轮询串行执行。

## 验证边界

使用本地 OPC UA SDK 服务验证会话共享、并发读写、订阅存活、取消和资源释放；这些结果不代表现场 S7-1500 的网络与处理速度。现场应比较升级前后的协议请求时间、排队时间、实际采集间隔和无效点数，不能仅凭 ping 或模拟测试保证达到某个周期。
