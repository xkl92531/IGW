# IGW 1.6.64 发布说明

打包日期：2026-09-17。平台：Windows x64，自包含 .NET 10 运行时。

版本号跳过 1.6.61–1.6.63：远端已有其他机器推进到 1.6.62，为避免同一版本号对应不同安装包，本包直接使用 1.6.64。

本版集中处理现场“QC 和采集读写卡顿、任务返回要几秒到几十秒”的问题。现场为 S7-1515，经 OPC UA 采集，同一 PLC 通道下多个工位共用一条会话。

## 排队与堵塞

- 删除订阅不再独占整条共享会话。以前订阅一重建，同一 PLC 上所有设备的采集和 QC 写入都要等最慢的在途读取返回；本地复现中 QC 写入排队约 3.1 秒，无独占时为 0。
- 共享会话的在途请求数按共用设备数自适应（设备数 + 1），不再固定为 2。一个通道下有三个工位时为 4，设备退出后自动收回。上限默认 6，可在通道设置 `maxConcurrentRequests` 调低；多个通道共用同一会话时，以最保守的设置为准。
- 读取超时不再缩小批量窗口。以前超时后窗口减半，同样的点位要拆成更多请求，负载更高、更容易再超时。现在保留窗口和会话，当前批次失败后交给下个周期重试；已经读到的前一部分数据照常发布。
- 订阅被 BadRequestInterrupted 打断后，先在当前会话内等 100ms 优先重试一次，期间不插入慢速兜底读取；再次失败才退回轮询并退避 5 秒。退避从失败完成时起算，不会因为新的 QC/MES 引用而提前结束。
- 1.6.60 已写明的超时与订阅中断修复在后续合并中丢失，本版已恢复，相应的验收用例重新通过。

## 分层采集（默认开启）

- MES 流程只按采集周期轮询判定所需的点：触发点、条件点、握手/心跳点、数组长度和结构体数量点。
- 上报、回写和协议指令用到的点，改为在触发条件满足后立即批量读取一次，上报的是触发时刻的实际值。读取失败时流程继续执行，未读到的点使用缓存值，并记录原因。
- 总开关为 `MesUpload.TieredAcquisition`，默认开启；任务级 `TieredAcquisition=false` 可让该任务恢复全量周期轮询。已有工程升级后无需重新保存配置。
- 历史记录只记录已采集到的数据，不再要求所有点位都被轮询。开启历史记录的工程中，分层采集任务的上报点只在触发时留下记录；需要连续曲线的任务请关闭分层采集。
- 报警点、计算点输入，以及 QC/REST/北向 OPC UA 正在读取的点仍保持轮询，不受影响。

## 大点数订阅

- 采集需求减少时，只从订阅中删除不再需要的点，不再拆掉整组订阅重建；监控项全部删除的订阅会一并删除。采样周期变化时仍整组重建。
- 仅被 QC/REST 访问的点，同样在一段时间内保留订阅，避免 30 秒活动窗口到期后反复重建订阅；最多保留 4096 点。
- 服务器拒绝了全部监控项的订阅会立即删除，以免占用 PLC 的订阅资源。
- 删除订阅的超时时间按订阅数量增加（每个 500ms，最长 30 秒）；有订阅未确认删除时写入诊断。

## 日志文件夹选择

- 修复“磁盘列表”按钮不显示磁盘、只返回日志存储目录的问题。原因是日志中心接口替换后，重新实现的目录浏览接口与前端约定不一致。
- 磁盘显示卷标与可用空间；可用空间不足 1 GB 的磁盘标红（日志目录保存时会被拒绝）。
- 不再列出隐藏和系统文件夹；恰好 500 个子文件夹时不再误报“仅显示前 500 个”；打开不存在的路径时明确报错；拒绝 `\\?\`、`\\.\` 设备路径。
- 打开对话框时，如果当前目录已不存在，自动改为显示磁盘列表并说明原因。

## 构建与验证

- `installer/build.bat` 改为在发布前确定版本号，并写入 Runtime 与日志服务的程序集版本。以前的安装包在启动日志和采集诊断导出中都显示 1.0.0.0，现场无法区分版本。打包中途失败时版本号已递增，重试时加 `--no-bump`。本包 Runtime、Core、OPC UA 驱动、MES 与日志服务文件版本均为 1.6.64.0，产品版本为 `1.6.64+34291fc…`，对应源码提交 34291fc。
- **本次未重新编译 S7 Plus 原生组件**：打包机的 Visual Studio 2022 缺少 MSVC v143 的 CRT 头文件与库（工具集下没有 `include`、`lib` 目录），`libz-sys` 无法编译。安装包沿用 2026-09-16 23:37 构建的 `igw_s7plus.dll`，SHA-256 为 `08DB184B2D71D2224488CB11E81FDF10D4DFAB6C6BF2FDFD1ED57EEBC9670B25`；原生源码自 1.6.43（989562b）后未改动，打包前已校验哈希。恢复完整构建需在 Visual Studio Installer 中补装“MSVC v143 - VS 2022 C++ x64/x86 生成工具”。
- Web UI 生产构建、Runtime 与独立日志服务的 win-x64 自包含发布、日志服务打包检查全部通过；OpenObserve 1.0.0 已通过 SHA-256 校验。
- 后端测试 1678 项、前端测试 350 项（76 个文件）、安装脚本测试 5 项全部通过，前端类型检查通过。
- 用独立数据目录启动了一个 Runtime 实例，直接请求线上注册的目录浏览接口，磁盘列表、隐藏目录过滤、不存在路径、设备路径四项结果均正确。
- 未在现场安装，也未连接 PLC；时延改善需要升级后在现场验证。建议重点观察采集批次日志中的排队时间，以及 MES 任务启动日志中“启用分层采集”的常驻点数。
