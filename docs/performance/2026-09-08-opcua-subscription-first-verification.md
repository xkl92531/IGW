# OPC UA 订阅优先采集验证

## 现场问题与改造结果

`igw-acquisition-diagnostics-20260908-090159.zip` 中 PLC9 的 4 个慢设备每个逻辑批次都只有 1 次物理 OPC UA Read，本机排队 P95 为 0 ms、本地处理为 0–1 ms、网络无丢包且 RTT 接近 0 ms。请求耗时随节点数近似线性增长，说明继续扩大单次 Read 点数不能消除上游 OPC UA 服务器逐节点处理成本。

本次实现将连接配置相同的 OPC UA 逻辑设备合并到一条物理 Session，并将 `scanMode=active` 下的 MES 周期需求加入 OPC UA 原生订阅。订阅建立后只做一次批量首读；Good 点位退出轮询计划，MES 流程按原周期读取 DataHub 最新快照。Bad 或缺失点位继续批量补读，收到 Good 通知后自动停止补读。最后一个 QC/MES 需求过期后，上游 Subscription 和 MonitoredItem 会被删除。

按现场包的配置，PLC9 如果 8 个逻辑设备的端点、认证、安全策略、网卡和超时完全相同，IGW 物理 Session 数将从 8 降到 1。原约 965 点次/秒的周期 Read 需求将变为一次首读加实际变化通知；准确的服务器吞吐改善需安装后重新导出现场诊断包确认。

## 现场复测观察项

安装后等待订阅建立和首读完成，再导出采集性能诊断：

- PLC9 同端点设备应显示“同端点设备 8 / 物理会话 1”（连接配置一致时）。
- OP025、OP020、OP230-1、OP230-2 的模式应从轮询变为订阅或仅少量失败点混合补读。
- 正常稳定期的逻辑批次数和物理 Read 数应接近 0；点位变化通过订阅进入 DataHub。
- 若仍有轮询，展开批次核对 Bad/缺失点 NodeId 和错误；这些点是自动保留的补读范围。
- 若服务器拒绝 MonitoredItem，日志会显示订阅建立失败并回退批量读取，不会静默停止采集。
