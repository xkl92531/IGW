# IGW 百万点前端 SSE 实时数据架构设计

## 1. 背景

IGW 当前 Quick Client 通过 `GET /api/v1/values?ids=...` 定时读取当前组全部点值。监控中心、设备状态和 MES 流程运行状态也分别使用 1～3 秒定时请求。PLC 点值接口读取的是 DataHub 缓存，不会由每次 HTTP 请求直接穿透 PLC，但前端全量轮询仍存在以下容量和实时性问题：

- 当前组全部点位 ID 被拼进 GET 查询串，数千点时容易达到浏览器、代理或服务器请求行上限；
- 即使点值没有变化，服务端仍拆分全部 ID、查询全部缓存、创建全部 DTO 并重新序列化 JSON；
- Quick Client 使用普通 `el-table`，每轮全量响应都会触发数千行比较和 DOM 更新；
- Quick Client 自动刷新没有请求互斥，接口耗时超过刷新周期时会产生重叠请求和乱序响应；
- 多个实时页面和多个客户端会把相同全量请求成倍放大；
- 100 ms～1000 ms 的刷新间隔本身构成可见延迟上限。

仓库中已经存在 `TagValueStreamRequest`、SSE 帧模型、`TagValueSseWriter`、流鉴权规则和 DataHub 按点订阅基础设施，但尚未注册可工作的流端点，也没有前端流客户端。本设计补齐完整的数据通道、故障隔离、工程热重载和百万点容量边界。

## 2. 已确认目标

1. PLC 点值、设备连接状态、监控状态和 MES 流程运行状态使用 SSE 实时推送。
2. 工程配置、日志查询、历史数据和其他低频页面继续使用普通 HTTP。
3. 前端不静默回退到轮询。实时连接失败时明确显示断线和数据过期，并持续重连。
4. 点值首次连接、断线恢复、丢帧、工程变更和定时校正时使用完整快照；正常阶段只发送变化增量。
5. 定时一致性快照默认每 60 秒执行一次，可配置范围为 15～300 秒。
6. SSE 心跳默认每 10 秒；连续 20 秒未收到业务帧或心跳时，前端将连接判定为失效。
7. 单个 IGW 工程支持最多 1,000,000 个已配置点位。
8. 同时活动采集点目标上限为 500,000。
9. 默认允许 100 个并发 SSE 实时客户端，可配置范围 1～200，服务端硬上限 200。
10. 单个 SSE 客户端最多订阅 10,000 个普通点位。
11. 正常负载目标为 DataHub 每秒持续 50,000 点变化；突发目标为每秒 200,000 点变化并持续 1 秒。
12. 正常负载下，DataHub 变化到 SSE 开始发送 P95 不超过 20 ms；SSE 到浏览器界面完成更新 P95 不超过 20 ms；IGW 内部推送链路 P99 不超过 50 ms。
13. 突发超载时允许合并同一点的中间状态，但最终值必须恢复一致，不能阻塞 PLC 读取、写入或 MES 业务。
14. 工程点表变化时删除全部旧订阅、旧句柄引用和旧前端缓存，并按照新工程点表重新建立，不能复用旧资源。
15. 所有协议共用一套前端实时数据协议；PLC 到 IGW 的采集方式仍由各协议能力决定。

## 3. 非目标和物理边界

- SSE 优化的是 IGW 到浏览器的数据链路，不改变 PLC 扫描周期、PDU、服务器 OperationLimits 或物理网络能力。
- OPC UA 可以通过原生 Subscription 把变化推入 DataHub；S7、Modbus、三菱 MC、Omron FINS 和部分 EtherNet/IP 路径仍需要周期批量读取。
- “工程 100 万点”不表示一个浏览器同时显示或订阅 100 万点。单客户端只订阅当前组或当前查询范围，最多 10,000 点。
- 不承诺 100 个客户端同时订阅相同 10,000 点且所有点每 20 ms 全部变化时仍逐个保留所有中间状态。该负载超过浏览器显示和常规工厂网络的信息吞吐能力，系统只保证最终状态和权威历史一致。
- 点值实时流是“当前状态流”，不是审计日志。报警事件、MES 节点事件和操作日志的权威记录仍由服务端持久化或环形时间线保存。
- 数组不按元素展开到 SSE。一个数组仍是一个逻辑点，流中只发送数组整体版本、质量和摘要；元素查看继续使用切片 HTTP 接口。
- Windows、浏览器和普通以太网不是硬实时系统。20 ms 和 50 ms 是可观测的服务目标，必须报告实际 P50、P95、P99 和超期。

## 4. 方案选择

### 4.1 采用方案：DataHub 原生 SSE 推送

服务端从 DataHub 统一缓存按点订阅，经过共享实时协调器合并、路由和限流后，以 SSE 推送到浏览器。该方案与 PLC 驱动解耦，适合服务器到浏览器的单向实时状态传播，也能复用现有 SSE 合同和写入器。

### 4.2 未采用：SignalR/WebSocket

SignalR 和 WebSocket 支持双向通信和动态订阅，但 IGW 写入已经使用独立 HTTP 接口，双向能力不是必要条件。引入它们会增加连接协议、依赖和部署诊断复杂度。

### 4.3 未采用：增量长轮询

长轮询可以减少全量响应，但仍持续创建 HTTP 请求，保留等待超时、重连和并发请求管理问题。实现版本游标、变化集和重新快照后，其复杂度已接近 SSE，却没有持续连接的低延迟优势。

## 5. 总体架构

```text
PLC 驱动
  ├─ OPC UA Subscription
  ├─ MQTT Broker 消息
  └─ S7 / Modbus / MC / FINS / EIP 批量 Read
                    ↓
                 DataHub
                    ↓
        RealtimeStreamCoordinator
  ├─ 联合按点订阅与引用计数
  ├─ Tag Handle → 客户端位图
  ├─ 分片变化合并
  ├─ 状态与有序事件分流
  ├─ 快照调度与工程代际
  ├─ 容量准入与慢客户端隔离
  └─ 指标与重置通知
                    ↓
             SSE 会话写入器
                    ↓
          前端 RealtimeStreamClient
  ├─ 初始/定时快照状态机
  ├─ 增量与事件序号校验
  ├─ 断线重连和过期显示
  └─ 页面范围订阅与资源释放
                    ↓
  Quick Client / 监控中心 / 连接状态 / MES 流程
```

SSE 只能读取 DataHub 和运行时状态快照，严禁在 SSE 回调或写入任务中直接调用 PLC 驱动。PLC 写入继续经过现有 HTTP 写入接口和运行引擎优先写队列，写入后的实际回读值由 DataHub 变化流推送到页面。

## 6. 服务端组件边界

### 6.1 `RealtimeStreamCoordinator`

协调器是单例运行时服务，负责：

- 管理当前工程代际和所有 SSE 会话；
- 维护联合订阅、点位引用计数和客户端路由位图；
- 接收每个 DataHub 点变化一次，而不是每客户端建立一份 DataHub 订阅；
- 把可合并的状态变化与不可合并的有序事件分开处理；
- 执行连接、点位数、快照并发和发送队列容量准入；
- 监控全局及每会话的队列深度、丢弃、延迟和发送字节；
- 在工程热重载时终止旧代际并重建新代际。

协调器不持有 PLC Session，也不能改变设备连接状态。

### 6.2 联合按点订阅

不能为 100 个客户端分别调用 `DataHub.SubscribePoints`，否则相同点会在 DataHub 内形成最多 100 份投递。协调器只创建一份专用 `IPointSubscription`：

1. 某点被第一个客户端订阅时，对 DataHub 执行 `Add(handle)`；
2. 后续客户端只增加协调器内部引用计数和客户端位图；
3. DataHub 变化只进入协调器一次；
4. 最后一个客户端取消该点时执行 `Remove(handle)`；
5. 工程代际结束时统一 Dispose，保证设备需求计数归零。

路由身份使用 DataHub 精确 TagId 和 Handle，比较器必须为 `StringComparer.Ordinal`。不能使用显示名称或不区分大小写去重，因为工业地址和外部 NodeId 可能大小写敏感。

### 6.3 分片变化合并器

DataHub 回调只能执行有界、非阻塞操作：记录 Handle、最新 DataValue 版本和到达时间，然后立即返回。

- 按 Handle 哈希分为最多 8 个处理分片；
- 协调器专用入口容量默认 262,144，可在硬上限内配置；
- 同一点在 10～20 ms 合并窗口内多次变化，只保留最新状态；
- 分派到客户端时写入“脏 Handle 集”，不复制一份完整 DTO；
- 客户端真正发送时从 DataHub 读取最新值并序列化；
- 入口或会话发生丢弃时增加计数，并使受影响会话进入 `reset-required`。

现有 DataHub 固定 10,000 容量的订阅队列需要扩展为可为内部消费者配置容量，或为协调器提供等价的专用有界订阅接口。不得把所有订阅队列全局扩大，以免无界增加其他消费者内存。

### 6.4 状态流与有序事件

流数据分为两类：

- **状态流**：点值、质量、设备连接状态、MES 节点当前状态。允许在合并窗口内覆盖中间值，最终状态必须一致。
- **有序事件流**：MES 节点流转、报警激活/恢复、连接事故。不能合并和乱序；权威记录先写入服务端时间线/历史，再推送到浏览器。

有序事件队列溢出时不能伪装成完整。服务端发送 `reset-required`，前端重新取得当前状态和权威时间线。

### 6.5 `RealtimeStreamSession`

每个会话持有：

- 唯一 `StreamId` 和不可变 `ProjectRevision`；
- 客户端 ID、登录用户和授权范围；
- 最多 10,000 个精确 Handle；
- 变化位图或集合、有限有序事件队列和发送任务；
- 单调递增事件序号；
- 最近发送、心跳、快照、队列和丢弃统计；
- 与 HTTP 请求取消令牌绑定的清理句柄。

网络发送失败、浏览器取消或超时只 Dispose 当前会话，不能调用设备断开或通道重连。

## 7. 流接口与协议

### 7.1 请求方式

前端使用 `fetch POST` 读取响应流，不使用原生 `EventSource`。原因是订阅最多包含 10,000 个 TagId，需要请求体，且需要携带现有认证信息和取消令牌。

建议端点：

```text
POST /api/v1/streams/realtime
Content-Type: application/json
Accept: text/event-stream
```

请求至少包含：

```json
{
  "protocolVersion": 1,
  "clientId": "work-window-id",
  "projectRevision": "revision-at-open",
  "tagIds": ["Channel.Device.Group.Tag"],
  "topics": ["devices", "mes-task:task-id"],
  "includeSnapshot": true,
  "heartbeatSeconds": 10
}
```

点值、设备和 MES 状态可在同一浏览器工作窗口的单条流内复用。页面切换订阅范围时取消旧请求并建立新请求，不新增双向订阅控制协议。

### 7.2 准入和鉴权顺序

开始写 SSE 响应头之前完成：

1. 验证功能启用状态和协议版本；
2. 验证用户身份；
3. 验证请求体大小、ClientId、TagId 长度和精确去重；
4. 验证请求的工程版本仍为当前版本；
5. 验证每一个点和主题的读取权限；
6. 验证客户端数、单流点数和总订阅关系容量；
7. 创建会话并注册联合订阅。

任意点无权读取时拒绝整条请求，不能在错误中返回无权点名称。不存在但用户有权访问其父范围的点可以在 `hello` 中报告为 Missing；前端随后按新目录重建。

### 7.3 事件类型

- `hello`：协议版本、StreamId、工程名、工程版本、接受点数和缺失点；
- `snapshot-begin`：SnapshotId、工程版本、基础序号、分块总数；
- `snapshot-chunk`：最多 256 个状态值；
- `snapshot-complete`：快照完整结束；
- `tag-delta`：合并后的点值变化；
- `device-state`：设备连接与诊断状态变化；
- `mes-state`：MES 任务和节点当前状态变化；
- `runtime-event`：不可合并的 MES/报警/连接事件；
- `heartbeat`：最后序号、工程版本、设备摘要、队列、丢弃和延迟；
- `project-changed`：旧工程代际终止，新工程版本可用；
- `reset-required`：序号缺口、过载、事件丢失或协议状态不可恢复；

每个 SSE 帧使用 `StreamId:Sequence` 作为事件 ID。重连后生成新 StreamId 并从完整快照开始，不尝试跨会话重放点值增量。

### 7.4 帧限制

- 快照每块最多 256 点；
- 增量每帧最多 256 点；
- 单帧最大 1 MiB；
- 超大字符串或结构值必须经过点类型限制，不能以拆破 JSON 值的方式跨帧；
- SSE 禁止代理缓冲和 HTTP 响应缓存；
- 写入器按帧 Flush，协调器负责先合并，不能每点 Flush。

## 8. 快照和一致性

### 8.1 初始快照

为避免订阅和快照之间丢值，顺序必须为：

1. 建立协调器会话并注册所有精确点位；
2. 开始缓存该会话的脏 Handle 和有序事件；
3. 记录 SnapshotId 和当前流序号；
4. 从 DataHub 分块读取快照；
5. 发送 `snapshot-complete`；
6. 发送快照期间积累的最新点值和有序事件；
7. 进入正常实时阶段。

状态点允许快照读取期间发生变化。因为订阅已经建立，变化会在快照完成后以更新值补发。若快照期间会话缓冲溢出，则废弃本次快照并发送重置，不能发布不完整快照为成功。

### 8.2 前端原子应用

前端收到 `snapshot-begin` 后创建临时状态 Map：

- 快照块只写入临时 Map；
- 快照期间到达的增量按序暂存；
- `snapshot-complete` 到达且块数完整时一次性替换正式状态；
- 然后按序应用暂存增量；
- 块缺失、序号跳跃、工程版本不一致或超时均放弃临时 Map 并重连。

这样可避免快照旧值覆盖刚到达的新值，也不会在页面上展示半份快照。

### 8.3 定时一致性快照

- 默认周期 60 秒，可配置 15～300 秒；
- 周期按 StreamId 计算固定相位，在一分钟窗口内错峰，避免 100 个客户端同时快照；
- 同一时间最多执行 4 个完整快照；
- 排队等待快照时实时增量继续发送；
- 快照只覆盖当前会话订阅范围；
- 断线、序号缺口、队列丢弃或工程变化立即重建，不等待定时周期。

定时快照是服务端主动推送，不是前端 HTTP 轮询。

## 9. 断线恢复和慢客户端隔离

### 9.1 前端重连

- 网络错误后按约 1、2、5、10、30 秒退避重连，并加入随机抖动；
- 30 秒是单次退避上限，用户保持页面时持续尝试；
- 不退回 `/api/v1/values` 轮询；
- 立即显示“正在重连”，保留最后值但标记为过期；
- 连续 20 秒没有业务帧或心跳时主动取消旧请求并重连；
- 重连成功必须完成新快照后才恢复“实时”标记。

### 9.2 慢客户端

- 每个会话拥有独立有界状态集合和有序事件队列；
- DataHub 和协调器处理任务从不等待某个客户端网络写入；
- 状态集合持续合并到最新值，不保存无限历史；
- 有序事件队列接近上限时发送重置；
- 网络已经无法发送重置时直接取消会话；
- 会话清理必须删除全部路由关系和引用计数；
- 慢客户端不得增加 PLC 扫描频率、阻塞写入或改变设备状态。

### 9.3 页面状态

所有实时页面统一显示以下状态：

- `连接中`：尚未收到完整快照；
- `实时`：快照完成且心跳正常；
- `正在重连`：连接失败但未超过过期判定；
- `数据已过期`：连接失效，最后值仅供参考；
- `重新同步`：正在构建新快照；
- `工程已变化`：正在删除旧数据并加载新点表；
- `容量受限`：连接数或点位数超过上限。

不能把请求异常吞掉后继续显示“良好”或“全部正常”。

## 10. 工程热重载

工程变化采用“旧代际完全销毁、新代际完全重建”，不能在旧句柄上局部修补。

```text
工程保存并热重载
  → 生成新 ProjectRevision
  → RealtimeStreamCoordinator 冻结旧代际分发
  → 删除旧 DataHub 联合订阅和全部会话路由
  → 释放旧设备点位需求计数
  → 尽力发送 project-changed
  → 关闭所有旧代际 SSE 会话
  → 前端删除旧点表、旧值、旧选择和写入上下文
  → 通过低频 HTTP 重新加载当前范围的新点表定义
  → 使用新 ProjectRevision 和新 TagId 建立 SSE
  → 完成新快照后恢复实时显示
```

规则：

- 不复用旧 DataHub Handle；
- 名称相同但类型、权限、路径、数组结构或工程版本变化的点也重新解析；
- 改名等价于删除旧点并新增新点；
- 已删除点必须从浏览器状态和联合订阅中消失；
- 当前组被删除时返回最近存在的父范围，并提示结构变化；
- 旧 StreamId 或旧 ProjectRevision 的迟到帧全部丢弃；
- 重建期间禁用写入；
- UI 写请求携带当前 ProjectRevision，服务端发现版本过期时返回 `409 project_changed`。

为兼容现有外部写入客户端，工程版本前置条件可以使用 UI 专用请求头或可选字段；IGW Web UI 必须携带，旧外部 API 客户端未携带时维持现有服务端校验语义。

## 11. 前端改造

### 11.1 通用流客户端

新增独立的前端流模块，不把 SSE 状态机继续堆入 `Points.vue` 或 `MesFlow.vue`。模块负责：

- 使用 `fetch` POST、现有认证头和 `AbortController`；
- 增量解析跨网络分块的 SSE 文本；
- 校验 StreamId、Sequence、SnapshotId 和 ProjectRevision；
- 管理快照临时 Map、暂存增量、重连和过期状态；
- 暴露按 TagId 更新的状态仓库和按序运行时事件；
- 页面卸载、切换组或工程变化时确定性释放连接。

### 11.2 Quick Client

- 删除自动全量 `/api/v1/values` 轮询和暖机重复轮询；
- 首次点表定义改为按当前设备/组范围通过低频 HTTP 加载，不能下载完整百万点工程；
- 使用 SSE 初始快照和增量更新点值；
- 手动“刷新”改为请求当前流重新同步，不再发起全量 GET；
- 普通 `el-table` 改为虚拟表格，支持最多 10,000 行；
- 只更新变化行，不在每帧复制完整行数组；
- 写入继续 HTTP，成功提示等待 SSE 回读；工程版本过期时阻止写入并重建。

### 11.3 设备和监控页面

- 设备连接、质量、诊断和异常摘要通过运行状态主题推送；
- 健康详情和历史诊断仍可由用户操作时 HTTP 查询；
- SSE 断线只标记页面数据过期，不能把设备显示为真实离线；
- 设备真实在线状态只能由运行引擎协议诊断产生。

### 11.4 MES 流程

- 当前任务和节点状态使用 SSE 状态流；
- 节点流转使用有序运行时事件；
- 取消每秒 `api.mes()` 与完整时间线轮询；
- 用户打开历史时间线时仍通过 HTTP 获取权威历史；
- 工程变化时清空旧任务运行映射并按新任务 ID/GroupRef 重建。

### 11.5 继续使用 HTTP 的页面

- 工程编辑与保存；
- 日志中心和日志保留设置；
- 历史数据和导出；
- 点表目录或组定义的按需加载；
- 数组切片查看和写入；
- 用户、权限、网卡和网关设置。

## 12. 协议适配

### 12.1 OPC UA

活动点由运行引擎建立原生 MonitoredItem/Subscription。DataHub 联合订阅会使这些点保持活动；订阅失败或服务器不支持时继续由现有批量 Read 回退。SSE 不直接建立或管理 OPC UA Session。

### 12.2 MQTT

MQTT 驱动已经订阅 Broker 并缓存最新消息，但当前没有通过 `IDriverSubscriptionProvider` 直接把消息推入 DataHub。改造时需要补齐直接更新路径，避免等待下一次模拟读取周期。MQTT 回调同样必须与网络发送解耦。

### 12.3 请求/响应 PLC 协议

Siemens S7/S7 Plus、Modbus TCP、Mitsubishi MC、Omron FINS、AB/Omron EtherNet/IP 和 Simulator 继续按照运行引擎计划读取。读取到的新值写入 DataHub 后统一触发 SSE。SSE 客户端数量不能使相同点的 PLC 读取次数倍增。

## 13. 配置和迁移

实时流设置至少包含：

| 设置 | 默认值 | 范围/硬限制 |
|---|---:|---:|
| `Enabled` | `true` | UI 实时功能启用 |
| `MaxTagsPerStream` | `10000` | 1～10000 |
| `MaxStreams` | `100` | 1～200，硬上限 200 |
| `HeartbeatSeconds` | `10` | 5～30 |
| `SnapshotIntervalSeconds` | `60` | 15～300 |
| `MaxConcurrentSnapshots` | `4` | 1～16 |
| `DeltaBatchWindowMs` | `20` | 10～100 |
| `CoordinatorQueueCapacity` | `262144` | 有界配置 |

现有 `/api/v1/values` 保留用于外部兼容和诊断，但 IGW Web UI 不再把它作为实时通道。旧工程缺少新增字段时按上述默认值迁移，不修改 PLC 点位、采集周期或 MES 流程配置。

公共外部实时流和 IGW 管理 UI 如果共用端点，必须共用相同鉴权与容量池；不能绕过用户读取分支权限。若后续需要为外部客户单独配额，再作为独立设计扩展，本次不新增第二套数据面。

## 14. 可观测性

监控中心增加只读实时流指标：

- 当前/峰值 SSE 客户端数；
- 当前联合唯一点数和总客户端订阅关系数；
- 每秒 DataHub 输入变化数、合并数和客户端投递数；
- 协调器各分片队列深度、丢弃和处理延迟；
- 每会话待发送点数、有序事件深度、发送字节和最近心跳；
- 快照排队、执行时间、分块数、失败和重新同步次数；
- DataHub 到发送的 P50、P95、P99；
- 慢客户端断开、容量拒绝、鉴权拒绝和工程代际重建次数。

日志必须包含 StreamId、ClientId、用户、工程版本、订阅点数、重置原因和清理结果，但不能记录密码、完整认证头或大批点值。

## 15. 测试和验收

### 15.1 后端单元测试

- 请求验证、精确大小写身份、权限和容量上限；
- SSE 帧顺序、单调 ID、最大帧和跨块完整性；
- 联合订阅首加/末删、引用计数和相同点多客户端；
- 状态合并保留最终值，有序事件不合并；
- 初始/定时快照期间的增量补发；
- 队列丢弃触发重置；
- 会话取消释放全部订阅；
- 工程代际变化清除旧 Handle 和旧会话；
- UI 写入工程版本过期返回 409。

### 15.2 API 集成测试

- POST 流建立、鉴权、快照、增量、心跳和取消；
- 连接数满、点位数超限、请求体超限和无权分支；
- 浏览器断开不影响设备状态；
- 工程热重载后旧流关闭，新流只包含新点表；
- 模拟慢输出时其他流和 PLC 写入仍正常；
- 代理缓冲和响应压缩被正确禁用。

### 15.3 前端测试

- 跨网络分块 SSE 解析；
- 序号缺口、心跳超时、重连退避和取消；
- 快照临时 Map 原子切换；
- 旧 StreamId/ProjectRevision 帧丢弃；
- 页面状态和过期值显示；
- 10,000 行虚拟表格局部更新；
- 工程变化后删除旧点并加载新目录；
- 写入后等待 SSE 实际回读；
- 不再创建 `/api/v1/values` 定时请求。

### 15.4 性能和故障注入

- 注册 1,000,000 点，记录启动时间、稳定内存和 GC；
- 激活 500,000 点，验证需求计划和唯一 PLC 读取；
- 50,000 变化/秒持续至少 30 分钟；
- 200,000 变化/秒突发持续 1 秒；
- 100 客户端分别订阅不同范围；
- 100 客户端订阅相同 10,000 点；
- 100 客户端错峰和集中断线重连；
- 运行期间持续执行批量读取、写入和写后验证；
- 注入慢客户端、网络中断、队列溢出、工程热重载和运行时停止。

验收条件：

- 正常负载 DataHub 到 SSE 发送 P95 ≤ 20 ms、P99 ≤ 50 ms；
- 浏览器收帧到可见行更新 P95 ≤ 20 ms；
- SSE 开启前后 PLC 扫描周期无显著恶化；
- 写入延迟相对无 SSE 基线增加不超过 5%；
- 正常负载 DataHub 和协调器队列零丢弃；
- SSE 故障不产生 PLC Session 重建；
- 过载后最终状态通过重置快照恢复一致；
- 工程热重载后旧订阅关系、旧会话和旧前端点归零；
- 100 客户端长时间运行没有持续内存增长。

性能测试使用 Simulator/DataHub 只能证明 IGW 内部能力。OPC UA、S7、Modbus 等真实 PLC 的扫描周期、写入时延和服务器容量必须分别现场验证，不能用模拟器结果代替。

## 16. 实施顺序

1. 完善流合同、配置、联合订阅协调器和指标，不接前端；
2. 建立可运行 POST SSE 端点和集成测试；
3. 实现前端通用流客户端及快照状态机；
4. 迁移 Quick Client，并同时完成范围点表 API 和虚拟表格；
5. 迁移设备/监控状态；
6. 迁移 MES 流程状态和有序事件；
7. 实现工程代际销毁/重建和写入版本保护；
8. 补齐 MQTT 直接 DataHub 推送；
9. 执行单元、集成、前端、性能和故障注入测试；
10. 在本机模拟器验证后打包安装程序，现场 PLC 验证单独记录。

每一阶段都必须保留可运行、可测试状态。前端页面只有在对应 SSE 后端完整可用后才删除原轮询；不允许在中间版本中既无可用 SSE 又无可见错误状态。
