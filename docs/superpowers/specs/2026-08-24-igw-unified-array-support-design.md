# IGW 统一数组标记完整支持设计

## 1. 背景与目标

当前 IGW 的工程模型已经包含 `TagDef.IsArray`，DCS/KEP 映射也能保存部分数组类型，但数组语义没有贯通到全部驱动和用户入口。西门子 DB 导入会把基础数组展开成多个标记，S7 Classic 仍按标量方法读写，S7 Plus 浏览会丢失数组信息；因此当前存在“配置或导入看起来是数组，但运行时不能把整个数组作为一个标记读写”的断层。

本设计把数组提升为 IGW 的协议无关一等数据类型。对用户而言，一个数组只注册为一个逻辑标记；读取返回完整类型化数组，写入可以覆盖整个数组、一个切片或一个元素。底层协议是否原生支持数组不得改变这一用户语义：原生支持时直接调用协议数组能力，不原生支持时由驱动通过连续块读写和本地编解码实现。

“全部支持”在本设计中明确包含：

- 一维和多维数组；
- 零或非零、正或负的 PLC 下界；
- Bool、Char、Byte、Int16、UInt16、Int32、UInt32、Int64、UInt64、Float、Double、BCD、LBCD、String、WString 和 ByteArray 元素；
- 基础类型数组、结构体数组、嵌套结构体和嵌套数组；
- 完整数组读取、完整数组写入、切片读写和单元素读写；
- Siemens S7 Classic、S7 Plus、OPC UA Client/Server、Omron NJ/NX EtherNet/IP、Omron FINS、Allen-Bradley EtherNet/IP、Mitsubishi MC、Modbus TCP、MQTT 和 Simulator；
- Siemens DB、KEP JSON、OPC UA 浏览和 IGW JSON 工程交换；
- 工程配置、QC、MES 上报/响应回写、REST/DCS 接口和 OPC UA 北向服务；
- 每个数组元素的质量、时间和错误隔离；
- 已有逐元素标记工程的向后兼容。

## 2. 非目标与物理边界

- 不声称所有 PLC 协议都具有“原子写整个数组”的原生操作。IGW 对外提供统一写入语义；底层需要分包时必须报告部分成功，不能伪装成原子成功。
- 不绕过 PLC 的访问保护、优化块限制、符号权限、最大 PDU、最大 CIP 元素数或服务器数组维度限制。
- 不把数组展开为数百万个常驻 `TagDef`、DataHub 槽位或前端响应式对象。逻辑元素通过数组元数据和分页视图访问。
- 不在扫描热路径保存数组历史版本；只保存最新稳定快照。历史功能以后若启用，只能由用户明确选择。
- 不承诺任意网络与 PLC 在任意周期内传输无限大小数组。系统必须显示实际吞吐、分包数、耗时和超期原因。

## 3. 统一工程模型

### 3.1 TagDef 兼容扩展

保留现有 `TagDef.DataType` 和 `TagDef.IsArray`，避免旧 JSON、KEP 映射及外部调用失效。增加可选的 `Array` 定义；`Array == null` 表示标量，旧工程中 `IsArray == true` 但缺少 `Array` 时执行兼容补全或给出明确校验错误。

数组定义至少包含：

- `Rank`：维度数量；
- `Dimensions`：每一维长度；
- `LowerBounds`：每一维 PLC 下界；
- `ElementType`：基础元素类型；
- `ElementStrideBytes`：绝对地址协议中的元素跨度；
- `StringLength`：String/WString 元素容量；
- `Layout`：协议无关的结构体布局；
- `SourceShape`：导入源的原始数组声明，供无损导出和诊断使用。

`TagDef.DataType` 对基础数组继续表示元素类型。结构体数组使用新的 `IgwDataType.Struct`，其 `Layout` 递归描述成员。`ByteArray` 保持现有原始字节块含义；`Byte + Array` 表示类型化字节数组，两者在 JSON 和 UI 中明确区分。

### 3.2 结构体布局

结构体布局由递归字段定义组成，每个字段包含名称、JSON 别名、数据类型、相对字节/位偏移、字符串容量、可选子结构和可选数组定义。布局是配置编译结果，不要求普通用户手写；它主要来自 Siemens DB、S7 Plus 符号、OPC UA DataTypeDefinition、KEP JSON 或模拟器项目导入。

同一结构定义在工程中使用稳定 ID 复用，数组标记只引用结构定义，避免大工程重复保存成员描述。移动组或重命名显示名称不得改变协议地址和结构定义引用。

### 3.3 校验

保存和导入时验证：

- `Rank`、`Dimensions` 和 `LowerBounds` 数量一致；
- 所有维度大于零，元素总数使用受检 64 位乘法，禁止溢出；
- 绝对地址协议具有可计算的元素大小和跨度；
- 结构字段不重叠、位偏移合法，递归结构不存在循环引用；
- String/WString 容量明确且符合协议上限；
- 协议无法推断的数组必须配置维度，不能静默按标量读取。

不设置固定的低元素数量上限。运行时根据可用内存和管理员容量配置进行保护，并在导入/启用前显示预计内存、每轮传输字节和分包数量。

## 4. 运行时数组值与质量

### 4.1 稳定快照

新增不可变 `ArrayValue` 和 `StructArrayValue`：

- `ArrayValue` 保存类型化连续数据、维度、下界和可选元素质量；
- `StructArrayValue` 使用列式成员缓冲保存结构体数组，避免为每个元素创建字典和对象；
- 边界序列化时才物化 JSON 数组或对象数组；
- 大缓冲使用分段池化内存和明确所有权，发布到 DataHub 后在没有读者前不得复用；
- 新扫描只有在内容或质量发生变化时替换快照，不原地修改已发布数组。

一个数组逻辑标记只占一个 DataHub 槽位。数组元素通过编译后的数组句柄访问，不注册 N 个完整路径点位。

### 4.2 元素质量

数组保存扁平行主序的元素质量：

- 全部元素 Good：数组整体 `Good`；
- Good 与 Bad/Uncertain 混合：数组整体 `Uncertain`，界面显示“部分有效”；
- 全部元素 Bad：数组整体使用最具体的 Bad 状态；
- OPC UA 等只返回整个变量质量的协议，把该质量应用到所有元素；
- 分块协议按失败块标记对应元素，成功块继续发布。

北向 JSON 中，Bad 字符串元素输出 `"Bad"`，其他 Bad 元素输出 `null`；同时输出或可查询对应元素质量，避免 `0`、`false` 与真实值混淆。MES 可继续使用 Good 元素，是否允许携带部分 Bad 由任务现有质量策略决定。

### 4.3 写入结果

完整数组、切片和单元素写入统一编译成 `ArrayWritePlan`。结果包含整体状态、成功元素数、失败元素索引与状态。协议需要分包时：

- 已成功分包保持成功，不虚假回滚；
- 后续失败立即停止或按调用方显式选择继续；默认停止；
- 返回 `Partial` 及精确失败范围；
- DataHub 只用 PLC 回读或明确成功的写入结果更新，不能先乐观覆盖全部数组。

## 5. 驱动能力与执行接口

### 5.1 能力描述

在不破坏现有 `IDeviceDriver` 的前提下增加数组能力接口，描述：

- 是否支持原生数组、结构体数组、多维数组和切片；
- 单请求最大元素、字节和维度；
- 是否支持原子完整写；
- 连续块地址和符号地址要求；
- Bool 位打包、字节序、字序和字符串布局。

配置编译器把 `TagDef + ArrayDef + 驱动能力` 编译为不可变的读取/写入计划。扫描热路径不解析名称、维度或结构体成员。

### 5.2 分包与并行

数组读取按设备、DB/内存区、周期和协议限制分包。同一设备默认遵守协议串行要求，不因一个数组创建大量并行 Socket；不同设备继续并行。超大数组使用分段缓冲，所有分块完成后发布一致快照；超时或部分失败时发布带元素质量的部分快照。

这套执行计划与现有百万点任意周期采集设计一致：不为每个元素创建 Timer、任务或消息，只调度数组读取块。

## 6. 各协议实现策略

### 6.1 Siemens S7 Classic

- 非优化 DB 使用起始绝对地址、元素跨度和维度计算连续字节范围；
- Bool 数组按 S7 位序打包/解包；整数和浮点按 S7 大端格式处理；
- String/WString 数组按每元素头部和固定容量跨步；
- 结构体数组按 DB 导入生成的字段偏移和结构跨度列式解码；
- 多维数组按 TIA 行主序映射 PLC 下界；
- 按协商 PDU 自动分包，同一 DB 的坏范围不影响其他 DB 或已成功分块；
- 优化 DB 不使用猜测绝对地址，自动路由 S7 Plus；不可用时给出“优化 DB 需要 S7 Plus/符号访问”的明确诊断。

### 6.2 Siemens S7 Plus

- 扩展 native bridge 的浏览结果，返回数组维度、下界、元素类型、字符串容量和 UDT 布局；
- 不再把浏览结果的 `IsArray` 固定为 `false`；
- 原生符号数组直接读写，原生库不能整结构写入时自动使用成员批写并返回部分状态；
- 认证、权限、符号不存在和固件不支持继续映射为现有细分诊断。

### 6.3 OPC UA Client 与 Server

- 浏览读取 `ValueRank`、`ArrayDimensions`、DataType 和 DataTypeDefinition；
- 基础数组使用原生 Variant 数组；结构体数组使用 ExtensionObject 并根据结构定义解码；
- 写入前把 JSON/运行时数组转换为服务器声明的精确 CLR/UA 类型；
- IGW OPC UA Server 为数组节点设置正确 `ValueRank`、`ArrayDimensions` 和 DataType；
- 结构体节点发布 DataTypeDefinition，客户端不需要依靠点名猜测结构。

### 6.4 Omron NJ/NX 与 Allen-Bradley EtherNet/IP

- 符号数组使用原生数组长度/元素范围能力；
- 支持 `MyArray[index]`、多维索引和结构体成员切片；
- 浏览或导入得到 UDT/结构体定义后组装结构体数组；
- 控制器限制单次元素数时自动分段，不退化成 N 次独立完整连接操作。

### 6.5 Omron FINS、Mitsubishi MC 与 Modbus TCP

这些协议以连续内存区/寄存器为基础，没有统一的远端数组类型。IGW 使用数组配置中的起始地址、维度、元素类型、跨度和字节序整块读取并本地解码：

- Bool 使用位/线圈批量读取；
- 数值按寄存器宽度、字节序和字序解码；
- 字符串和结构体只有布局已知时允许创建；
- 多维数组在传输层扁平化，运行时恢复维度；
- 只要一部分寄存器可用，就保留对应 Good 元素。

### 6.6 MQTT 与 Simulator

- MQTT 接受标准 JSON 数组/对象数组，也支持按 JSON Pointer 从消息中定位数组；
- 写入发布相同结构的 JSON，不把数组转成逗号字符串；
- Simulator 支持生成、编辑和回写全部数组类型及结构体数组；
- 模拟器导入 Siemens DB、KEP JSON 后保留数组定义，用作全部协议的自动化测试数据源。

## 7. 导入、导出与工程迁移

### 7.1 Siemens DB

DB 解析器支持：

- `ARRAY[lo..hi] OF 基础类型`；
- 多维 `ARRAY[a..b, c..d]`；
- `ARRAY OF STRING/WSTRING`；
- `ARRAY OF STRUCT` 和 `ARRAY OF UDT`；
- 嵌套结构体中的数组、数组结构体中的嵌套数组；
- 优化和非优化 DB 的结构保留，非优化块额外计算绝对偏移。

基础数组默认生成一个数组标记；结构体数组生成一个带结构定义的数组标记。工程树可以按需展开逻辑成员预览，但不得为每个元素生成真实 `TagDef`。

### 7.2 KEP/IGW JSON

- 读取并输出 KEP 数组数据类型码；
- KEP 能表达的维度、长度和地址写入标准字段；
- KEP 无法完整表达的下界、结构布局和质量策略写入现有 `igw` 扩展；
- IGW 导出再导入必须无损恢复数组、MES 流程和别名；
- 纯 KEP 导入缺少必要维度时显示待补全项，不静默拆点或按标量运行。

### 7.3 旧工程兼容

- 已有逐元素标记原样加载、采集和回写；
- 不在加载时自动合并，避免改变外部 TagId；
- 提供显式“合并为数组标记”工具，预览名称、维度、地址连续性、MES 引用和北向影响后再执行；
- 新数组也可显式生成兼容元素别名；别名引用同一数组槽位，不增加 PLC 请求；
- 删除、移动数组组时沿用现有 MES 引用清理规则，不能留下幽灵标记。

## 8. 工程配置与 QC

### 8.1 标记编辑

标记属性增加“标量/数组”模式。数组模式提供元素类型、维度、每维下界/长度、字符串容量和高级布局预览。协议浏览或文件导入可识别的字段自动填充；普通用户不需要填写跨度和结构偏移。

数据类型下拉框开放全部数组类型，不再显示不可选的灰色占位项。选择设备和协议后只隐藏确实不可能的原生操作，但连续块逻辑数组仍可配置。

### 8.2 树与点表

工程树中数组是一个节点，显示类型、形状和元素总数，例如 `CellData : Struct[1..10]`。展开时展示结构定义和虚拟索引窗口，而不是创建所有元素节点。搜索可以命中数组名、成员名和带索引路径。

### 8.3 QC

QC 数组视图包含：

- 形状、下界、整体质量、Good/Bad/Uncertain 数量；
- 虚拟滚动和服务端切片，默认只加载可见窗口；
- 多维索引跳转；
- 结构体成员列选择；
- 单元素、连续切片和完整数组写入；
- 写入前类型/长度校验和部分写入结果；
- 实时刷新只更新当前可见切片，不重复传输整数组。

大型数组不会进入 Vue 的全量深响应式对象，也不会因为打开 QC 改变 PLC 的基础采集计划；QC 仅登记可见切片的临时订阅。

## 9. MES 流程语义

- 条件节点可选择数组元素、结构体成员、切片统计或“任一/全部”判断；
- 上报节点可直接选择整个数组、某个切片或结构体成员投影；
- 现有“起始、数量”严格按 PLC 下界解释并在预览中显示实际索引范围；
- JSON 名称和结构成员名称继续允许自定义，默认采用 PLC 名称；
- 响应直写优先复用上报映射，把接口对象数组匹配回 PLC 结构体数组；自定义回写规则覆盖自动映射；
- 某个成员类型或长度不匹配只标记该成员失败，其他成员继续写入；字符串超过 PLC 容量按现有要求截断并报告；
- 接口业务失败仍停留在上报节点，只有满足成功判定时才进入响应直写；
- 数组来源离线或部分 Bad 时按元素质量输出，不把 Good 元素整体判废。

## 10. REST、DCS 与 OPC UA 北向接口

### 10.1 兼容接口

现有标量接口保持不变。DCS `AddTags` 的数组类型增加可选 `dimensions`、`lowerBounds` 和结构定义；OPC UA/S7 Plus 可从服务器推断时允许省略，S7 Classic 等绝对地址协议无法推断时返回明确 400 校验错误。

现有 `ReadTag/ReadTags` 对数组返回 JSON 数组或对象数组。现有 `WriteTag/WriteTags` 接受同形状 JSON；形状不一致时返回期望/实际维度，不执行隐式截断。

### 10.2 大数组接口

增加数组切片接口并进入 Swagger：

- 读取形状和质量摘要；
- 按多维起点和数量读取切片；
- 写入切片或单元素；
- 查询失败元素及状态；
- 订阅可见切片的变化。

接口使用流式 JSON 序列化和响应大小保护。调用方显式请求完整超大数组时允许流式返回，但不会先在内存中创建第二份完整 JSON 对象树。

## 11. 错误处理与诊断

数组错误进入现有设备/DB/点位诊断体系，并补充：

- 数组维度缺失或不匹配；
- 元素类型与 PLC/服务器声明不一致；
- 结构体布局或字符串跨度错误；
- 数组范围越界；
- 协议单包限制导致分包；
- 部分分块超时或地址不可用；
- 完整写非原子及部分成功；
- 优化 DB 误用 Classic；
- OPC UA ExtensionObject 无法解码；
- S7 Plus/UDT 浏览权限不足。

监控中心显示数组总元素、有效元素、失败范围、最近耗时、分包数量和诊断建议。单个坏数组/DB 不得让同设备其他 DB、数组或标量停止采集。

## 12. 性能与容量设计

- 一个逻辑数组一个槽位和一个编译计划，不为元素创建常驻对象；
- 基础数组使用类型化连续/分段缓冲，结构体数组使用列式缓冲；
- 编解码使用 Span 和预计算字段访问器，热路径不反射、不解析字符串地址；
- REST/MES/OPC UA 边界按需物化，不复制未选择成员；
- QC、工程树和搜索全部虚拟化/分页；
- 扫描按 PDU 和驱动限制分块，不按元素发 N 个请求；
- 数组变化检测按分段哈希和质量位图完成，避免每周期深比较百万元素；
- 与百万点设计共用设备调度和过载指标，不增加每数组线程或 Timer。

容量验收至少覆盖单个百万元素数组、多个数组合计百万元素、50 个并行工位、200 ms 全量目标周期和数百元素 10 ms 快速任务。验收必须同时记录 CPU、工作集、GC、请求数、网络字节、平均/P95/P99 周期和 UI 响应；真实 PLC 能力另行认证，不能用模拟器结果代替。

## 13. 测试与验收

### 13.1 模型与序列化

- 所有元素类型的一维、多维、非零/负下界往返；
- 结构体数组、嵌套数组和别名无损保存；
- KEP JSON、IGW 扩展和旧工程兼容；
- 溢出、非法维度、循环结构和地址不足正确拒绝。

### 13.2 运行时

- 完整、切片、单元素读写；
- 部分 Good/Bad/Uncertain 汇总和元素质量；
- Bad 字符串输出 `Bad`，其他类型输出 `null`；
- 分包失败、超时、取消、热重载和缓冲所有权；
- 旧逐元素别名不产生重复 PLC 请求。

### 13.3 驱动矩阵

每个内置驱动至少验证基础数值数组、Bool、字符串、结构体数组、维度、下界、分包、完整写和部分失败。协议不具备远端结构类型时使用已知布局验证逻辑结构数组。S7 Classic 同时验证优化/非优化诊断，S7 Plus 验证匿名/认证和符号权限，OPC UA 验证 Variant/ExtensionObject。

### 13.4 UI、MES 和接口

- QC 百万元素数组不全量渲染，可编辑指定元素和切片；
- MES 上报对象数组及响应自动回写与自定义 JSON 名称；
- 条件任一/全部、起始/数量和非零下界正确；
- Swagger 数组请求响应、形状错误和部分写结果；
- OPC UA Server 的 ValueRank、ArrayDimensions、DataType 和写入；
- 工程导出再导入后数组和采集流程不丢失。

### 13.5 最终验收

实现过程中采用测试先行并持续运行受影响测试，但不发布半成品安装包。只有全部协议、UI、MES、接口、兼容回归和容量测试完成，且安装包 payload 验证通过后，才交付统一版本。任何未通过项必须明确报告，不能以“已注册数组元数据”冒充端到端数组支持。

## 14. 实施边界与顺序

内部实现按依赖顺序推进，但最终统一交付：

1. 数组/结构模型、运行时快照、元素质量和序列化；
2. Simulator、QC 切片和 REST/DCS 数组接口，建立可重复测试基线；
3. Siemens DB 导入、S7 Classic 连续块数组；
4. S7 Plus native bridge、符号数组和 UDT；
5. OPC UA Client/Server 数组与 ExtensionObject；
6. Omron/AB、FINS、Mitsubishi、Modbus、MQTT；
7. KEP/IGW JSON、MES 参数选择、上报和响应回写；
8. 旧工程迁移、完整回归、百万元素性能测试和安装包验证。

每一步必须保持标量路径和现有工程可运行。配置格式新增字段均为可选，运行时接口通过能力扩展而不是一次性破坏全部驱动。
