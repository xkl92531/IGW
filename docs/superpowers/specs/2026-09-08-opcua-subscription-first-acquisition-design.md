# OPC UA 订阅优先采集设计

## 目标

现场性能包显示 PLC9 的本机排队 P95 为 0 ms、本地处理为 0–1 ms、网络无丢包且 RTT 接近 0 ms，但 OPC UA 单次 Read 随节点数近似线性增长到 0.8–4.6 秒。IGW 已经把同周期、同优先级的点位合成一次逻辑批次，每批也只有一次物理 Read；继续增加 Read 批量不能消除服务器逐节点处理成本。

本次改造让同一 OPC UA 端点只建立一条物理 Session，并让 MES 周期需求与 QC/监控一样优先使用 OPC UA 变化订阅填充 DataHub。MES 流程仍按自己的周期执行，但读取 DataHub 内的最新快照，不再为每次流程周期重复向上游发送 Read。

## 会话边界

物理会话按以下会影响连接结果的配置共享：规范化端点 URL、安全策略、匿名或用户名身份、密码、证书信任模式、超时、本地网卡绑定和设备级转发超时。逻辑设备名称、设备 ID 和运行时全路径不进入共享键。

同一端点但认证、安全策略、本地网卡或超时不同的设备仍使用不同 Session。每个逻辑设备继续拥有独立的 DeviceLoop、点表、订阅租约、采集状态、错误诊断、写队列和重载生命周期。移除或重载一个逻辑设备只释放自己的租约；最后一个租约释放时才关闭物理 Session。

共享 Session 的 Read、Write、订阅建立和订阅删除继续经过同一个优先级调度器。写入保持高优先级并直接发往 PLC，不使用缓存代替写入。

## 订阅优先规则

仅在 `scanMode=active`、驱动声明支持订阅且连接正常时启用。订阅候选集包含：

- QC、监控、北向客户端当前引用的点位；
- MES、自动任务等 ScanDemandRegistry 中明确声明的周期点位。

驱动按点位有效周期设置 OPC UA SamplingInterval，并使用一个或多个受上限保护的 Subscription/MonitoredItem 集合。订阅创建后执行一次受服务器能力上限约束的批量首读，确保 DataHub 立即有值。

首读返回 Good 的点位退出轮询计划，后续由变化通知更新 DataHub。首读缺失或返回 Bad 的点位保留在原周期批量轮询计划中；收到后续 Good 通知后自动退出轮询。订阅建立失败时全部点位继续按原计划批量轮询，并在退避后重试建立订阅。

最后一个 QC、监控或 MES 数据需求释放且活动窗口过期后，DeviceLoop 删除自己的上游 Subscription 和 MonitoredItem，停止继续监控这些点位。物理 Session 是否待机保持由现有连接策略决定。

稳定且未变化的点位不会仅因 SourceTimestamp 较旧而补读。OPC UA 的变化订阅在值不变时可以只发送 Publish keepalive；把值时间戳当作链路新鲜度会制造新的轮询压力。Session KeepAlive 失败、共享连接代次变化或订阅租约失效时，DeviceLoop 会关闭旧订阅并回到现有连接恢复与批量读取路径。

## 诊断与兼容

采集性能页继续显示每个逻辑设备的轮询点数、订阅点数和逻辑批次数。共享连接诊断显示同一物理会话的逻辑设备租约数、待处理请求和恢复等待。日志中的订阅建立文案必须说明周期业务从 DataHub 读取订阅快照，只有首值失败点进行周期补读。

S7 Classic、S7 Plus、Modbus、EtherNet/IP、FINS、MC、MQTT 等驱动的连接键和轮询行为不在本次变更范围内。它们继续使用已经实现的同设备、同周期、同优先级逻辑批次与自适应驱动能力。本次只改变 OPC UA，因为只有 OPC UA 驱动提供原生变化订阅并且现场证据指向 OPC UA 服务器逐节点处理。

## 验证

按用户要求不执行 TDD。完成实现后统一验证：

- 相同端点与连接配置的多个逻辑设备只创建一条物理连接，删除一个设备不关闭其余设备的会话与订阅；
- 不同认证、安全策略、本地网卡、超时或端点仍隔离；
- MES 明确周期点位创建订阅，首读 Good 后不再周期 Read，流程读取 DataHub 最新值；
- 首读 Bad 或缺失时只对失败点周期补读，收到 Good 通知后停止补读；
- 订阅失败、断线和重连仍自动回退并恢复；
- 写队列优先级、连接代次和逻辑设备诊断不回归；
- 完整后端、前端和安装包测试通过；本地 OPC UA 模拟器用于证明会话数与请求数下降，真实 PLC 的最终吞吐仍以现场诊断包复测为准。
