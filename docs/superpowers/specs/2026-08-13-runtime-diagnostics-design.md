# IGW 运行诊断分类设计

## 目标

让工程配置和 MES 采集流程直接说明异常发生在哪一层、为什么失败，避免把 PLC 通信、MES 网络和 MES 业务拒绝都显示成笼统的“故障”。同时将设备周期统计改为最近 60 秒窗口，避免历史网络故障长期污染 P95。

## 状态分类

- PLC 通信异常：点位缺失或质量为 Bad，显示具体点位/DB；不等同于 MES 接口失败。
- MES 无响应：连接拒绝、超时、DNS 或网络中断，HTTP 状态为 0；流程停在上报节点。
- 业务 NG：MES 已返回 HTTP 响应，但业务成功条件不满足；展示响应状态和业务错误，流程停在上报节点。

## 设备诊断

设备运行状态继续由 `/api/v1/devices` 提供，但 `detailState/detailMessage` 必须保留驱动原始原因。工程树和通道诊断按结构化代码显示：网络异常、DB/地址不匹配、S7/S7 Plus 协议或符号不匹配、需要认证、认证失败、权限不足、固件不支持、部分在线。

西门子 Classic 读取整批失败但 TCP 会话仍存在时，不再只显示“通道离线”。驱动保留最后一次读取错误，并结合受影响点位地址给出 DB 编号和错误摘要。S7 Plus 原生返回码继续映射为认证、权限、固件、符号/协议等结构化状态。

## 性能指标

平均周期、P95、P99 和点/秒使用最近 60 秒滚动窗口；累计读写成功/失败和累计过期周期保持累计口径。窗口无新样本时返回 0，网络恢复后旧的 2048ms/8192ms 异常会在 60 秒内自然退出统计。

## 验证

- 后端单元测试覆盖滚动窗口淘汰、MES 失败分类、西门子 Classic DB 错误归因。
- Web 单元测试覆盖工程树状态文案和 MES 三类状态。
- 运行后端完整测试、Web Node 测试、类型检查和生产构建。
