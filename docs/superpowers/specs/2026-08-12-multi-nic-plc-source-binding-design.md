# IGW 多网卡工业协议源地址绑定设计

## 背景与根因

服务器安装多个网卡时，Windows 会根据路由表为每条出站连接选择本地源地址。当前 IGW 虽然在通道配置中保存 `networkAdapter`，但运行时驱动没有读取或应用该值。S7、Modbus TCP、Omron、三菱、AB、OPC UA Client 与 MQTT Client 都直接连接目标地址。因此，Ping 可以通过某条路由到达设备，而 IGW 的 TCP 连接仍可能从另一张网卡发出并失败。

本设计让通道选择的网卡真正控制 PLC 出站连接，同时保持协议实现、工程结构和默认行为兼容。

## 目标

- 通道选择具体网卡后，该通道所有受支持的出站 TCP 连接都从该网卡当前启用的 IPv4 发出。
- S7 Classic、S7 Plus、Modbus TCP、Omron FINS TCP、Omron/AB EtherNet/IP 显式消息、三菱 MC TCP、OPC UA Client 与 MQTT Client 使用完全相同的源地址选择规则。
- 默认配置继续交由操作系统选择路由，不改变现有工程行为。
- 网卡失效、地址变化或 TCP/协议握手失败时，诊断信息明确指出失败阶段。
- 不修改 Windows 路由表，不要求额外管理员权限，不改变 PLC 协议报文。
- 重连、读取和回写继续复用同一条已绑定的会话链路。

## 非目标

- 不自动调整网卡 metric、默认网关或系统静态路由。
- 不通过 Ping 判断设备在线。
- 不为 EtherNet/IP 隐式 I/O、UDP、串口或其他非 TCP 数据流增加绑定；当前 IGW 驱动使用的 TCP 显式消息纳入范围。
- 不改变现有扫描周期、熔断或 MES 调度规则。

## 方案选择

采用协议透明的本地 TCP 转发层，而不是分别分叉各个第三方协议库：

1. 选择具体网卡时，IGW 为设备创建仅监听环回网段的临时转发端点。
2. PLC 驱动仍按原方式连接该环回端点。
3. 转发层创建真正的出站 Socket，先绑定所选本地 IPv4，再连接 PLC 的真实 IP 和端口。
4. 建立后只做双向字节转发，不解析或修改 S7/COTP/TLS 数据。
5. 设备断开或驱动释放时，转发连接和监听器同步释放。

这样所有 TCP 驱动都能共享同一个绑定机制。S7 Plus、OPC UA 与 MQTT 使用 TLS 时，TLS 仍然在驱动与目标设备之间端到端完成，转发层只传输字节。

### 首期协议范围

| 驱动 | 真实目标来源 | 默认端口 | 绑定范围 |
|---|---|---:|---|
| Siemens S7 Classic / Plus | 设备 `Endpoint` | 102 | Classic 与 Plus 的全部 TCP 会话 |
| Modbus TCP | 设备 `Endpoint` | 502 | 读写会话 |
| Omron FINS TCP | 设备 `Endpoint` | 9600 | 读写会话 |
| Omron NJ/NX EtherNet/IP | 设备 `Endpoint` | 44818 | 当前驱动使用的 TCP 显式消息；独立环回 IP + 固定 44818 |
| Allen-Bradley EtherNet/IP | 设备 `Endpoint` | 44818 | 当前驱动使用的 TCP 显式消息；独立环回 IP + 固定 44818 |
| Mitsubishi MC TCP | 设备 `Endpoint` | 5000 | 读写会话 |
| OPC UA Client | 通道 `settings.url` | URL 端口 | 发现、会话、浏览、读写 |
| MQTT Client | 设备 `Endpoint` | 1883 | 连接、订阅与发布 |

Simulator、OPC UA Server、MQTT 发布服务以及 IGW Web/REST 监听属于本机服务端或非设备客户端，不使用该出站通道绑定配置。

## 配置模型与兼容性

通道继续使用已有的 `settings.networkAdapter`，但新保存值采用稳定标识并带展示信息：

- `networkAdapterId`：系统网卡 ID，用于同一台机器上的稳定匹配。
- `networkAdapterIpv4`：用户选择时的 IPv4，用于运行时绑定和迁移提示。
- `networkAdapter`：保留当前展示名称，兼容旧工程和 JSON 配置。

解析顺序：

1. 值为空、`默认值` 或 `Default`：不建立转发层，继续使用操作系统路由。
2. 有 `networkAdapterId`：在当前启用网卡中按 ID 查找，再校验其 IPv4。
3. 旧工程只有名称：按名称匹配唯一的启用网卡，并补全 ID 与 IPv4。
4. 无法唯一匹配：不静默切换网卡，设备保持离线，并报告“配置的网卡不可用”。

从其他电脑导入工程时，旧网卡配置继续显示并标记“不可用”；用户重新选择当前服务器网卡后才更新配置。

## Web 配置交互

通道属性的“网络适配器”改为下拉选择，仅列出当前启用且具有 IPv4 的非环回网卡，显示格式为“网卡名称 — IPv4”。第一项为“默认值（由操作系统选择）”。

若工程中保存的网卡当前不存在，下拉框保留该项并显示“不可用”，避免保存时静默覆盖。应用配置后，通道下设备按现有重载流程重建连接，不要求重启 IGW 服务。

网卡枚举由 Runtime 提供只读 API；Web 不自行推断服务器网卡，也不使用浏览器所在电脑的网络信息。

## 运行时组件

### NetworkAdapterResolver

- 枚举当前服务器中状态为 Up、非 Loopback 且具有 IPv4 的网卡。
- 将网卡 ID、名称、IPv4、前缀长度返回给配置页面。
- 根据通道配置解析唯一的本地 IPv4。
- 对网卡失效、无 IPv4、地址已变化和配置歧义返回结构化错误。

### BoundTcpRelay

- 普通驱动监听 `127.0.0.1` 的系统分配临时端口，不暴露到外部网络。
- libplctag 的 EtherNet/IP `Gateway` 不接收自定义端口，因此 AB/Omron 每台设备从受控的 `127.64.0.1` 至 `127.127.255.254` 地址池租用一个独立环回 IP，并在该 IP 固定监听 44818；租约随设备释放。地址池只绑定环回网段，不添加网卡地址或系统路由。
- 每个设备实例拥有自己的转发器，避免不同 PLC 会话互相影响；固定端口协议依靠不同环回 IP 隔离。
- 出站 Socket 在 Connect 前执行 `Bind(localIpv4:0)`。
- 对连接、读写和停止使用取消令牌及有限超时。
- 任一方向结束或失败时关闭双向链路，促使原有设备循环进入重连。
- 只允许驱动建立预期数量的本地会话；S7 混合驱动可同时建立 Classic 与 Plus 两条会话，二者绑定同一个 IPv4。

### 通用端点改写

工程配置始终保留真实设备或服务器地址。工厂创建驱动时：

- 默认网卡：把真实端点直接交给现有驱动。
- 指定网卡：启动转发器，并把环回临时端点交给现有驱动；真实端点只交给转发器。OPC UA 的 `opc.tcp://` scheme、路径和安全配置保持不变，只替换运行时 host/port。

该转换只存在于运行时，不回写工程配置，不影响 JSON 导入导出。

## 在线状态与诊断

设备在线仍以有效的 TCP/协议会话及读取结果为准，Ping 不参与状态判断。

诊断至少记录并展示：

- 目标：`设备或服务器 IPv4:端口`
- 源：`网卡名称 — 本地 IPv4`，或“系统自动选择”
- 阶段：网卡解析、TCP 连接、协议握手、身份验证、读取、写入、浏览、订阅或发布
- 最近错误：包含 SocketError、超时或协议结果，不再只显示“离线”
- 最近成功连接时间和最近断开时间

日志不得记录 PLC 密码或其他凭据。

## 生命周期与并发

- 转发器与设备驱动由同一个设备运行时生命周期拥有。
- 保存并应用、手动重连、停用设备和服务停止时，都先取消连接，再释放驱动和转发器。
- 多个设备可并行连接；每个设备的转发状态隔离。
- 双向复制使用异步流，不为每个数据包创建线程。
- 设置合理缓冲区并保持背压，不缓存无上限数据。

## 错误处理

- 选定网卡当前不可用：立即失败，不回退其他网卡。
- 本地 IPv4 已从网卡移除：立即失败，并提示重新选择。
- 目标 TCP 端口不可达：报告所用源 IPv4、目标地址和 Socket 错误。
- TCP 成功但协议握手失败：保留 TCP 成功证据，并报告对应协议阶段失败。
- 运行中网卡断开：关闭对应转发会话，设备进入现有重连流程；网卡恢复后自动重新解析并连接。

## 测试策略

### 单元测试

- 默认值不创建转发器。
- 按网卡 ID 解析正确 IPv4。
- 旧名称配置能唯一迁移；重名或不存在时明确失败。
- 已保存但不可用的网卡不会被替换。
- 转发器的出站 Socket 实际绑定指定 IPv4。
- 多台 EtherNet/IP 设备获得不同环回 IP，均可在本机固定 44818 端口并行工作，释放后地址可安全复用。
- 双向数据完整传递；任一端关闭后资源释放。
- 所有首期 TCP 驱动都使用所选源 IPv4；S7 Classic 与 Plus 两条会话使用同一个源 IPv4。

### 集成测试

- 使用两个本地测试地址模拟多网卡，在错误地址不可达、正确地址可达时验证绑定结果。
- 对八类首期驱动验证运行时目标被改写为环回转发端点，默认网卡时保持原始端点。
- OPC UA 浏览和 MQTT 订阅/发布经过转发后仍保持协议及 TLS 行为。
- 保存并应用后旧连接释放，新连接使用新选择的 IPv4。
- 断开和恢复网卡模拟条件下，设备状态和诊断按预期变化。
- 无网卡选择的旧工程保持原有直连行为。

### 现场验证

在目标服务器记录以下证据：

1. Runtime 枚举出的网卡名称、ID 与 IPv4。
2. 选定网卡到设备目标 TCP 端口的绑定探测结果。
3. IGW 诊断显示的源 IPv4和目标设备。
4. 现场使用协议的连续读取及写入结果。
5. 至少一次断线重连，确认仍从相同源 IPv4连接。

## 验收标准

- 多网卡服务器选择工业网络所在网卡后，IGW 当前全部出站 TCP 驱动从该网卡 IPv4 发出。
- S7 Classic/Plus、Modbus TCP、Omron FINS/CIP、三菱 MC、AB EtherNet/IP、OPC UA Client、MQTT Client 的连接和自动重连使用统一规则。
- 各协议的读取、写入、浏览、订阅和发布功能不因透明转发改变。
- 未选择网卡的旧工程无行为变化。
- 配置无效时不偷偷改用其他网卡，页面能看见具体原因。
- 全部新增测试、现有后端测试、Web 测试、类型检查和安装包构建通过。
