# IGW 分层采集性能诊断设计

## 背景与目标

现场需要从一次慢采集中区分 IGW 排队、IGW 本地处理、网络链路和 PLC/OPC UA 服务器四层影响。现有采集性能页已经记录批次总耗时、驱动耗时、本地处理、协议请求次数与请求耗时、共享队列等待，但网络没有独立观测值，也没有把证据整理成可解释的归因结论。现场导出的普通日志因此仍需要人工比对。

本次实现把现有指标组合成分层诊断，在不增加 PLC 点位读取的前提下增加低频网络探测、自动归因和诊断包导出。归因必须显示原始证据与置信度。无法区分时显示“证据不足”，不能把 OPC UA 往返时间直接写成 PLC 执行时间。

## 技术边界

OPC UA SDK 调用耗时包含网络传输、PLC 或 OPC UA 服务器排队与处理、响应传输及驱动内部拆批。客户端无法直接取得 PLC 端的请求处理时长。ICMP 往返也不等同于 OPC UA TCP 往返，只能作为同一时段网络健康的辅助证据。

因此诊断结论使用以下名称：

- `IGW共享队列`：有直接计时，可确定。
- `IGW本地处理`：有直接计时，可确定。
- `网络链路疑似`：网络探测与协议请求同时变差时成立。
- `PLC/OPC UA服务器疑似`：网络稳定、IGW排队和本地处理较低，而协议请求持续变慢时成立。
- `请求形态`：拆批、重试、数组或服务端容量限制增加协议请求时成立。
- `证据不足`：网络探测不可用或数据窗口不足时使用。

界面和日志不得只显示“PLC问题”或“网络问题”，必须保留“疑似”及支撑指标。

## 数据采集

### 采集批次

继续使用 `ProtocolOperationTiming` 和 `ScanTimingHistory` 的单调时钟记录：

- 批次开始与实际开始间隔；
- 总耗时、驱动耗时、本地处理耗时；
- 共享调度队列等待；
- OPC UA 实际请求数、累计耗时、最大耗时、失败数、取消数；
- 点位数、样本数、Bad 数、采集块、设定周期、漏期；
- 实际参与本批的 IGW 路径和 NodeId。

批次历史仍为每设备最近 200 条内存记录。性能页查询缓存，不产生额外 PLC Read。成功日志维持约 30 秒限流，异常日志维持现有合并规则。

### 网络探测

为每个唯一的 `(远程PLC IP, 配置的本地网卡IPv4)` 建立一个共享探测器，同一通道下的多个逻辑设备复用结果，禁止为每个点位或每个设备重复探测。

- 默认每 5 秒发送一次 ICMP Echo，超时 1 秒。
- 宿主级 ICMP 最多并发 8 个；相同远程 IPv4 和源 IPv4 的活动逻辑设备共享同一工作器。
- Windows 使用可指定源 IPv4 的探测实现，保证走工程配置的 PLC 网卡；其他平台无法保证源地址时标记为“路由未验证”。
- 保存最近 120 个样本：时间、RTT、成功/超时、源地址、目标地址和错误。
- 连续探测异步运行，不占用 OPC UA 会话、共享调度器或采集线程。
- ICMP 被禁、目标不响应或权限不足时状态为“网络指标不可用”，不产生网络或 PLC 归因。
- 只在状态变化及连续失败达到合并阈值时写网络告警，避免每 5 秒写日志。

网络探测是只读诊断流量，不建立 OPC UA 会话，不读取或写入 PLC 点位。

## 分层归因

归因器接收一条批次记录、批次完成时刻之前 30 秒的网络窗口，以及不包含当前批次的协议基线，输出主因、次要因素、置信度和证据数组。协议基线是先前最多 200 条保留批次各自 `RequestMaxMs` 的 P95；当前批次不参与自己的基线，也没有保留原始单请求序列可供计算单请求 P95。第一版使用固定且可测试的规则，避免现场可调阈值造成不同机器结论不一致。当前批次 `RequestMaxMs` 同时达到该基线的 1.5 倍并至少增加 20 ms 时视为协议请求变慢；没有协议基线时保留测量值，但不归因为网络或 PLC/OPC UA 服务器疑似：

1. 本地处理不低于 50 ms 且占总耗时至少 20%，主因标记 `IGW本地处理`。
2. 共享队列不低于 100 ms 且占驱动耗时至少 40%，主因标记 `IGW共享队列`。
3. 网络窗口至少 6 个有效样本；出现丢包，或当前 RTT 超过稳定基线 P95 的 3 倍且至少增加 20 ms，同时协议请求相对近期基线变慢，标记 `网络链路疑似`。
4. 网络窗口满足至少 6 个有效样本、无丢包且 RTT 稳定；共享队列和本地处理均未达到上述阈值，而协议请求相对近期基线变慢且最大耗时占批次总耗时至少 70%，标记 `PLC/OPC UA服务器疑似`。
5. 实际协议请求数大于 1、发生失败/取消、同会话重试或批量降级时，将 `请求拆分或重试` 加入次要因素。
6. 多条规则同时成立时按直接计时证据优先：本地处理、共享队列、网络疑似、PLC/OPC UA服务器疑似。界面同时列出其余因素。
7. 缺少协议指标或网络数据不足时输出 `证据不足`，不补零、不猜测。

网络稳定只能支持“PLC/OPC UA服务器疑似”，不能把服务器处理时间伪装成已测量值。

## 后端结构

- 在 Abstractions 增加网络样本、网络窗口和批次归因只读契约。
- 在 Core 增加可注入的 `INetworkProbe`、按物理端点共享的探测协调器和纯函数归因器。
- Runtime 根据运行中的 OPC UA 通道创建和释放共享探测租约；工程重载和程序退出时取消后台任务。
- `ScanTimingRecord` 返回与批次时间关联的网络快照及归因，现有字段保持兼容。
- 采集日志追加网络状态、RTT、窗口丢包、归因代码、置信度和证据。未提供的字段写“未提供”，不写成 0。
- 诊断导出使用独立只读 HTTP 端点返回 ZIP。点位读写和实时状态继续走 SignalR；文件下载不承载 PLC 数据操作。

探测器及归因器不得引用前端类型。所有后台任务必须接受宿主取消令牌，并设置并发、超时和历史容量上限。

## 采集性能页面

设备概览增加四层指标：

- IGW队列 P95；
- OPC UA 请求 P95/最大；其中 `ProtocolRequestP95Ms` 是保留批次的每批 `RequestMaxMs` 的 P95，不是原始单请求 P95；
- 网络 RTT P95/丢包率；
- IGW本地处理 P95；
- 最近归因与置信度。

批次表保留现有列。展开行显示分层证据、网络样本状态、请求次数和完整点位列表。颜色只表达严重程度，不替代文字。网络探测不可用时展示具体原因和“无法区分网络与PLC/OPC UA服务器”。

页面增加“导出性能诊断”按钮。导出 ZIP 包含：

- `summary.json`：构建标识、工程版本、采集时间范围和设备概览；
- `batches.csv`：当前缓存中的完整批次字段及归因；
- `network.csv`：网络探测样本；
- `connection-diagnostics.json`：当前及最近恢复的连接异常；
- `README.txt`：字段口径与归因限制。

导出内容不包含密码、授权头、MES请求体或工程密钥。NodeId、IGW路径、远程和本地地址保留，便于现场定位。
`network.csv` 只包含抓取时仍活动的端点工作器所保留的最近 120 个样本；端点租约已经释放后，旧工作器及其样本可以不出现在导出中。最新批次没有网络窗口或最新 RTT 为空时，设备网络指标保持不可用，不沿用旧批次值。

## 日志格式

成功和异常批次统一追加：

`实际协议请求数、请求累计、请求最大、共享队列等待、失败请求、取消请求、网络探测状态、网络RTT、窗口丢包率、归因、置信度、归因证据`。

成功批次沿用 30 秒诊断限流；异常批次沿用错误指纹合并。网络状态仅在正常、不可用和恢复之间变化时记录。长期明细由现有日志滚动与保留设置控制。

## 失败与降级行为

- 网络探测失败不得阻塞、取消或降低 PLC 采集优先级。
- 探测协调器故障时采集性能仍显示现有队列、协议和本地处理指标。
- 导出时某一数据源不可用，ZIP 仍生成，并在 `summary.json` 标记缺失项。
- 工程重载期间结束旧探测租约，禁止旧端点样本混入新工程。
- 页面轮询或 SignalR 断开时保留最后成功快照并明确标记时间，不把旧结论显示为当前结论。

## 验证

- TDD 覆盖成功与异常批次日志、无协议指标的“未提供”字段。
- 归因器表驱动测试覆盖软件排队、本地处理、网络疑似、PLC/OPC UA服务器疑似、拆批和证据不足。
- 探测协调器测试覆盖相同物理端点复用、源地址、5秒节拍、超时、状态恢复、工程重载和取消。
- 运行集成测试证明打开采集性能页和导出诊断不会增加 PLC Read 或 OPC UA 会话。
- API 测试验证 ZIP 文件、字段完整性、容量上限及敏感信息过滤。
- Web 测试覆盖四层指标、展开证据、不可用提示和导出操作。
- 运行完整后端测试、完整前端测试、类型检查和生产构建。

现场验收需要在同一时间窗口对照 KEP 与 IGW，并保存展开批次、网络样本和日志包。验收报告分别标记源码验证、自动化测试和现场证据，不能用模拟器结果替代真实 PLC 结论。
