# MES 流程参数选择器设计

## 背景与根因

MES 流程画布中的采集周期条件、条件节点、上报字段、值分流和回写等配置虽然使用了自动补全控件，但候选点位来自运行时数据面 `GET /api/v1/tags`。该接口依赖授权状态和已启动的 DataHub；新机器未激活、设备待机、PLC 离线、工程尚未热重载时会返回 403 或空列表，导致配置态只能手工输入完整路径。

配置候选项应来自工程配置，而不是运行时数据。用户必须能在 PLC 离线时完成流程设计，并能跨 DB、跨 PLC 选择点位。

## 目标

- 点击参数框即可看到当前任务绑定 DB/结构体的候选点位。
- 支持按点位名、PLC、DB、结构体和完整路径搜索整个工程。
- 当前 DB 优先，其次当前 PLC 的其他 DB，最后是其他 PLC。
- 支持百万点工程，不把全部点位复制到浏览器内存或一次性渲染。
- 保留旧工程中的手工值；候选项不存在时不静默清空。
- 不改变 MES 画布、节点模型和整体配置面板布局。

## 不在本次范围

- 不修改 PLC 采集调度、扫描周期或点位质量逻辑。
- 不把响应 JSON 字段误当成 PLC 点位。响应捕获字段和判断字段继续按响应模型配置。
- 不为搜索建立历史数据库，也不持久化搜索记录。
- 不重构整个 `MesFlow.vue`；只抽取可复用的参数选择器和必要的搜索服务。

## 方案选择

### 方案 A：继续使用运行时 `/api/v1/tags`

改动最少，但未授权、待机、离线和未热重载场景仍不可用，不能解决根因。

### 方案 B：浏览器展开整个工程

离线可用，但百万点工程会在浏览器中产生大量完整路径字符串和组件选项，带来明显内存、初始化和输入过滤成本。

### 方案 C：工程配置搜索接口加远程虚拟下拉（采用）

后端直接遍历当前工程模型并返回有上限的结果；前端只保留当前查询的少量候选项。该接口属于配置管理面，不经过 DataHub 授权门禁，也不主动连接 PLC。

## 后端设计

新增配置态只读接口：

`GET /api/v1/project/parameter-options`

查询参数：

- `q`：可选搜索文本；空值表示打开下拉后的默认候选。
- `scopeGroup`：当前 MES 任务绑定的完整组路径。
- `kind`：`tag` 或 `group`。
- `access`：`read` 或 `write`；回写目标只返回可写点位。
- `limit`：服务端限制在 1 到 100，默认 100。

响应：

```json
{
  "items": [
    {
      "value": "Line1.PLC1.DB1604.AutoStacking.StartFlag",
      "label": "StartFlag",
      "fullPath": "Line1.PLC1.DB1604.AutoStacking.StartFlag",
      "scope": "CurrentGroup",
      "kind": "tag"
    }
  ],
  "truncated": true
}
```

搜索服务直接读取 `host.Project`，不调用 `DataGate()`、DataHub 或设备驱动。它使用三只固定容量结果桶完成排序：当前组、当前设备、其他设备。达到 `limit` 后停止收集；查询可响应 `CancellationToken`，前端新查询会取消旧请求。

为避免百万点工程产生第二份常驻完整路径索引，服务不预先复制全部点位。遍历时复用组前缀；只有命中结果才创建完整点位路径。空查询只遍历当前组。全局查询采用 250 毫秒防抖，且至少输入 2 个字符才搜索当前组以外范围。该成本只发生在人工配置时，不创建采集需求、不连接 PLC，也不进入扫描热路径。

组候选与点位候选分开：`kind=group` 只返回设备内真实组路径，用于结构体基准组；普通条件和读写字段使用 `kind=tag`。

## 前端设计

新增共享组件 `MesParameterPicker.vue`，基于 Element Plus 虚拟选择器实现：

- `filterable`、远程搜索、点击展开。
- 空查询显示当前任务绑定组的前 100 个点位。
- 输入至少 2 个字符后搜索整个工程。
- 每项主标题显示叶子点位名，副标题显示完整路径。
- 使用范围标识区分“当前 DB”“当前 PLC”“其他 PLC”。
- `allow-create` 保留手工输入能力，兼容特殊旧工程。
- 当前值不在候选项时插入只读展示项并标记“当前工程中不存在”，不修改原值。
- 请求失败时显示错误提示，但仍允许保留或手工填写，不阻塞工程编辑。
- 使用请求序号或取消令牌确保较慢的旧查询不能覆盖较新的输入结果。

组件接收 `scopeGroup`、`kind` 和 `access`，不自行理解节点类型。

## 应用范围

点位选择器替换以下 PLC 点位输入：

- 采集周期节点的触发条件点位。
- 条件节点每个分支的条件点位。
- 上报节点字段/结构映射模式中的点位。
- 结构体数量模式为“按点取”时的数量点。
- 值分流节点的判值点。
- 回写节点的目标点和复制来源点。

结构体“基准组”使用同一组件的 `kind=group` 模式。响应变量名、响应字段、JSON 字段名、固定值和参数码不改为 PLC 点位下拉。

## 数据一致性与兼容

- 选择结果仍写入原有 `tagId`、`baseGroup`、`countTagId`、`switchTag` 和 `copyFromTagId` 字段，不改变工程 Schema。
- 保存、自动保存、模板导入导出和运行时执行不需要迁移。
- 工程热重载后搜索接口读取新项目；前端项目 revision 变化时清理查询缓存。
- 删除点位不会自动改写已有流程，编辑时仅显示“不存在”状态，由用户决定更换或保留。

## 错误处理

- 搜索接口参数无效返回 400；工程搜索内部失败返回明确错误，不返回空成功掩盖问题。
- 前端搜索失败保留当前输入，并提供“重新加载候选”入口。
- 无匹配结果显示“未找到工程点位”，不显示 PLC 离线，因为候选来源与 PLC 在线状态无关。
- 结果被截断时显示“继续输入以缩小范围”。

## 测试与验证

后端测试：

- 未授权且 Hub 为空时仍能返回工程点位。
- PLC 离线或无采集任务时仍能返回工程点位。
- 当前组、当前设备、其他设备排序正确。
- 跨 DB、跨 PLC 搜索正确。
- `read`/`write` 权限过滤和 `kind=group` 正确。
- 百万点合成工程只返回有上限的结果，不建立第二份全量前端列表，并支持取消。

前端测试：

- 打开选择器会请求当前组候选，输入后执行防抖全局搜索。
- 所有列出的节点字段都使用共享选择器。
- 旧值不存在时仍保留并显示警告。
- 后到的旧请求不会覆盖新查询。
- 搜索失败不清空现有值。

运行验证：

- 在浏览器中以未连接 PLC 的工程打开 MES 画布。
- 验证当前 DB 默认候选、跨 DB/PLC 搜索、选择后保存及刷新恢复。
- 使用大点位工程检查下拉打开、输入和滚动期间界面无全量渲染卡顿。

## 验收标准

用户无需手工输入完整点位路径即可配置条件、上报、分流和回写；PLC 离线、设备待机或新机器未激活时仍可选择工程已有参数。百万点工程不会把全部候选一次性传给浏览器，旧工程的自定义值不会被静默改写。
