# IGW 安装器静默防火墙规则设计

## 目标

安装或升级 IGW 时，不再依赖 Windows 首次启动 `IGW.Runtime.exe` 时弹出防火墙确认框。安装器静默创建一条入站规则，使 Runtime 在域、专用、公用三类网络中都能被访问，并兼容用户后续修改 REST、OPC UA 等监听端口。

## 方案

- 以安装后的 `{app}\IGW.Runtime.exe` 为目标创建程序级 TCP 入站允许规则，不写死 `48020`、`4840`。
- 规则覆盖 `profile=any`，即域、专用、公用网络。
- 禁止边缘遍历，不额外开放 UDP，也不创建面向其他程序的规则。
- 安装和升级时先按固定规则名删除旧规则，再创建新规则，保证安装路径变更后不会留下失效规则。
- 必须在 Windows 服务启动前完成规则刷新，避免 Runtime 首次监听时触发系统确认框。
- 卸载时按固定规则名删除规则，不影响用户自行创建的其他防火墙规则。
- `netsh` 命令全部隐藏执行。创建或删除失败时记录安装日志，但不阻止主程序安装或卸载。

## 安装流程

1. 安装器完成文件复制。
2. 删除同名旧规则。
3. 为当前 `{app}\IGW.Runtime.exe` 创建 `dir=in action=allow protocol=TCP profile=any edge=no` 规则。
4. 注册或更新 `IGW Gateway` 服务。
5. 启动服务并等待网页健康检查。

## 卸载流程

1. 停止并删除 `IGW Gateway` 服务。
2. 删除安装器管理的防火墙规则。
3. 继续执行文件卸载。

## 验证

- 静态回归测试确认安装脚本包含程序路径、TCP、入站、`profile=any`、安装前刷新和卸载删除逻辑。
- 使用 Inno Setup 编译脚本，确认安装器可成功生成。
- 重新运行 Runtime 全量测试与中文迁移路径自包含启动检查。
- 不在当前开发机执行真实安装，以免覆盖正在使用的 IGW 服务和工程数据；安装行为由脚本回归与编译验证覆盖。
