# OPC UA 在线状态与西门子协议自动识别设计

- 日期：2026-08-11
- 状态：待用户审阅
- 范围：IGW Runtime、工程配置状态展示、独立多协议 PLC 模拟器

## 1. 背景与问题

当前存在两个彼此独立的问题：

1. 已配置的 OPC UA Client 可以浏览服务器并拉取节点，但在没有采集任务时 Runtime 不建立或不保持会话，工程树因此显示“全部待机”。这会让用户误以为连接失败。
2. 独立模拟器界面可以选择 S7-1500，但底层只启动了 Classic S7 服务。IGW 导入的优化 DB 使用符号地址并通过 S7 Plus 读取；Classic 服务只能处理 `DB2100.DBW2` 一类绝对地址，因此表现为 TCP 可连接、读取全部失败，最终显示离线。

型号不是协议模式。S7-1200/S7-1500 既可能使用非优化 DB 的 Classic 绝对地址，也可能使用优化 DB 的 S7 Plus 符号地址，因此不能让用户靠手工选择“Classic”或“Plus”来修正导入结果。

## 2. 目标

- OPC UA 设备只要已建立会话，就显示在线；没有采集需求时显示“在线 · 采集待机”。
- 空闲 OPC UA 会话不创建点位订阅、不轮询点位，不因状态展示产生额外采集负载。
- 模拟器根据 DB 文件或 KEP JSON 的实际内容自动识别 Classic S7、S7 Plus 或混合模式。
- 模拟器提供真实协议端点，让 IGW 只修改正式 PLC 地址即可在模拟器与现场 PLC 之间切换。
- Classic、S7 Plus、OPC UA、欧姆龙协议共享一份内存值；任一协议写入后，其他协议读取立即得到新值。
- 导入结果必须保留结构体、数组、中文注释、类型和可用协议地址。

## 3. 非目标

- 不保存点位历史数据。
- 不要求用户配置“普通通道”“极速通道”或手工选择 Classic/S7 Plus。
- 不因为 OPC UA 在线状态而自动激活所有点位。
- 不把“浏览 OPC UA 成功”当作已保存设备的运行状态；浏览仅用于配置诊断。
- 首版不承诺未经实测的所有第三方 S7 Plus 客户端兼容性。IGW 当前 S7 Plus 客户端的端到端兼容是发布门槛，其他客户端按实测结果标注。

## 4. OPC UA 空闲在线策略

### 4.1 连接策略

在驱动能力中增加明确的空闲连接策略：

- `DisconnectWhenIdle`：无采集需求时允许断开，状态为待机。
- `KeepSessionWhenIdle`：无采集需求时保持轻量会话，但不读取点位。

OPC UA Client 默认使用 `KeepSessionWhenIdle`。其他现有驱动沿用当前策略，避免扩大行为变化。

Runtime 对已保存、已启用的 OPC UA 设备执行以下状态机：

1. 启动或配置应用后，建立 OPC UA Session。
2. Session 建立成功即进入 `Online`。
3. 没有 MES、监控或 API 读取需求时，读取计划为空，订阅数为零，状态文案为“在线 · 采集待机”。
4. 出现读取需求后，按现有需求调度器建立订阅或读取计划，状态文案为“在线 · 采集中”。
5. 需求消失后销毁点位读取计划，Session 继续保持。
6. Session 断开时进入“重连中”；超过重连阈值后显示“离线”，不能回退显示“待机”。

### 4.2 在线判定

在线判定以 Runtime 的已保存设备会话为准，不以浏览窗口的临时连接为准：

- Session 已激活且安全通道有效：在线。
- Session 已激活、活动点位为 0：在线 · 采集待机。
- 正在重建 Session：重连中。
- 连接失败或服务端不可达：离线，并保留最近错误与发生时间。
- 设备未启用或驱动策略明确不连接：待机。

工程树、诊断窗口和监控中心必须复用同一 Runtime 状态，不允许前端自行推断在线状态。

### 4.3 性能边界

- 空闲在线只保留 OPC UA SecureChannel、Session 与协议规定的保活，不读取业务点位。
- 不为展示在线状态创建全量 Subscription 或 MonitoredItem。
- 重连使用带抖动的指数退避；手动“重连”可以立即触发一次，但不能形成忙循环。
- 诊断计数分别展示会话保活与业务读取，避免把保活误计为采集。

## 5. 西门子协议自动识别

### 5.1 DB 文件识别

导入西门子 DB 时，以源文件属性和可生成地址为证据：

| 导入证据 | 识别结果 | 地址形式 |
| --- | --- | --- |
| `S7_Optimized_Access := 'FALSE'` | Classic S7 | 绝对地址，如 `DB2100.DBW2` |
| 优化访问为 `TRUE` | S7 Plus | 符号地址，如 `DB2100_电芯OCV_DataDB.PLCFlag` |
| 同一导入项目同时出现绝对与符号点位 | Hybrid | 两套端点共享数据 |
| 属性缺失但全部成员可确定绝对偏移 | Classic S7，并显示推断依据 | 绝对地址 |
| 属性缺失且包含无法可靠展开的优化结构 | S7 Plus，并显示警告 | 符号地址 |

识别结果是导入模型的一部分，不能只显示在日志中。每个点保留原始符号路径；能确定偏移时同时保留绝对地址，便于混合模式使用。

### 5.2 KEP JSON 识别

KEP JSON 使用两级证据：

1. 优先读取通道/设备的驱动、型号与协议元数据。
2. 元数据不足时检查点位地址：
   - `DBx.DBX/DBB/DBW/DBD`、M/I/Q 等绝对地址判为 Classic。
   - 完整符号路径判为 Plus。
   - 同一设备同时出现两类地址判为 Hybrid。

存在矛盾时不静默丢点：导入预览显示“自动识别结果、证据、冲突点数”，使用可确定的混合模式，并把无法路由的点标为导入警告。

### 5.3 用户界面

- 删除会误导用户的协议手工选择器，改为只读“自动识别：Classic / S7 Plus / 混合”。
- 显示简短依据，例如“非优化 DB，70 个绝对地址”或“优化 DB，81 个符号地址”。
- 用户可以返回修正源文件或重新导入，但不通过手工切换协议覆盖地址事实。

## 6. 模拟器协议架构

### 6.1 统一模型

导入管线生成统一模型：

- `SimulationProject`
- `SimulationDevice`
- `DetectedSiemensProfile`：`Classic`、`Plus`、`Hybrid`
- `SimulationTag`：逻辑路径、数据类型、注释、数组/结构层级、Classic 地址、Plus 符号地址、OPC UA NodeId、Omron 地址
- `SimulationValueStore`：按稳定逻辑标识存储当前值与质量

结构体和数组保留层级，不因某个协议需要扁平叶子而破坏模型。各协议可生成自己的叶子索引，但 UI 和后续导出仍保留原结构。

### 6.2 端点与路由

- Classic 模式：102 端口提供 S7comm Classic，处理绝对地址。
- Plus 模式：102 端口提供 IGW 当前客户端可协商的真实 S7 Plus 会话，处理符号浏览、读取与写入。
- Hybrid 模式：同一 102 端口先识别握手类型，再路由到 Classic 或 Plus 处理器；不得要求用户配置两个 S7 端口。
- OPC UA：49320 端口发布统一模型的结构化地址空间，并支持浏览、读、写。
- 欧姆龙：按导入设备的协议配置启动真实可连接端点，并映射到统一值存储。

所有协议写操作先执行类型转换和范围校验，成功后原子更新 `SimulationValueStore`。单个字段转换失败只拒绝该字段并记录明确错误，不影响其他独立字段。

### 6.3 S7 Plus 安全与兼容

- 模拟器默认允许匿名连接，符合现有测试用途。
- 支持 IGW 当前 S7 Plus 客户端使用的握手、安全协商、符号解析、批量读写路径。
- 若客户端要求非匿名或更高安全策略，返回可诊断的协议错误，不以进程崩溃或无响应代替。
- Classic 与 Plus 处理器异常必须被会话边界捕获，单个客户端错误不能终止模拟器。

## 7. 兼容与迁移

- 现有非优化 DB 和绝对地址项目继续使用 Classic，无需修改。
- 现有优化 DB 若旧导入结果缺少 `ProtocolAddress`，重新加载时按符号路径补齐并迁移为 Plus；无法补齐时提示重新导入，不能伪装在线。
- 现有混合 KEP 项目升级为 Hybrid，并保留所有可识别点位。
- 已保存、已启用的 OPC UA 设备升级后默认保持空闲 Session；点位激活策略不变。
- 配置保存时持久化识别结果和证据，重启后不能因重新猜测而改变协议。

## 8. 错误处理

- 端口占用：启动前检测并指出占用端口和进程信息，已启动的其他协议服务不受影响。
- 导入错误：先在临时模型中完成解析和校验，成功后一次性替换，失败不破坏当前项目。
- 地址冲突：列出冲突点和来源；不使用最后写入覆盖的静默行为。
- 不支持的 Plus 类型：保留结构节点并标记具体类型，不丢弃整个结构体。
- OPC UA 会话失败：保留状态码、端点、安全策略和最近失败时间，树上显示离线而非待机。

## 9. 测试策略

实现必须先增加失败测试，再写生产代码：

### 9.1 导入与分类测试

- 非优化 DB 自动识别 Classic，并为所有可读叶子生成绝对地址。
- 优化 DB 自动识别 Plus，并为结构体数组生成完整符号地址。
- KEP JSON 根据显式驱动识别协议；元数据缺失时根据地址识别。
- 混合地址识别 Hybrid，结构体层级、中文注释和全部点位保持不变。
- 导入失败不修改当前模拟项目。

### 9.2 协议回环测试

- IGW Classic 驱动连接模拟器，按绝对地址读写成功。
- IGW Plus 驱动连接模拟器，按符号地址读写成功。
- Hybrid 在同一 102 端口同时接受 Classic 与 Plus 客户端。
- OPC UA 写入后 Classic/Plus 读取到相同值，反向亦然。
- 客户端异常断开、停止服务与重复启动不会导致模拟器进程崩溃。

### 9.3 OPC UA Runtime 测试

- 已启用 OPC UA 设备在零采集需求时建立 Session，状态为 Online，活动点数为 0，业务读取次数不增长。
- 增加需求后开始读取；移除需求后停止读取但 Session 保持。
- 服务端停止后状态依次为重连中、离线；恢复后自动回到在线。
- 工程树、诊断与监控中心显示同一状态和错误。

### 9.4 性能测试

- 多设备空闲 Session 场景验证无业务点位读取、无忙轮询，CPU 保持稳定。
- 大结构导入与浏览使用虚拟化列表，不因数千点位阻塞 UI。
- 10 ms 任务仅激活实际任务点位，不把空闲在线策略扩大为全量扫描。

## 10. 验收标准

1. 模拟器导入非优化 DB 后显示“自动识别：Classic”，IGW 使用绝对地址可读写。
2. 模拟器导入优化 DB 后显示“自动识别：S7 Plus”，IGW 使用符号地址可读写。
3. 混合 KEP JSON 显示“自动识别：混合”，Classic 与 Plus 均可在同一 102 端口工作。
4. 用户不需要也不能通过协议选择器修正导入结果。
5. OPC UA 服务器可达、已保存设备 Session 建立后，工程树显示“在线”；无任务时补充“采集待机”，但不读取业务点位。
6. OPC UA 服务器不可达时显示“离线/重连中”和具体原因，不显示“全部待机”。
7. 任一协议写入后，其他已启用协议能立即读到相同值。
8. 结构体、数组、中文注释和类型在 DB、KEP JSON 导入后完整保留。
9. 自动化测试覆盖分类、Classic/Plus 回环、共享值、OPC UA 空闲在线和异常恢复。
10. 安装包发布前使用实际 IGW Runtime 做端到端连接、浏览、读取、写入和重连验证；未验证的第三方兼容性必须明确标注。
