# 百万点任意周期采集架构设计

## 1. 背景与已确认目标

IGW 面向的项目规模不是固定产线拓扑。工程可能包含约 50 个同时工作的工位，最大约 1,000,000 个点，点位分布在多台 PLC 上。正常大规模任务可能配置约 200 ms 的采集周期，个别只包含几百个点的任务可能配置 10 ms，也允许用户输入其他任意正整数毫秒周期。

用户只配置业务需要的采集周期。页面不得要求用户理解或选择“极速通道”“普通通道”、线程数、优先级、批大小或连接数量；这些全部属于运行时内部实现。

采集数据只要求保存在内存中。本设计不要求按每个扫描周期保存全量历史数据。

本设计的目标是：

- 支持最多约 1,000,000 个已配置且有采集需求的点。
- 支持多台 PLC 并行工作；单台设备异常不得阻塞其他设备。
- 支持每个 MES 任务或点位设置任意采集周期，而不是固定周期档位。
- 相同点位被多个消费者引用时只采集一次，并采用所有有效需求中的最短周期。
- 同一设备内自动合并协议允许的连续或可批量读取范围。
- 过载时不积压已经失去时效的扫描轮次，只保留最新一次待执行需求，并明确报告周期无法满足。
- 没有任何采集、订阅、监控、写入或浏览需求的设备不主动连接。
- MES 跨 PLC 数据范围中，离线 PLC 的字段输出 `null` 和离线质量，其他 PLC 继续工作。
- 工程配置、监控和 Quick Client 在百万点项目中不得全量加载或渲染点表。

## 2. 非目标与边界

- 不承诺 Windows/.NET 提供硬实时保证。10 ms、200 ms 都是目标周期，系统必须报告实际周期、抖动和超期情况。
- 不承诺任意 PLC 数量、任意型号和任意网络条件下都能完成 1,000,000 点/200 ms。IGW 内核不得成为明显瓶颈，但真实吞吐仍受 PLC、协议、连接数、PDU、服务器限制和网络质量约束。
- 不在本工作中保存每轮百万点历史数据。以后启用历史功能时，只能对用户明确选择的子集工作，不得隐式订阅全部点。
- 不改变 MES 画布的整体结构、节点类型和业务执行语义。
- 不让前端直接订阅或接收每轮全部点位更新。

## 3. 用户可见行为

### 3.1 配置

用户继续只设置“采集周期（毫秒）”。允许 10、17、35、83、200、750 等任意正整数周期。保存时不要求用户选择调度分组。

周期需求可以来自：

- 启用的 MES 任务及其数据范围；
- 点位自身的扫描周期配置；
- OPC UA、Quick Client、监控页面、报警、计算点等消费者；
- 写入、浏览和诊断产生的临时设备需求。

一个点存在多个周期需求时，有效周期为最短周期。需求解除后立即重新计算有效周期；设备没有任何需求时按现有按需连接规则断开。

### 3.2 运行状态

运行状态至少显示：

- 用户配置周期；
- 实际最近周期、平均周期、P95 和 P99；
- 最近一次扫描耗时；
- 超期次数与连续超期次数；
- 当前计划中的点数、读取块数和每秒样本数；
- 设备连接、离线、熔断和恢复状态；
- “周期无法满足”的明确原因，例如 PLC 响应慢、请求超时、计划过载或网络异常。

内部采用何种队列、数据块或连接策略不得出现在普通用户配置中。

### 3.3 过载

当某个计划的执行时间超过其周期时：

1. 不为错过的每一轮追加任务；
2. 当前读取完成后，只保留最新一次到期需求；
3. 下一截止时间继续以原始时间轴计算，避免长期漂移；
4. 增加超期计数并更新实际周期指标；
5. 达到连续超期阈值后显示“周期无法满足”，但不静默修改用户配置；
6. 不允许一个慢设备拖住其他设备的调度。

## 4. 总体架构

运行时拆成五个边界明确的单元：

1. `DemandCompiler`：把工程、MES 流程和运行期消费者编译为点位周期需求。
2. `DevicePlanCompiler`：按设备和驱动能力把点位需求编译为协议读取块。
3. `DeviceScheduler`：每台设备一个长期执行器，按任意截止时间调度读取块。
4. `DataPlane`：使用整数槽位和预分配内存保存最新值、质量、时间和版本。
5. `ConsumerDispatcher`：只向真实订阅者分发需要的变化，不广播全部扫描结果。

这些单元通过稳定接口通信。MES 流程不得直接调用 PLC 驱动；它只登记需求并读取 `DataPlane` 中已完成的版本。

## 5. 需求编译

### 5.1 稳定槽位

工程加载时，每个点位获得一个整数槽位。名称、完整路径、设备、DB、数据类型、地址和字节布局只在配置编译阶段解析。扫描热路径只使用整数槽位和已编译地址，不执行字符串分割、全量 `ListTagIds()`、LINQ 分组或工程树遍历。

### 5.2 需求合并

内部需求记录至少包含：

- 消费者标识；
- 设备标识；
- 点位槽位；
- 请求周期；
- 需求类型和生命周期；
- 是否需要变化通知。

同一槽位的有效周期为所有活动需求周期的最小值。相同 MES 流程跨多个 PLC 时，需求先按设备拆分；不同设备计划并行编译和执行。

配置修改只重编译受影响的设备。未修改设备继续采集，不能因保存一个 MES 流程而整体重启百万点工程。

## 6. 设备计划编译

### 6.1 驱动读取计划接口

当前 `IDeviceDriver.ReadAsync(IReadOnlyList<TagBinding>)` 仍可作为兼容入口，但高吞吐驱动需要增加“编译读取计划”和“执行读取块”的能力。计划包含协议已经解析完成的地址、批请求参数、解码布局和目标槽位。

协议适配策略：

- S7：按 PLC、DB 和连续字节范围合并读取，读取后在本地按固定偏移解码。
- Omron EtherNet/IP：按驱动和控制器允许的批量请求大小分组，缓存符号和类型解析结果。
- OPC UA：优先使用服务器订阅与协商后的更新周期；不适用订阅时使用受服务器限制约束的批量 Read。
- 其他驱动：通过能力描述提供最大批大小、连续跨度、并发数和是否支持多连接。

### 6.2 周期与地址联合优化

计划编译器同时考虑周期和地址：

- 同设备、同周期、连续地址优先合并。
- 不同周期的相邻点可以在总成本更低且不延误任何截止时间时合并；被合并点允许比配置周期更快地采集，但不得更慢。
- 大跨度空洞、超出协议最大包或会明显放大快速读取负载时拆分。
- 同一槽位只保留一个最短有效周期，不重复进入多个读取块。

优化结果是内部数据块计划，不改变用户配置值。

## 7. 任意周期调度

### 7.1 每设备隔离

每台设备只有一个长期 `DeviceScheduler`。不同设备可并行执行；同一设备的实际在途请求数量由驱动能力决定，默认串行，驱动明确支持时才允许有限并发。

调度器使用单调时钟和截止时间优先队列。不得为每个点、每个读取块或每个 MES 流程创建永久线程、`Timer` 或周期 `Task`。

### 7.2 无漂移截止时间

读取块保存原始相位和周期。完成一次读取后，下一截止时间从原始时间轴推导，而不是简单使用“当前完成时间 + 周期”。这可以避免慢读取造成扫描周期永久向后漂移。

### 7.3 合并唤醒

同一设备上截止时间足够接近、且合并后仍能满足最短截止时间的读取块可一次执行。合并窗口由计划编译器和驱动开销模型自动计算，用户不可见。

写入继续走设备执行器并有优先级，但必须设置每轮写入预算，避免大量写请求长期饿死读取。

## 8. 内存数据面

### 8.1 最新值存储

每个槽位保存：

- 当前类型化值或值引用；
- OPC/IGW 质量码；
- 源时间或采集时间；
- 版本号。

数值和布尔值使用紧凑、分段的预分配存储。字符串和数组使用池化或稳定引用，只有内容变化时替换。扫描更新不得为每个数值点创建新对象或装箱。

### 8.2 批更新

驱动一次读取块解码后，通过批量接口更新多个槽位。批量更新应：

- 避免每点进行全局字典查询；
- 避免为每点构造变化事件对象；
- 对值、质量或有效时间语义没有变化的点不进入变化分发队列；
- 只对存在点订阅、报警/计算依赖或北向变化订阅的槽位登记脏标记；
- 使用有界脏槽位集合或位图，由订阅端按批次消费。

这一步是百万点性能的必要条件。现有每次 `UpdateByHandle` 都写入变化总线的路径不能用于全量 5,000,000 点值/秒场景。

### 8.3 MES 一致性视图

每个读取块完成时递增版本并记录完成时间。MES 周期到期时记录所需块的目标版本：

- 已在本周期完成的块直接引用其槽位；
- 尚未完成的块等待其本轮完成或任务超时；
- 离线或超时设备对应字段输出 `null` 与坏质量；
- 其他设备的有效数据继续组成上报；
- 组装 JSON 时只遍历该 MES 任务预编译的槽位索引，不遍历工程树，也不复制完整 DataPlane。

跨 PLC 不能伪造完全相同的物理采样时刻。上报快照应保留各来源采集时间，并提供本轮最大时间偏差指标。

## 9. 变化订阅与北向接口

百万点扫描与百万点变化广播是两个不同问题。默认扫描只更新最新值。只有真实消费者需要的点才进入变化分发：

- OPC UA 客户端只接收其订阅节点；
- 监控页面只接收当前可见或选择的点；
- Quick Client 只接收当前查询窗口；
- 报警与计算点使用预编译输入槽位；
- MQTT 和历史功能不得因启用而隐式遍历并订阅全部百万点，除非用户明确选择范围并接受容量告警。

慢消费者使用有界队列和“最新值覆盖旧值”语义，不得反向阻塞设备采集。

## 10. 百万点工程配置与页面

运行内核优化不能解决浏览器全量对象问题。百万点项目需要同时调整配置边界：

- `/project` 不再作为页面每次操作都传输完整百万点对象的唯一接口。
- 工程树按层级懒加载；点表由服务端搜索、排序和分页。
- 点位批量导入在服务端解析并以批次写入，前端不创建百万个 Vue 响应式对象。
- 自动保存发送增量补丁或批次变更，不执行完整工程 `structuredClone`、全量 PUT 和随后全量 GET。
- Quick Client 设置明确的查询范围和分页上限。
- 导出 `.igwproj` 可以生成完整工程文件，但导出属于显式低频操作，不能位于运行热路径。
- 旧工程接口保留兼容窗口，小工程可继续使用；大工程页面自动使用分页接口。

页面查询、展开和搜索不得改变设备采集需求，除非用户明确打开实时值监控；关闭页面后相应临时订阅必须释放。

## 11. 故障、熔断与热重载

本设计复用现有按需连接及 `Closed / Open / HalfOpen` 熔断语义，并补充：

- 熔断按设备隔离；计划中的所有槽位立即变为坏质量。
- 半开只执行驱动允许的最小有效读取块。
- 恢复后从当前最新截止时间恢复，不补跑熔断期间错过的轮次。
- 日志只记录状态转换和聚合统计，不按每次失败或每个坏点刷屏。
- 热重载以不可变计划快照交换；旧计划中正在执行的读取完成或取消后释放，不能同时写入已复用槽位。
- 删除任务、数据范围或点位后立即解除其需求，自动保存后刷新不能恢复已删除配置。

## 12. 性能预算与验收

### 12.1 合成基准场景

建立独立、可重复的无网络合成驱动基准：

- 1,000,000 个点；
- 50 个同时启用的 MES 工位任务，每个约 20,000 点；
- 全量目标周期 200 ms；
- 额外覆盖若干每任务约 500 点、周期 10 ms 的需求；
- 混合布尔、整数、浮点、字符串和数组类型；
- 连续运行至少 30 分钟；
- 同时执行分页查询和一个可见点位监控页面。

第一阶段参考机器定义为现代 x64 处理器 12 核、32 GB 内存、NVMe SSD；合成驱动不计入真实 PLC 和网络等待。验收门槛：

- 无任务队列持续增长；
- 无扫描轮次补跑风暴；
- 10 ms 任务 P99 调度迟到不超过 10 ms；
- 200 ms 任务 P99 调度迟到不超过 50 ms；
- 稳态进程 CPU 不超过参考机器总 CPU 的 50%；
- 稳态工作集不超过 8 GB；
- 稳态热路径分配受控，不出现由逐点更新引起的持续 Gen 2 GC；
- 页面打开后 CPU 增量不超过 5 个百分点；
- 任何一个模拟设备延迟、离线或熔断时，其他设备周期不出现同步阻塞。

这些是 IGW 内核验收门槛，不代表真实 PLC 已通过 200 ms 认证。

### 12.2 真实驱动认证

S7、Omron EtherNet/IP 和 OPC UA 分别建立驱动基准，记录：

- 控制器或服务器型号；
- 固件、协议限制和连接参数；
- 点类型和地址连续程度；
- 每轮请求数、字节数和耗时；
- 实际平均/P95/P99 周期；
- PLC 通信负载、主机 CPU、内存和网络吞吐。

运行页面显示容量实测结果。系统允许用户保存超出实测能力的周期，但必须显示容量告警，不能静默声称已经满足。

## 13. 测试范围

### 13.1 单元测试

- 任意互质周期的截止时间正确且长期不漂移。
- 多消费者最短周期合并与解除需求正确。
- 同设备地址合并、跨度拆分和最大批大小正确。
- 读取耗时大于周期时只保留最新一次，不积压历史轮次。
- 写入预算不会饿死读取。
- 批更新不为无订阅点创建变化事件。
- 慢订阅者不会阻塞采集。
- 删除或热重载后不写入旧槽位。
- 离线设备输出 `null`，其他设备继续形成 MES 数据。

### 13.2 集成测试

- 多设备并行及单设备故障隔离。
- MES 跨 PLC 数据范围的版本等待、超时和时间偏差。
- OPC UA 订阅、Quick Client 可见范围和报警/计算点只登记所需需求。
- 百万点工程分页、搜索、批量导入和增量保存。
- 无消费者时设备不连接；需求出现和消失时自动连接、断开。

### 13.3 回归测试

- 现有 MES 画布节点、上报、判定、回写和等待超时语义不变。
- 现有按需连接、熔断、主备切换和模拟模式行为不变。
- 小工程的配置和运行方式保持兼容。

## 14. 分阶段交付

该改造涉及采集调度、驱动接口、数据面和百万点页面边界，必须分阶段落地：

1. 建立基准与指标，锁定现有性能和回归行为。
2. 引入需求编译器、任意周期调度器和过载合并语义。
3. 引入批量 DataPlane 更新与按订阅分发，移除全量逐点事件风暴。
4. 为 S7、Omron 和 OPC UA 实现协议读取计划。
5. 将工程配置、自动保存、搜索和 Quick Client 改为分页/增量接口。
6. 完成百万点合成压测和各协议真实设备认证。

每一阶段都必须先有失败测试或基准，再修改实现；通过当前阶段验收后再进入下一阶段。任何阶段不得通过降低质量码正确性、隐藏超期或关闭现有功能来换取表面性能。
