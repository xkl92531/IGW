# MES 响应继承上报映射设计

## 目标

MES 流程只在上报节点配置一次 PLC 点位、JSON 名称、结构体别名和缩放系数。接口返回 HTTP 200–299 后，响应直写节点自动使用最近一次成功上报的映射反向写回原 PLC 点位，不要求用户重复配置。

## 数据流

1. 上报节点构造请求报文，并保留本次 `MesPayload` 映射上下文。
2. 解析响应时自动定位 `backResult`、`parameterDic` 或包装层中与上报字段匹配度最高的对象。
3. 普通字段按上报的 `FieldName` 反向写回 `TagId`。
4. 结构体按 `AliasName` 定位数组，按成员 `FieldName` 匹配响应字段，再按数组下标写回原 PLC 结构体。
5. 响应节点中的手工映射仅作为可选覆盖，同一 PLC 目标上手工配置优先。

## 错误隔离

- null、对象或无法直写的复合值不生成单点写入。
- 某一点类型转换、下发或确认失败时，只记录该点失败，其他响应字段继续写入。
- HTTP 非 2xx、超时或连接失败时不执行响应回写。

## 配置保护

重新“填入本组全部点”或自动识别结构体时，保留已有的 `FieldName`、`AliasName` 和缩放系数，防止 `NgReason → ErrorMessage` 等接口契约被静默清空。

## 验收

- 使用实际 `value.backResult.structures` 响应时，`NgReason` 写入 `ErrorMessage`、`IsNg` 写入 `IsNG`。
- `ErrorInfo=""` 写入 `Int16` 失败时，上述其他点仍执行写入。
- 重新自动识别后，用户自定义 JSON 名称保持不变。
- 响应直写界面明确告知用户无需重复配置，手工映射标记为可选覆盖。
