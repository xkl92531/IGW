# 监控中心工位多选筛选设计

## 背景

监控中心当前使用单个 `chFilter` 字符串保存工位筛选。点击新工位会替换旧工位，且选中反馈主要依赖边框和异常列表上方的通道标签，用户难以确认当前筛选范围，也无法同时观察多个相关工位。

## 目标

- 支持同时选择任意多个工位。
- 现场鼠标和触摸屏都可直接操作，不依赖 Ctrl、Shift 等组合键。
- 选中状态在工位卡片和顶部汇总处都清晰可见。
- 未选择任何工位时表示“显示全部”，与现有默认行为兼容。
- 搜索工位名称只影响卡片可见范围，不隐式清除仍然存在的已选工位。

## 方案比较

1. **卡片直接多选并显示复选框（采用）**：点击卡片任意位置切换选择，右上角复选框提供明确反馈。适合鼠标和触摸屏，操作成本最低。
2. **普通点击单选、Ctrl/Shift 扩展多选**：符合部分桌面软件习惯，但触摸屏无法使用，现场用户也容易忘记组合键。
3. **独立多选下拉框**：实现简单，但工位健康卡与筛选控件分离，用户需要在两处来回核对，异常定位效率较低。

## 交互设计

- 每张工位卡右上角放置复选框；点击复选框或卡片空白区域都切换该工位。
- 已选卡片使用蓝色高对比描边、浅蓝背景叠层和勾选图标。原有红、黄、绿健康色保留在左侧状态条和状态圆点上，避免选中色覆盖健康语义。
- 顶部在搜索框后显示 `已选 N 个`，并提供 `清空筛选` 按钮。
- `清空筛选` 将选择集合清空，界面立即恢复显示全部异常。
- 原“显示全部工位”按钮统一改为 `清空筛选`；它只在已选择至少一个工位时出现。
- 再次点击已选卡片会取消该工位；取消最后一个工位后自动回到显示全部。
- 异常列表采用 OR 语义：条目所属工位命中任一已选工位即显示；根因条目只要自身或其折叠子项命中任一已选工位即保留。
- 异常列表上方不再堆叠多个可关闭通道标签，只显示紧凑摘要 `工位筛选：N 个`，详情通过顶部已勾选卡片确认。

## 状态模型

- 将 `chFilter: Ref<string>` 替换为 `selectedChannels: Ref<Set<string>>`。
- 所有增删操作都创建新的 `Set` 实例，以保证 Vue 响应式更新稳定。
- 工位数据刷新后，删除已经不存在的工位名称；临时搜索未命中不会删除选择。
- 工位排序和后台静默轮询保持现状，刷新不得清空选择或展开状态。

## 边界与错误处理

- 选择工位后若该工位当前没有异常，异常列表显示“所选工位当前无异常”，而不是误报“全部正常”。
- 搜索隐藏了某个已选工位时，顶部 `已选 N 个` 仍保留，并提示其中多少个当前被搜索条件隐藏。
- 工位被工程配置删除时，下次数据刷新自动移除对应选择，避免永久空筛选。
- 本功能只改变监控中心前端筛选，不改变服务端异常接口和设备状态计算。

## 测试与验收

- 选择两个工位后，两者相关异常同时出现，其他工位异常隐藏。
- 点击已选卡片可单独取消，点击 `清空筛选` 恢复全部异常。
- 复选框、蓝色选中描边、`已选 N 个` 三处反馈一致。
- 工位搜索、后台轮询、异常排序和展开状态不破坏选择集合。
- 删除工程中的已选工位后，选择集合能够自动清理。
- 增加纯函数/界面回归测试，并通过前端类型检查和生产构建。
