# MES 跨 PLC / 跨 DB 数据范围设计

## 背景

当前 MES 上报任务以一个 `groupRef`（通常是一个 DB）作为主要绑定对象。运行模型中的条件、字段、结构体和回写已经使用完整点位路径，因此可以手工引用其他 DB；但自动填充、结构识别和右侧配置仍围绕单个 DB 展开，并会把点位逐条展开成输入行。

现场业务需要一条流程同时读取两台 PLC 下的多个 DB。一个 DB 或结构体可能包含几千个点，不同结构体的成员也可能完全不同。配置必须保持简单，画布整体结构不能改变，PLC 离线不能阻塞其他 PLC 的数据上报。

## 目标

- 一个上报节点可引用不同设备、不同 PLC 下的多个 DB 或结构体。
- 普通用户只选择“整个 DB”或“整个结构体”，无需逐点配置。
- 自动保留 PLC、DB、结构体层级，并允许设置 MES 输出别名。
- 不同结构体独立建模，不要求字段一致。
- PLC 或 DB 离线时继续上报其他来源，对应数据输出 `null`。
- 几千至上万点配置时，工程文件、配置界面和运行周期都保持可控。
- 兼容现有逐字段、结构体和自定义报文模板配置。

## 非目标

- 不实现两台 PLC 的原子同步快照或时间一致性屏障。
- 不在画布上为每个 PLC、DB 或结构体增加节点。
- 不增加可复用的独立“数据集”节点。
- 不改变现有画布的左侧任务区、中央画布、右侧详细设置三栏结构。
- 不强制转换或重写旧工程的报文结构。

## 已确认的交互方案

### 画布

采用“数据归属于上报节点”的方案。画布继续表达业务步骤：

`采集周期 → 条件 → 上报 → 判定 → 回写`

上报节点只显示摘要，例如：

- `2 PLC · 3 个数据范围`
- `约 3050 点`
- `PLC-B 离线字段 → null`

DB 数量和结构体数量不会增加画布节点数量。选中上报节点后，在右侧点击“配置数据”进入数据范围选择窗口。

### 上报节点右侧详细设置

整体宽度和布局不变，采用“常用项固定 + 高级项折叠”：

1. 始终显示：节点名称、上报地址、等待超时。
2. 始终显示“上报数据”摘要和“配置数据”按钮。
3. “响应与成功判定”折叠区显示成功字段/值摘要。
4. “报文高级设置”折叠区包含附加字段和自定义模板。
5. “响应变量”折叠区显示变量数量并提供管理入口。

折叠标题必须展示已配置摘要，避免用户因为内容收起而误判为未配置。

### 数据范围选择

配置窗口默认只展示已选择的数据范围，每个范围是一行摘要：

- 来源：`PLC-A › DB1604_AutoStacking`
- 范围：整个 DB / 单个结构体
- 规模：点位数、识别到的数组/对象数量
- 输出：默认输出路径或用户别名
- 状态：在线 / 离线（离线策略固定为 `null`）

“添加数据范围”通过可搜索的懒加载树选择整个 DB 或结构体。选择后默认包含所有后代点位并自动识别结构。只有点击“排除少数字段”时才打开字段级高级编辑。

字段级高级编辑使用虚拟滚动和搜索，只渲染可见行，不创建几千个输入组件。

## 配置模型

在 `MesPayload` 中增加数据范围列表，旧的 `Fields`、`Structs` 和 `Append` 保留：

```text
MesDataRange
  SourcePath      完整来源路径（通道.设备.DB[.结构体]）
  Scope           Group / Struct
  OutputPath      默认由设备、DB、结构体名称生成，可设置分层别名
  IncludeMode     All（首版只支持整块包含）
  Excludes        被排除的相对点位路径集合
  OfflineMode     Null（首版固定）
```

新建上报节点默认使用数据范围模式。旧工程继续使用现有逐字段/结构体模式，并在右侧标记为“高级旧版配置”。不自动迁移，不静默改变报文。后续可提供显式“转换为数据范围”操作，但不属于本次首版范围。

同一个上报节点内不允许选择相互重叠的数据范围，例如已经选择整个 DB 后不能再次选择该 DB 下的结构体。界面应提示“已被上级范围包含”。不同范围的 `OutputPath` 不允许冲突，保存校验必须给出具体冲突项。

`groupRef` 继续用于从工程树打开任务、默认定位和兼容旧任务，不再限制上报节点只能使用该组数据。

## 数据结构与 JSON 规则

默认按设备、DB、结构体建立稳定层级：

```json
{
  "PLC_A": {
    "AutoStacking": {
      "Tray": [],
      "Result": {}
    },
    "Recipe": {}
  },
  "PLC_B": {
    "Quality": null
  }
}
```

- 不同范围分别解析自己的字段、对象和数组形状，彼此不要求同构。
- 整台 PLC、整个 DB 或整个结构体不可用时，对应范围的子树直接输出 `null`，不展开成数千个 `null` 字段。
- 设备在线但个别点质量异常、无值或读取失败时，仅该字段输出 `null`。
- 一个来源离线不阻塞其他来源，也不把上报节点判为传输失败；运行状态中显示“某来源离线，已按 null 上报”。
- 即使所有来源都离线，流程仍按既定条件执行并发送结构稳定、值为 `null` 的报文。
- 自定义报文模板仍属于高级模式；使用模板时按现有占位符规则处理，不自动套用分层输出。

## 运行架构

### 范围解析

工程保存并热重载时，将 `MesDataRange` 一次性解析为不可变的运行映射：

- 来源设备和组路径
- 输出路径段
- 点位句柄/完整 TagId
- 对象、数组和字段结构
- 排除集合

解析失败必须阻止应用配置，并指出失效的 PLC、DB、结构体或别名冲突。运行周期内不遍历工程树，不重复做结构识别，也不为枚举结构反复调用全量 `ListTagIds()`。

### 取值

流程触发时，从 IGW 已采集的数据缓存创建本轮只读值快照，不直接向两台 PLC 发起同步阻塞读取。各 PLC 独立采集，互不等待。

值是否有效同时参考：

- 运行时设备在线状态
- 点位质量
- 当前缓存值是否存在

设备离线时不能继续使用断线前残留的“最后好值”。整个来源范围应输出 `null`。

### JSON 生成

使用预解析映射和流式 JSON 写入器生成报文：

- 不构造数千个中间字段配置对象。
- 不反复拼接大字符串。
- 数值、布尔值、字符串和 `null` 保持正确 JSON 类型。
- 输出顺序按用户选择的数据范围和工程树内稳定顺序保持一致，便于现场对比和测试。

## 性能策略

- 工程配置只保存范围和排除项，配置大小与被排除字段数相关，而不是与 DB 全部点数线性相关。
- 数据源树按需展开，搜索使用预建索引。
- 高级字段列表使用虚拟滚动，DOM 行数保持在可见窗口附近。
- 热重载时预编译范围；运行时按预编译映射读取。
- 枚举数组和嵌套对象的元素路径在热重载时确定，不在每个采集周期扫描所有 TagId。
- JSON 预览采用采样/按需生成，关闭预览时不持续构建大报文。

## 状态与错误展示

上报节点的运行详情需要区分：

- 数据完整：所有来源有效。
- 部分数据：列出离线/异常来源数量，说明已输出 `null`。
- 配置错误：来源路径失效、范围重叠、输出别名冲突；阻止保存应用。
- 传输失败：HTTP 超时、连接失败、非 2xx；沿用现有失败和重试机制。

来源离线属于数据质量状态，不等于 HTTP 上报失败。若 HTTP 成功，上报节点仍可完成，但节点详情保留本轮部分数据说明。

## 兼容性

- 旧 `Fields`/`Structs` 配置继续按原逻辑运行。
- 新数据范围模式和旧模式在单个上报节点内互斥，避免同一字段重复输出。
- 旧任务打开、保存和自动保存时不得被静默转换。
- 工程组或设备重命名时，现有引用迁移逻辑需要覆盖 `SourcePath` 和 `OutputPath` 中由来源自动生成的部分；用户自定义别名不得随来源重命名。
- 删除被引用的 DB/结构体时，保存校验必须列出受影响的上报节点，不能静默丢字段。

## 测试与验收

### 后端

- 两台 PLC、多个 DB 同时生成一份分层报文。
- PLC-A 在线、PLC-B 离线时，PLC-A 有值且 PLC-B 对应范围为 `null`。
- 设备离线后不泄漏最后好值。
- 单点质量异常只输出该字段 `null`。
- 多个不同结构体、嵌套对象、索引数组可同时生成且互不串字段。
- 范围重叠、别名冲突、来源删除时保存校验失败并给出具体路径。
- 旧逐字段/结构体任务报文保持不变。
- 10,000 点范围连续构建报文时无每轮全量路径扫描，内存分配和耗时保持稳定。

### 前端

- 上报节点摘要正确显示 PLC、范围和点位数量。
- 右侧常用项固定，高级折叠标题显示配置摘要。
- 数据源树支持跨设备搜索和懒加载。
- 高级字段编辑在数千点时只渲染可见行。
- 整块添加、结构体添加、排除字段、范围重叠提示和别名冲突提示符合设计。
- 旧配置进入高级旧版模式，不被自动改写。

### 现场验收

- 用户可在一个上报节点中选择两台 PLC 下至少三个 DB，并在不逐点操作的情况下保存应用。
- 任一 PLC 断开后，流程继续执行，其他 PLC 数据正常，对应离线范围输出 `null`。
- 包含数千点的结构体不会导致右侧面板长列表卡顿或复杂滚动。
- 画布节点数量和整体布局与现有版本一致。
