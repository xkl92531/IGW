# MES 采集流程空白新建与模板确认覆盖设计

## 背景

工程配置中首次打开某个 PLC DB 的 MES 采集流程时，系统会创建绑定该 DB 的任务，并自动铺设“采集周期 → 条件 → 上报 → 判成败 → 成功/失败回写”流程。自动流程会干扰用户从空白画布设计，也会让该 DB 被判定为“已有任务”，导致保存的流程模板无法套用。

## 目标行为

1. 首次打开尚未配置 MES 任务的 DB 时，只创建一个绑定该 DB、默认停用的空白任务，不自动添加任何节点或连线。
2. 用户从画布工具栏选择内置模板时，始终先显示确认提示；确认后替换当前画布，取消后保持当前画布完全不变。
3. 保存的流程模板允许选择已有任务的单个 DB。目标已有任务时，明确标记“将覆盖”，执行前再次确认。
4. 确认覆盖后保留目标任务的 ID、名称和 DB 绑定，套用模板中的节点、连线、参数及引用映射；任务强制保持停用，等待用户检查后手动启用。
5. 批量套用继续只允许无任务 DB，避免一次操作覆盖多个现场流程。

## 方案选择

采用“保留空白任务，模板可确认替换”的兼容方案。

- 不采用“完全延迟创建任务”，因为当前画布、自动保存、监控定位及任务列表都依赖已绑定任务，改动范围过大。
- 不采用“只有空任务才允许覆盖”，因为用户可能需要用模板重做已有流程，且已明确要求确认后可以使用模板。
- 单组覆盖由后台原子完成，前端不能先删除旧任务再调用套用接口，以免接口失败后丢失原流程。

## 前端交互

### 新建流程

- `createTaskForGroup` 继续创建空的 `flow.nodes` 和 `flow.edges`。
- 删除从工程树右键打开、以及从左侧任务条目首次进入时自动调用标准握手模板的逻辑。
- 空画布保持现有空状态和“添加节点 / 流程模板”入口。

### 内置模板

- `applyTemplate` 对 `handshake`、`timer`、`writeback` 先弹出确认框。
- 空画布提示“确认套用该模板”；非空画布提示将替换当前节点和连线。
- 只有确认完成后才清空并生成模板节点，随后标记为未保存。
- `_save` 和 `_manage` 命令不进入模板覆盖确认。

### 保存的流程模板

- 单组选择器不再禁用已有任务的 DB，而是显示“已有任务，将覆盖”。
- 点击执行时，已有任务目标弹出覆盖确认；无任务目标仍弹出普通套用确认。
- 确认后调用单组模板接口并传入 `replaceExisting: true/false`。
- 批量选择器和“全选无任务组”行为不变，已有任务仍不可选。

## 后端与数据一致性

- 单组套用请求增加 `replaceExisting` 布尔字段，缺省为 `false`，保持旧客户端安全语义。
- `MesFlowTemplateOps.Apply` 先完成模板存在性、目标 DB、引用重写及报告构建，再决定新增或替换任务。
- 当目标已有任务且 `replaceExisting=false` 时，继续返回“目标组已有采集任务”。
- 当 `replaceExisting=true` 时，在原任务索引处替换，保留原 `Id`、`Name`、`GroupRef`、`DeviceRef`，并把 `Enabled` 设为 `false`。
- REST 层仍在工程副本上执行并只在成功后 `ReloadAsync`，任何校验、生成或重载失败都不会删除当前任务。
- 批量接口不增加覆盖参数，继续原子拒绝任何已有任务的目标组。

## 错误处理

- 用户取消确认：不修改节点、连线、任务或工程版本。
- 单组覆盖失败：保留旧任务，显示服务端错误。
- 模板引用在目标 DB 中缺失：沿用现有报告机制，保留引用并提示用户检查，不静默删除字段。
- 套用完成后重新加载工程并定位到被替换任务，避免前端继续持有旧对象或旧版本号。

## 测试

1. 前端回归：首次打开新 DB 不再调用 `applyTemplate('handshake')`，新任务画布为空。
2. 前端回归：内置模板在确认前不修改画布，确认后才替换；取消保持原节点和连线。
3. 模板面板回归：单组允许选择已有任务并传递 `replaceExisting=true`；批量仍禁用已有任务。
4. 核心逻辑回归：默认拒绝覆盖；显式覆盖保留任务 ID/名称/绑定、复制模板流程并强制停用。
5. 核心逻辑回归：模板或目标非法时原任务不变；批量套用仍拒绝已有任务并保持原子性。
