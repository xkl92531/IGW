# Siemens DB 导入、S7 Plus 自动路由与安全认证设计

## 目标

IGW 的一个“西门子 S7”设备同时兼容 S7 Classic 和 S7 Plus。用户只配置 PLC 型号、IP 和常规通信参数，不选择协议模式，也不选择 DB 是否优化。系统根据 PLC 型号、在线能力和每个点位的寻址方式自动路由。

DB/UDT 导入必须保留声明层级和中文注释，展开结构体、数组及其任意嵌套。非优化 DB 生成绝对地址，优化 DB 使用符号路径。S7 Plus 默认匿名连接；PLC 拒绝匿名时明确提示用户启用身份验证，验证成功后把凭据加密保存在本机，不写入工程文件。

## 已确认规则

- S7-1200、S7-1500优先使用 S7 Plus；S7-200、S7-300、S7-400继续使用 S7 Classic。
- 同一台 S7-1200/1500可以同时包含优化和非优化 DB，两类点位可以同时采集。
- 用户不配置“普通/极速通道”“优化/非优化”“S7/S7 Plus”等模式。
- 没有任何采集、订阅、读取或写入需求时，不主动连接 PLC。
- S7 Plus默认匿名连接。
- 匿名被 PLC 明确拒绝时，不自动冒充离线、不显示在线，也不绕过认证切到 Classic；设备进入“待认证”。
- 用户开启身份验证并输入凭据后，必须先通过在线验证才能保存。
- 验证成功的凭据使用 Windows DPAPI 加密保存在当前机器；工程只保存不含秘密的凭据引用。工程上传 Git 或复制到其他电脑不会携带 PLC 密码。
- 工程迁移到新电脑后，凭据引用失效时显示“需要重新验证”，不得清空点位或修改工程结构。
- 所有解析或运行时不支持的类型都必须给出具体路径和原因，不得静默跳过。

## 总体架构

### 统一 Siemens 设备驱动

外部继续只有一个驱动 ID：`Siemens.S7`。设备模型不分裂成 Classic 和 Plus 两种设备，以免用户重复建 PLC 或复制点位。

驱动内部增加三个边界清晰的组件：

1. `ISiemensClassicTransport`：包装现有 IoTClient S7 Classic，负责绝对地址和旧型号 PLC。
2. `ISiemensPlusTransport`：负责 S7-1200/1500 的符号浏览、符号读写、TLS 会话和身份验证。
3. `SiemensRoutePlanner`：根据 PLC 型号、点位地址描述和已探测能力，把批次分配给 Classic 或 Plus。

Plus 实现必须隔离在传输接口之后。当前公开 C# 候选库可以匿名读取优化 DB，但其认证能力不能直接假定为完整；实现阶段必须以支持真实 PLC 身份验证的驱动或内部适配实现为准，并通过实机验证门槛后才能进入安装包。协议库的替换不得影响工程模型、导入器和采集调度器。

### 点位寻址描述

`TagDef.Address` 继续兼容旧工程的 Classic 地址。新导入点位使用明确的地址形式：

- Classic：`DB2100.DBW2`、`DB2100.DBD58`、`DB2100.DBX0.0`。
- Plus：符号路径，例如 `DB2100_电芯OCV_DataDB.CellData[0].KValue`。

实现层为点位生成规范化的 `SiemensAddressDescriptor`，包含寻址种类、DB 编号、绝对偏移、位偏移、符号路径、数据类型和字符串长度。该描述在工程加载或配置热重载时解析并缓存，扫描循环中不得反复解析字符串。

非优化 DB 的导入结果可以同时保留绝对地址和符号路径元数据，以便 Plus 会话可用时进行符号校验；工程的主运行地址仍使用绝对地址，保证 Classic 回退兼容性。优化 DB 没有稳定字节偏移，只保存符号路径。

## DB/UDT 统一解析器

### 解析模型

把当前页面中的正则解析逻辑拆成独立的、可单元测试的词法分析和递归声明解析器。解析器读取 UTF-8/UTF-8 BOM 文本，注释不能在解析前整体删除。

语法树至少包含：

- 标量声明；
- 定长 `STRING`、`WSTRING`；
- 一维及多维数组；
- 内联 `STRUCT`；
- 命名 UDT；
- 数组中的结构体、结构体中的数组，以及任意层级组合；
- DB 优化属性、DB 名称和 DB 编号；
- `//` 行尾中文注释和可识别的块注释。

结构节点递归展开到可采集叶子点。组名沿用声明名；数组下标保留真实下界，例如 `CellData[0]`，界面分组可显示为 `CellData_0`，但内部符号路径不能丢失方括号。

普通数值、位、字符、字符串、时间日期等可转换类型映射到 IGW 数据类型。引用、指针、`ANY`、`VARIANT` 等无法作为普通采集叶子的声明保留在导入报告中，并显示完整路径、原始类型和原因。

### 非优化 DB 布局

非优化 DB 按 Siemens Classic 对齐规则计算偏移。布尔量按位分配；跨越到非布尔类型前完成字节边界对齐；WORD/INT、DWORD/DINT/REAL、64 位类型、STRING/WSTRING、数组和结构体分别执行对应对齐与步长规则。布局器与语法解析器分离，使偏移规则可以用独立夹具验证。

`DB2100_电芯OCV_DataDB.db` 的验收基准：

- 导入70个叶子点，跳过列表为空。
- `CellData : Array[0..10] of Struct` 生成11个结构组，每组6个点。
- `CellData[0].DMCCode` 为 `DB2100.DBB6`，`KValue` 为 `DB2100.DBD58`。
- 每个 `CellData` 元素步长166字节。
- `CellData[10].Errorinfo` 为 `DB2100.DBW1830`。
- `Temperature` 为 `DB2100.DBD1832`。
- `条码`、`K值`、`MES返回NG原因(中文描述)` 等注释进入点位说明。

优化 DB 不计算虚假的绝对偏移，其叶子点直接生成符号路径，并在首次在线绑定时通过 PLC 符号表校验。

## 自动连接与路由

### 按需连接

现有按需连接规则不变。仅当 MES 流程、OPC UA、Quick Client、REST、计划任务或其他消费者对该设备产生数据需求时，才创建传输连接。

S7-200/300/400直接建立 Classic。S7-1200/1500按以下流程处理：

1. 如果设备已配置有效凭据，建立 Plus 会话后直接进行身份验证；否则先匿名建立 Plus 会话。
2. Plus 成功后获取并缓存 DB/符号元数据，绑定所有符号点位。
3. 对绝对地址点位按需建立 Classic 通道；Plus 和 Classic 可在同一设备实例中并存。
4. Plus 协议明确不受该 PLC/固件支持时，只允许绝对地址点位走 Classic。
5. Plus 返回认证要求或认证拒绝时，停止 Plus 重连并进入“待认证”；不得用 Classic 绕过 PLC 安全策略。
6. 网络不可达、端口关闭和超时按设备离线/通信故障处理，不能误报为需要认证。

符号句柄、DB 元数据和路由结果在连接期间缓存。批量读写按传输、扫描周期和连续/可合并范围分组，扫描循环不进行全量符号浏览。

### 状态与诊断

连接状态对用户至少区分：

- 未使用：当前没有数据需求，未连接；
- 连接中；
- 在线；
- PLC/网络不可达；
- S7 Plus 不受支持，已使用 Classic；
- 待认证；
- 凭据错误；
- 权限不足；
- 安全通信配置不兼容；
- 符号不存在或 PLC 程序结构已变化；
- 部分在线：例如 Plus 正常但 Classic PUT/GET 不可用，或某个 PLC 离线。

只有服务端明确返回认证相关结果时才显示“待认证”。错误消息提供下一步操作，但不泄露用户名、密码、加密内容或协议握手细节。

## 身份验证交互

设备默认显示“匿名连接”。普通创建向导不展示凭据字段。

当匿名连接被拒绝时：

1. 工程树设备状态和诊断面板显示“需要身份验证”。
2. 提供“配置身份验证”操作，打开设备级对话框。
3. 用户开启“使用身份验证”，填写用户名（协议/PLC需要时）和密码。
4. 点击“验证并保存”后，Runtime 使用临时凭据建立一次 Plus 会话并完成最小权限读取验证。
5. 只有验证成功才写入本机凭据库和工程中的 `credentialRef`，随后只重连该设备。
6. 验证失败时对话框保持打开，密码不回显、不写日志、不进入工程自动保存。

已配置设备允许执行“重新验证”和“删除本机凭据”。删除后设备恢复匿名模式；如果 PLC 仍要求认证，则再次进入“待认证”。修改 IP、PLC 型号或设备标识后，旧凭据不得自动套用到另一个设备，必须重新确认。

## 凭据安全

工程文件只保存：

- `authMode`：`anonymous` 或 `credential`；
- `credentialRef`：不可推导密码的随机标识；
- 不敏感的认证能力/最近验证状态可以作为运行时状态展示，但不写入工程历史。

用户名和密码作为一个整体保存在 `%ProgramData%\IGW\secrets` 下的本机凭据库：

- 使用 Windows DPAPI 的机器级保护加密；
- 凭据文件 ACL 仅允许 Runtime 服务账户、SYSTEM 和 Administrators；
- 加密数据不复制到安装目录、工程包、Git、日志、诊断导出或崩溃报告；
- REST API 读取工程时永远不返回密码或密文；
- REST 写接口不能直接提交明文密码到通用工程设置字段，只能调用专用“验证并保存”端点；
- 内存中的明文凭据仅存在于验证和建立会话的最短生命周期，异常消息不得包含其内容。

DPAPI 密文复制到其他机器后不可解密。Runtime 遇到缺失或不可解密的 `credentialRef` 时显示“需要重新验证”，工程结构和点位保持不变。

## API 边界

新增专用设备认证操作，而不是把密码混入通用 `PUT /project`：

- 查询设备认证状态：只返回模式、是否存在本机凭据、最后一次认证结果和可执行动作。
- 验证并保存：接收设备 ID、用户名和密码；成功返回凭据引用和连接结果，失败不改变原配置。
- 删除凭据：删除本机密文并把设备恢复匿名模式。

接口必须要求现有 IGW 管理权限，并具备请求大小限制、失败节流和审计事件。审计只记录操作者、设备、时间和成功/失败分类，不记录凭据。

## 失败与恢复

- 认证失败不进入高速重连，保持“待认证/凭据错误”，等待用户操作或配置变化。
- 连接超时和 PLC 离线继续遵守现有熔断策略。
- PLC 在线程序发生变化导致符号失效时，标记受影响点位坏质量，重新浏览一次并尝试按符号重绑定；仍失败则报告具体符号。
- Plus 通道故障不应清空 Classic 点位缓存；Classic 故障也不应把正常 Plus 点位标为离线。
- 多 PLC 场景按设备隔离。一台 PLC 离线或待认证时，其点位为空/坏质量，其他 PLC 继续采集。

## 测试与验收

### 导入器

- 使用 `DB2100_电芯OCV_DataDB.db` 验证70点、全部偏移、结构层级和中文注释。
- 覆盖优化/非优化 DB、命名 UDT、多维数组、结构数组、嵌套结构、STRING/WSTRING、时间日期和位对齐。
- 对不可采集声明验证“保留并报告”，不存在静默跳过。
- 旧 CSV、旧工程和手工 Classic 地址保持兼容。

### 路由与连接

- 1200/1500的符号点走 Plus，绝对地址点走 Classic；同一设备两类点同时工作。
- 200/300/400不尝试 Plus。
- 无数据需求时连接次数保持为0。
- Plus 不支持时只对绝对地址安全回退；认证拒绝时不回退。
- 符号浏览只在连接/结构失效时执行，不进入每次扫描。

### 认证与安全

- 匿名可用时不提示认证。
- 服务端明确要求认证时显示“待认证”。
- 正确凭据验证后保存并恢复连接；错误凭据、权限不足和安全配置不兼容分别显示。
- 验证失败不覆盖原有有效凭据。
- 工程 JSON、API 响应、日志、诊断包和安装包中扫描不到测试密码。
- 把工程复制到另一台电脑后显示“需要重新验证”，不会闪退或丢失配置。
- 非管理员读取凭据库失败；Runtime 服务账户能够解密并连接。

### 发布门槛

- S7 Plus 必须在真实 S7-1200和 S7-1500或等效的受支持 PLCSIM Advanced 环境分别验证匿名、正确凭据、错误凭据、优化 DB 符号读取和混合 DB 路由。
- 完成 .NET 单元/集成测试、前端测试、类型检查和生产构建。
- 在不含开发工具链的干净 Windows 机器安装验证，确认 native 依赖、DPAPI 凭据、重启恢复和卸载升级行为。
- 缺少真实 PLC/仿真环境时只能标记为“自动化测试通过、实机未验证”，不得宣称 S7 Plus 生产验证完成。

## 非目标

- 不绕过 PLC 的访问保护或证书策略。
- 不把用户名密码写入 `.igwproj`、源码、安装包或 Git。
- 不依赖 OPC UA 来代替原生 Siemens 通信。
- 不要求用户手工选择 Classic/Plus 或优化/非优化模式。
- 本阶段不设计集中式跨机器凭据同步；新机器必须重新验证。
