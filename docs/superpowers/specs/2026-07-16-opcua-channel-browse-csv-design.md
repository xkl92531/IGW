# OPC UA 通道配置、选择式标记生成与 KEP CSV 层级导入设计

## 目标

修复 OPC UA Client 在工程配置中的三处不一致：服务器端点错误地落在设备层、CSV 导入丢失标记组层级、自动生成标记只能全量平铺导入。最终交互对齐 KEPServerEX：一个 OPC UA 通道对应一个上游 OPC UA 服务器，设备节点用于组织该服务器内选中的逻辑数据，用户先浏览服务器树并选择，再生成标记。

## 已确认根因

1. `Project.vue` 的 CSV 导入使用 `line.split(',')`，无法可靠解析带引号的 KEP 地址；它还把 `Tag Name` 原样当作叶子名称追加到当前节点，没有把 `LogOff1.AESCM2E_1.Tag` 拆成组路径。
2. `BrowsedTag` 只有叶子 `Name`、`Address`、`DataType`。OPC UA 驱动递归浏览时没有保留父对象路径，因此前端无法还原服务器树。
3. 当前“生成标记(浏览)”拿到所有叶子后直接写入 `device.tags`，没有选择、冲突预览和组结构合并阶段。
4. `OpcUaClientDriverFactory` 当前优先使用 `DeviceDef.Endpoint`，虽然通道设置中已经包含认证和安全策略。这与 KEP 的“通道=服务器连接”模型不一致。

## 方案比较

### 方案 A：通道端点 + 完整路径浏览 + 选择后合并（采用）

服务器 URL、安全策略、匿名/账号、超时均归 OPC UA 通道。浏览结果增加相对路径和数组信息，前端构建可搜索、可多选的树，确认后才合并到设备。旧工程在通道 URL 为空时仍回退到设备端点。

优点是与 KEP 一致、旧工程可继续运行、能同时解决浏览和 CSV 层级问题；代价是需要同时调整驱动 DTO、配置 UI 和导入工具。

### 方案 B：保留设备端点，只增加选择弹窗

实现量较小，但服务器连接仍分散在设备层；同一通道可能指向多个服务器，安全参数却共享，模型继续矛盾，不采用。

### 方案 C：新增独立 OPC 连接实体

连接、命名空间和设备可完全解耦，但需要迁移整个工程模型、运行引擎和 API。当前需求不需要这一级抽象，不采用。

## 配置模型

- OPC UA 通道设置增加并固定使用：
  - `url`：`opc.tcp://host:port`
  - `securityPolicy`
  - `anonymous`
  - `username`
  - `password`
  - `timeoutMs`
- 新建 OPC UA 通道时，向导直接要求填写服务器 URL；通道属性页增加“UA 服务器”分类。
- 新建 OPC UA 设备时不再要求连接地址，设备只填写名称和说明。
- 运行时解析规则：
  1. `channel.settings.url` 非空时始终使用通道 URL。
  2. 通道 URL 为空时，使用 `device.endpoint`，保证旧工程继续运行。
  3. 同一旧通道存在多个不同设备端点时不自动覆盖；界面显示迁移提示，要求用户拆分通道或统一 URL。
- `DeviceDef.Endpoint` 暂不从序列化模型删除，避免旧工程反序列化和回退版本丢失数据。

## OPC UA 浏览与选择导入

### 浏览数据

`BrowsedTag` 增加：

- `Path`：从 OPC UA Objects 下开始的相对对象路径，叶子名不包含在内。
- `IsArray`：变量是否为一维或多维数组。

OPC UA 驱动递归时携带父路径，保留对象层级；标准命名空间节点仍跳过。单次浏览最多返回 10,000 个变量，达到限制时返回截断标志和明确提示，不静默丢失。

### 自动连接

新增仅用于预览的 OPC UA 浏览 API。前端把当前通道中的 URL、安全策略和认证信息提交给 Runtime；Runtime 创建临时 OPC UA Client 会话，完成浏览后立即释放。这样用户不需要先保存工程、等待热重载或创建一个可运行设备，修改端点后即可直接测试并浏览。

API 只接受 OPC UA Client 配置，不保存请求中的密码，也不写工程文件。

### 选择弹窗

设备右键入口名称改为“自动生成标记…”。弹窗包含：

- 连接摘要和“重新连接”按钮。
- 服务器层级树；对象节点可展开，变量节点显示数据类型。
- 名称/NodeId 搜索。
- 点击对象可选择其全部后代变量，点击变量可单独选择；无需 Ctrl。
- 顶部显示“已选 N 个”，提供“清空选择”。
- 确认前显示新增、跳过、冲突数量。

合并规则：

- OPC 对象路径映射为 `TagGroupDef` 递归结构。
- 同路径、同地址的点视为已存在并跳过。
- 同路径但地址不同视为冲突，默认不覆盖；用户勾选“覆盖同路径标记”后才更新。
- 未选节点不写入工程。

## KEP CSV 导入

新增独立的 KEP 标记 CSV 解析器，替换页面内的简单字符串拆分：

- 按 CSV 记录和字段解析，兼容标准双引号转义，也兼容用户样本中 NodeId 内未双写的引号。
- 识别 KEP 表头：`Tag Name`、`Address`、`Data Type`、`Client Access`、`Scan Rate`、`Tag Group`、`Description` 等。
- `Tag Name` 中最后一段是标记名，之前的点分段全部是相对组路径。
- 若存在 `Tag Group`，先使用它，再追加 `Tag Name` 自带的父路径。
- 导入到设备时路径从设备根开始；导入到组时路径相对当前组。
- 应用前先展示解析预览和错误；解析失败时工程保持不变。

对 `PLC4.csv` 的验收结果必须是：44 个标记；根下包含 `LogCheck1`、`LogOff1`；`LogOff1` 下包含 `AESCM2E_1`；所有 NodeId 内部引号完整保留。

## 数组点位

`TagDef` 增加 `IsArray`，默认 `false`，因此旧工程 JSON 无变化。KEP 的 `String Array` 映射为 `DataType=String, IsArray=true`。OPC UA 浏览也根据变量值秩设置该属性。

北向 OPC UA Server 创建变量时：数组点使用 `ValueRanks.OneDimension`，标量继续使用 `ValueRanks.Scalar`。运行时 `DataValue` 已能以引用值承载数组，不需要改变热路径变体结构。

## 错误处理

- URL 为空或格式非法：在连接前直接提示。
- DNS、端口、证书或认证失败：显示服务器返回的具体错误，不创建任何标记。
- 浏览超过 10,000 个变量：展示“结果已截断”，允许用户缩小服务器范围后重试，不允许把截断结果误认为完整结果。
- CSV 缺少必要列、记录引号不闭合、路径段为空：列出行号和原因，整体不导入。
- 类型不支持：列出行号和原始类型，整体不静默降级。

## 非目标

- 本次不把所有协议的设备端点迁移到通道。
- 本次不共享多个设备之间的 OPC UA Session；运行采集仍保持现有每设备驱动实例，避免引入调度回归。
- 本次不自动信任未知的安全证书；沿用现有 OPC UA Client 证书策略。
