# IGW 全驱动自适应采集性能设计

> 2026-09-07 最终修复补充：原计划 1.6.42 已完成并保留；最终审查修复另交付 1.6.43。当前固定版本 s7commplus 0.1.0 无经过核验的 PLC 容量码映射，未知 ProtocolFailure 与本地 ABI BufferTooSmall 不参与容量学习；仅未来底层明确返回 CapacityFailure 时才启用真实 S7 Plus 自动降窗。该保守实施边界已确认，以下容量恢复要求在明确容量类别下成立；不可把契约桩测试当成已验证现场容量识别。

## 1. 背景与现场证据

当前采集引擎已经按设备、周期和优先级生成读取计划，也具备分层采集性能诊断。但现场 `PLC3.PLC3` 的 72 个已配置点位被拆成 34 个读取块，同一设备的完成间隔平均约 644 ms、P95 约 2048 ms，而正常批次本身可以在 10～65 ms 内完成。日志还记录过约 9.5 s 的 S7 TCP 失败、设备离线和随后重连，并反复出现约 0.9～1.0 s 的成功慢批次。

这说明存在两个需要分别处理的问题：

1. 网络或 PLC 通信会间歇性停顿、超时或断线。软件优化不能消除该物理故障，必须继续如实记录。
2. IGW 对已配置点位的读取计划过度拆分。一轮包含的请求越多，任一请求变慢时对整轮完成间隔的放大越明显。

当前 S7 地址解析器把字符串长度当作 1 字节，且 Siemens 混合驱动把 `MaxGap` 固定为 0。现场工程中的字符串实际上占用连续的 PLC 字节范围，例如 S7 `STRING[50]` 包含长度头和 50 字节容量。错误的跨度使原本连续的结构被切碎。工程里虽然保存了 `maxGap=8`，Siemens 运行路径并未使用它，因此用户填写该值既不能解释实际行为，也不应成为获得合理性能的前提。

本设计在现有能力驱动 I/O 引擎上增加自动范围规划、会话级容量学习和全驱动协议计时。用户默认不填写 `maxGap`、批量大小、并发数或 PDU 有效载荷。

## 2. 已确认目标

1. S7 Classic、S7 Plus、OPC UA 以及适合批量读取的 Modbus、三菱 MC、Omron FINS、EtherNet/IP 驱动都使用协议安全的自动批处理。
2. 默认只读取工程中已配置且当前有采集需求的点位；不得因为合并范围而读取整个 DB、整个 OPC UA 命名空间或未配置的符号树。
3. `maxGap` 从普通配置界面移除，默认模式为“自动”。高级设置可显式选择手动上限，用于特殊 PLC 的现场兼容。
4. 自动模式根据真实字段跨度、协议帧或服务上限、当前会话已验证容量和近期结果生成批次，不要求用户理解字节间隔。
5. 同一设备、周期和优先级的到期点位每周期只形成 1 次逻辑轮询任务；驱动以批次完成 P95 和高优先级写入等待为目标，自动选择协议安全的请求规模，不把“请求数绝对最少”当成单独目标。
6. 容量或地址错误只拆分受影响批次；不把容量错误误判为设备离线，不让一个坏点阻塞同设备其他安全范围。
7. MES、QC 和外部点位写入继续走高优先级写队列；同一业务阶段内可以安全批量写，不跨越业务阶段或握手顺序合并。
8. 所有驱动输出统一的队列、请求数、协议耗时、重试、拆分和容量降档指标，现场能够区分 IGW 排队、软件处理、网络疑似和 PLC/服务器疑似。
9. 点位读写及实时状态继续使用已确定的 SignalR 通道；工程配置、流程保存、日志查询和诊断包下载继续使用 HTTP。
10. 打开 QC、看图或采集性能页面不得新增 PLC 读取。页面订阅只消费 DataHub 和运行状态；关闭页面后释放对应的前端实时订阅引用。
11. 完成自动化验证后构建新的 1.6.42 安装包，现场真实 PLC 结果单独作为部署验收证据。
12. 一个 IGW 设备实例只维持一个主协议会话。同一 IP 下的多个设备实例各自拥有独立会话，不按 IP 自动共享；显式配置的备用端点只在切换时成为活动会话。

## 3. 物理边界与非目标

- Windows、普通工业以太网和 PLC 均不是硬实时系统。配置 100 ms 或 200 ms 是调度目标，不保证物理完成时间。
- IGW 不能突破 PLC 的 PDU、服务器 `OperationLimits`、最大会话数、连接质量或扫描周期。
- 客户端无法从一次 OPC UA、S7 或其他协议往返中直接分离“网络传输”和“PLC 内部执行”。归因必须保留“疑似”和原始证据。
- 自动合并允许在两个已配置字段之间读取少量未配置字节，以减少协议往返；这些字节只作为连续块载荷，不创建点位、不进入 DataHub、不推送前端，也不允许越过不可读区域或协议安全边界。
- 每个连续范围的响应只保留到本批解码完成。驱动在这份字节映像中拆出多个已配置点位，再以一个逻辑批次汇总到 DataHub；不建立整 DB 常驻副本，也不让页面访问触发额外 PLC 读取。
- MQTT 和模拟器不需要地址间隔学习。MQTT 由消息推送，模拟器使用内存批量访问。
- 本次不重写现有设备调度器、DataHub、MES 流程引擎或工程存储格式；只扩展现有能力、计划、执行和诊断边界。

## 4. 方案选择

### 4.1 采用：能力驱动的自动范围规划与会话学习

每个驱动声明自己的批处理形态和硬边界。计划器先使用真实字段存储跨度生成安全候选批次，执行器再根据当前会话成功或容量失败的结果调整点数、字节数和并发窗口。该方案能复用现有 `DriverCapabilitySnapshot`、`AddressBlockOptimizer`、`TransferBatchPlanner` 和 `ProtocolOperationTiming`，同时允许不同协议采用不同规则。

### 4.2 不采用：统一固定 `maxGap`

同一个数值对 S7 字节地址、Modbus 寄存器、FINS 字地址和 OPC UA NodeId 没有统一含义。固定值也不能表达 PDU、服务节点上限和单次编码大小，因此不能作为所有驱动的主要性能参数。

### 4.3 不采用：整 DB 或全量符号读取

整 DB 读取可能跨越不可访问范围并显著增加载荷；OPC UA 和 S7 Plus 也没有可安全推导的“整个服务器读取”。IGW 只围绕当前活动的已配置点位生成最小安全范围。

## 5. 总体架构

沿用现有执行链并补齐四个明确职责：

```text
已配置点位 + 当前采集需求
             ↓
  ProtocolStorageSpanResolver
  解析真实起点、长度、区域和不可跨越边界
             ↓
  AdaptiveProtocolPlanCompiler
  根据协议能力和会话画像生成候选批次
             ↓
       DeviceIoScheduler
  保持周期、优先级、写入抢占和在途限制
             ↓
       驱动批量请求执行
  成功学习 / 容量降档 / 故障隔离 / 统一计时
             ↓
    DataHub + 采集性能诊断 + 日志
```

`ProtocolStorageSpanResolver` 只描述协议存储布局，不发起 I/O。`AdaptiveProtocolPlanCompiler` 是纯计划逻辑，输入相同能力和点表时产生相同初始计划。会话学习只改变下一次编译使用的能力画像，不直接修改工程配置。

## 6. 自动模式与 `maxGap` 迁移

### 6.1 配置模型

通道增加批处理模式：

- `Auto`：默认。驱动决定范围合并、点数、字节数和安全并发。
- `Manual`：高级兼容模式。用户可以设置协议支持的上限，但仍不能突破硬安全边界。

普通界面只显示“批处理：自动”。手动设置收进高级区域，并显示单位和风险说明。对 S7 Plus、OPC UA、MQTT 等没有地址间隔语义的协议，不显示 `maxGap`。

### 6.2 旧工程兼容

没有 `batchingMode` 的旧工程按 `Auto` 加载。旧 `maxGap` 保留在工程 JSON/数据库中作为兼容提示值，不直接强迫自动计划合并；导出再导入不得丢失该值。用户显式切换到 `Manual` 后，该值才成为协议允许范围内的手动上限。

这项迁移不会把现有 Siemens `maxGap=8` 当成用户已经确认的调优决策，因为当前 Siemens 路径实际固定使用 0。其他驱动进入自动模式后也必须受既有协议硬上限约束，并在失败时拆分，不能用旧间隔盲目扩大范围。

### 6.3 自动合并决策

自动模式不寻找一个全局 `maxGap` 数字，而是逐个候选范围判断：

1. 只有协议区域、DB、周期、优先级和访问方式相同的点位可以进入同一候选批次。
2. 使用真实字段末端计算中间空隙。字段范围重叠或相邻时直接合并。
3. 存在空隙时，只有增加的载荷仍处于协议安全字节上限，且预计节省一次请求的收益高于读取空隙的成本时才合并。
4. 不跨越驱动声明的不可读边界、数组切片边界、符号根边界或独立服务调用边界。
5. 单批同时受点数、编码后字节数、地址跨度和当前会话窗口限制。
6. 对候选窗口使用正常业务请求的单位载荷耗时进行前后比较。放大后若连续样本使批次预计完成时间恶化超过 20%，回退到上一个稳定窗口并冷却；因此请求数允许增加，只要总完成延迟和写入等待更低。
7. 自动决策记录实际合并空隙、最终块数、窗口回退和限制来源，供页面和日志解释。

初始成本模型使用驱动的保守协议常量，不进行额外 PLC 探测。运行中只利用正常业务请求已经产生的成功、容量错误和耗时样本更新会话画像。

读取执行按设备隔离：不同 PLC 可以并行；同一物理会话只使用驱动声明的安全并发。连续范围读取完成后在本地内存中解码多个点位，汇总本逻辑批次的 `TagSample` 后一次提交给 DataHub。临时响应缓冲区受单请求载荷上限约束，发布后立即释放引用。

会话归属按稳定设备 ID 隔离。会话键由设备 ID、驱动协议、端点、认证/安全参数及机架槽位等连接参数组成；设备 ID 不同，即使 IP 和其他参数相同也不得合并。OPC UA 现有连接池继续负责生命周期、退避和清理，但池键必须包含设备身份。Siemens 同一设备只能选择一种活动访问模式；Plus 回退到 Classic 前先关闭 Plus，会导致 Classic 与 Plus 同时常驻的混合地址配置在保存/加载时给出明确校验错误。

## 7. 字段真实跨度

### 7.1 通用合同

`ProtocolStorageSpan` 至少包含：

- 协议区域或符号根；
- 起始单位与单位类型；
- 实际存储长度；
- 编码后预计请求/响应字节数；
- 对齐要求；
- 是否可与相邻点合并；
- 不可跨越边界及其原因。

无法证明跨度的点位按独立点处理，不能猜测长度后扩大读取范围。

### 7.2 Siemens

S7 Classic 必须依据 `TagDef` 和地址共同计算长度：标量使用 PLC 类型宽度；`STRING[n]` 包含 S7 字符串头和声明容量；`WSTRING[n]` 包含其头部与 UTF-16 容量；数组和结构使用已确认的元素布局、维度和对齐。位地址合并为覆盖所需位的最小字节范围。

计划按 DB 和连续字节范围生成，再按配置或驱动确认的 PDU 安全载荷拆分。PDU 未能协商时使用型号保守值；不得把 `int.MaxValue` 当作 Siemens 最大读取字节数。

S7 Plus 的符号请求没有字节 `maxGap`。标量按兼容符号根和服务容量组成多变量请求；原生数组或结构优先整体或安全切片，无法批量的对象保持独立请求。

## 8. 各驱动策略

| 驱动 | 自动批处理依据 | 容量失败处理 | 订阅行为 |
|---|---|---|---|
| S7 Classic | DB、真实字节跨度、PDU 安全载荷 | 二分拆分范围；单点仍失败时隔离该点 | 无原生订阅，继续周期批读 |
| S7 Plus | 符号根、标量多变量能力、数组/结构切片能力 | 缩小节点窗口；数组切片继续细分 | 按驱动实际能力，不能伪装订阅 |
| OPC UA | `MaxNodesPerRead/Write`、编码大小、会话自适应窗口 | 容量码或服务级超时降窗；健康会话内重试 | 实时点优先 Subscription，只轮询创建监控项失败或数据过期的点 |
| Modbus TCP/RTU | 功能码、站号、连续线圈或寄存器、协议帧上限 | 缩短连续范围并隔离异常地址 | 周期批读 |
| Mitsubishi MC | 设备区、连续设备地址、帧上限 | 缩短连续范围；不跨设备区 | 周期批读 |
| Omron FINS | 内存区、连续字地址、帧上限 | 缩短连续范围；隔离异常字 | 周期批读 |
| EtherNet/IP | CIP 路径、Multiple Service Packet、连接大小 | 减少服务项或报文大小；不因容量错误重连 | 只有真实支持时启用 |
| MQTT | 主题消息 | 不适用 | 消息推送，不建立轮询 |
| Simulator | 内存批量范围 | 不适用 | 内存事件或计划读取 |

驱动如果没有经过验证的原生批量 API，必须保留现有安全行为并在能力快照中标记“批量不可用”，不能在核心层用并行逐点请求冒充批量。

## 9. 会话级自适应容量

每个物理会话分别维护读取、写入和验证读取画像：

- 当前点数窗口、字节窗口和最大安全在途数；
- 最近成功窗口与连续成功次数；
- 最近容量失败、超时、取消和拆分原因；
- 驱动或服务器能力版本；
- 会话指纹和生效时间。

调整规则固定且可测试：

1. 初次连接从协议或型号的保守值开始，服务器明确上限只作为硬上限。
2. 容量状态码、请求/响应过大或 PDU 超限时立即二分降窗，只重试当前失败范围。
3. 单节点或最小合法范围仍失败时，记录逐点错误并继续其余范围。
4. 超时只有在会话健康且同类大批次重复出现时才参与降窗；网络断线和用户取消不作为容量学习样本。
5. 连续 20 个成功批次、请求 P95 未恶化且没有超期时，窗口最多增长 25%；每次只增长一个维度。
6. 降档后的窗口至少保持 60 秒，防止成功一次就立即放大产生振荡。
7. 重连后保留驱动硬上限，清空未经服务器确认的临时增长；相同服务器指纹可复用最近已验证的保守窗口。

自适应画像只驻留运行时。工程重载或驱动能力版本改变时重新编译受影响设备计划。

## 10. 调度、写入与实时状态

设备之间继续并行。同一设备默认遵循驱动声明的有序会话和最大在途数。计划优化不得通过无限增加并发掩盖请求过多。

一个调度周期中的所有到期点位合并为一次逻辑轮询任务。逻辑任务与物理协议请求必须分开计数：例如界面中的“轮询点位 71”表示 71 个点使用轮询采集，不代表 71 次请求；在 PDU 960 且跨 DB 的情况下，一次 71 点轮询任务可能安全拆成约 4～6 个实际 S7 请求。系统不得为了追求“1 个物理请求”跨越 PDU 或服务器限制。

写入进入设备高优先级队列后，可以在以下条件全部相同时合批：同一物理设备、同一业务阶段、同一调用优先级、协议允许批量、没有顺序或脉冲边界。MES/QC 握手的阶段顺序、确认点和写后验证保持不变。采集调度在当前不可中断协议请求结束后让出执行机会，记录实际写入排队时间。

SignalR 负责浏览器与 IGW 之间的点位请求、写入结果和实时状态传播。它不改变 PLC 驱动协议。QC、看图和监控页面只订阅当前可见或业务需要的点位；关闭页面或切换工程时释放前端订阅。OPC UA 原生 Subscription 可继续在没有页面打开时服务 MES/QC 的后台业务需求，但纯 UI 需求的引用归零后必须释放相应监控项。S7 等轮询协议则由统一需求计数决定是否采集，不能因打开一个页面复制第二套设备轮询。

## 11. 统一性能指标与日志

所有实际驱动调用接入同一 `ProtocolOperationTiming`，至少记录：

- 驱动名称、协议操作和物理会话；
- 计划点数、计划范围数、实际协议请求数；
- 每个请求的点数、跨度、有效数据字节、空隙字节和限制来源；
- 调度队列等待、驱动内部会话队列等待、协议调用耗时、本地解码/映射耗时；
- 成功、部分失败、超时、取消、重试、拆分和降窗；
- 降档前后窗口、原因及恢复时间；
- 本地/远端地址、网络 RTT/丢包辅助证据和最终归因。

采集性能页增加“自动批处理”证据：当前安全窗口、原始候选块数、最终请求数、合并节省、最近降档原因。没有某项直接测量时显示“未提供”，不得显示 0。成功明细继续限流写日志，异常、降档和恢复立即记录；诊断 ZIP 包含相同字段，方便现场导出。

设备诊断同时显示设备 ID 的匿名短指纹、会话代次、活动主会话数、重连次数，以及相同远端端点下的设备实例数和活动会话数。不得记录用户名、密码、证书私钥或原始连接键。活动会话数接近驱动已知上限时告警，但不因相同 IP 自动合并设备会话。

概览字段改为不会混淆的口径：`轮询点位`、`订阅点位`、`本周期逻辑批次`、`本批实际协议请求`。原“轮询 / 订阅”保留兼容数据合同，但前端不再把点位数量显示成类似请求次数的文案。展开批次必须展示每个物理请求覆盖的 DB/区域、字节跨度、点位数和耗时。

界面中的“PLC/服务器疑似”仍要求网络稳定、IGW 排队和本地处理较低，并且协议请求显著变慢。S7、S7 Plus 和其他驱动补齐请求计时后才能获得该归因；在此之前保持“证据不足”。

## 12. 错误处理与安全降级

- 容量错误：拆分批次、降低窗口、保持健康连接。
- 地址或权限错误：二分定位到最小范围，逐点报告 IGW 路径、真实地址、质量码和具体错误，其余点继续。
- 网络或会话错误：交给现有重连策略；不得污染容量学习。
- 解码错误：保留原始请求证据并只标记受影响点，不能把整个 DB 写成 Bad。
- 自动规划异常：回退到驱动现有保守计划并记录回退原因，不停止其他设备。
- 诊断或页面故障：不得触发额外 PLC 读取、会话重连或计划重编译。

自动合并产生的未配置间隙数据在驱动本地立即丢弃。任何日志、DataHub、SignalR 或北向接口都只暴露已配置点位。

## 13. 实施范围与顺序

1. 先修正协议字段跨度合同和 Siemens 字符串/数组范围，补齐 PDU 安全能力。
2. 在现有计划器上增加自动合并决策与旧配置迁移，不另建第二套采集循环。
3. 为 S7 Classic、S7 Plus 和 OPC UA 接入会话容量画像、拆分和统一请求计时。
4. 按能力矩阵逐一接入 Modbus、MC、FINS 和 EtherNet/IP；没有可靠批量 API 的驱动明确保持保守模式。
5. 扩展采集性能页面、日志和诊断 ZIP，显示实际计划与降档证据。
6. 完整回归点位读写、MES/QC 优先写、SignalR 实时状态和安装包。

每一步均保持可回退：禁用新的自动计划器后应恢复驱动原有保守批次，不回滚工程数据。

## 14. 验证与验收

### 14.1 自动化测试

- 使用当前 PLC3 的 72 点布局建立脱敏回归夹具：11 组 `STRING[50]`、`REAL`、`WORD`、`STRING[100]` 连续结构及 DB2101 点位。验证真实跨度、解码偏移和工程点值完全一致。
- 验证同周期、同优先级的 72 个到期点只创建 1 次逻辑轮询任务，页面显示“轮询点位 72”，不得显示成 72 次轮询请求。
- 在配置 PDU 960 的夹具中，初始安全计划总读取范围不得超过 6 个，替代当前 34 个；每个范围不得超过计算后的 PDU 有效载荷，也不得跨 DB。
- 验证自动模式只访问夹具中的已配置字段及为连续合并覆盖的内部空隙，不生成额外 Tag、不发布间隙数据、不读取整 DB。
- 表驱动测试覆盖 S7 Classic、S7 Plus、OPC UA、Modbus、MC、FINS 和 EtherNet/IP 的能力边界、批次拆分、单点隔离与无批量能力回退。
- 容量错误测试验证二分降窗不重连；网络断线、取消和停机不参与容量学习；稳定成功达到阈值后只缓慢升窗；放大后单位载荷成本持续恶化时回退到上一个稳定窗口。
- 调度测试验证高优先级写入不会被长读取队列饿死，不跨 MES/QC 阶段合并，并保留写后验证。
- 运行集成测试验证打开/关闭 QC、看图和采集性能页面不会创建重复 PLC Read；关闭纯 UI 消费者后释放需求引用。
- 会话生命周期测试验证一个设备的读、写、订阅和重连复用同一活动主会话；相同 IP 的两个不同设备 ID 使用两个独立会话；OPC UA 不再跨设备共享会话；Siemens Plus 回退前释放旧传输，混合 Classic/Plus 地址被明确拒绝。
- 诊断测试验证每个支持的轮询驱动都能输出请求数、协议耗时和降档原因，未知值保持空值。
- 运行完整后端测试、完整前端测试、Vue 类型检查、生产构建和安装器测试。

### 14.2 性能基准

内存或协议桩基准比较相同点表优化前后：逻辑轮询任务数、物理协议请求数、批次完成 P95、高优先级写入等待、计划编译耗时、批次分配量和本地解码耗时。通过条件为每周期 1 次逻辑轮询任务，PLC3 初始安全计划从 34 个范围降到不超过 6 个，点值和质量完全一致，计划与解码的 IGW 本地 P95 不超过 20 ms；若协议桩模拟大包变慢，自动回退后的批次完成 P95 必须低于继续使用大包的结果。

该基准不宣称真实 PLC 的网络时间。真实设备仍需在同一网络和点表下至少观察 10 分钟，对比请求数、完成间隔 P50/P95、协议请求 P95、超时和重连，并导出诊断包。若仍出现约 1 s 或 9.5 s 的单请求停顿，应按网络/PLC 证据处理，不能归因于前端或本地计划器。

与 KEPServer 的现场 A/B 必须使用同一电脑、网卡、PLC、点表、扫描周期、运行时长和写入脚本，且两者不能同时抢占同一 PLC 会话资源。记录完成间隔 P50/P95、单请求 P95、PLC 请求数/秒、点位吞吐、漏周期、超时、重连、优先级写入 P95、CPU 和工作集内存。首轮持平门槛为 IGW 完成间隔 P95 不高于 KEP 的 105%、写入 P95 不高于 KEP、无新增漏周期；只有这些条件成立后，才能把更低请求量、页面零额外 PLC I/O 或诊断完整性列为超过项。
