# OPC UA 设备根与空流程模板判断设计

## 目标

- OPC UA 浏览树的第一层设备节点只表达远端设备身份，不作为工程标记组或 MES 采集流程边界。
- 设备节点下的业务目录（例如 `DB2100_电芯OCV_DataDB`）才是可独立配置 MES 流程的主数据组。
- 刚进入采集流程产生的空任务不再被误报为“已有流程”，并可直接套用模板。

## OPC UA 导入语义

- 浏览结果中已选点位必须来自同一个第一层设备根；不同设备根不能一次导入到同一个 IGW 设备。
- 导入预览保留设备根用于选择和展示，但生成工程标记路径时剥离该段。
- 设备根显示为“设备”，其目标名称用于 IGW 设备名称；默认设备名或空名称可随远端设备名更新，用户已有的自定义设备名保留且仍可编辑。
- 设备根下面的目录按原层级导入为 `device.groups`；结构和点位重命名继续只改变工程名称，不改变 OPC UA NodeId。
- 再次从同一设备根导入旧工程时，识别同名的历史包装组并安全展开到设备下；迁移相关 MES 引用。若存在无法无损迁移的非空根流程或名称冲突，则阻止自动展开并给出明确提示，不静默丢配置。

## MES 边界

- OPC UA 设备根本身不显示 MES 采集流程入口。
- 设备下直属业务组作为 MES 主边界，内部结构体不重复生成流程入口。
- 工程树右键、一键启停、采集流程任务列表和流程模板目标列表统一使用 `buildMesTaskBoundaries`，避免各处重复推断产生不同结果。

## 空流程判断

- “任务记录存在”和“已有实际流程”分开判断。
- `flow.nodes` 或 `flow.edges` 有内容时才显示“已有流程，将覆盖”的警告。
- 空任务套用模板按新流程展示，不显示覆盖警告；调用后台时仍携带任务记录是否存在，以便安全替换空任务并保持单组单任务约束。
- 批量套用继续保持原子性；空任务允许作为可用目标，非空流程仍不可批量覆盖。

## 验证

- 前端测试覆盖设备根剥离、单设备根限制、设备名称映射、历史包装组安全展开和 NodeId 不变。
- MES 边界测试覆盖“设备根不可配置、下级 DB 可独立配置”。
- 模板测试覆盖空任务不警告且可套用、非空流程继续警告、批量只排除非空流程。
- 运行 Web UI 测试、类型检查、生产构建及相关 .NET 测试。
