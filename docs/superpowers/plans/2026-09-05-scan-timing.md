# 采集与标签扫描耗时

用户需要在监控中心查看设定周期、实际采集间隔和逐次采集耗时，并在自动生成标签时看到扫描进度与耗时。

- 在现有设备读取路径使用单调时钟记录采集批次，区分驱动调用与本地处理；记录成功、部分失败和异常，不改变扫描计划或新增 PLC 请求。
- 每台设备保留最近 200 条内存记录，可按设备和标签查阅。实际间隔为同一读取块的开始到开始间隔；重编译后不同读取块不串用历史。
- 单独增加顶部“采集性能”页面：所有设备概览、设备批次详情和最近缓存平均/最大耗时/慢批次统计，监控中心提供入口。显示当前轮询/订阅模式、有效周期范围、读取块数、最近读取时间。订阅通知不冒充 PLC 往返耗时，记录可用于查看某标签所属批次，但不能声称是单标签独立耗时。
- 自动生成标签窗口显示浏览请求经过时间、完成/失败时间和已有进度信息。修复普通 UDT 父节点不可整体解码时妨碍成员遍历的问题，同时保留 DTL 整体类型识别。
- 验证：可控时钟的统计测试，真实 DeviceLoop 假驱动成功/失败集成测试，REST 查询测试，前端组件行为测试，全量回归、构建、隔离运行和安装包检查。

实施分工：主代理负责核心记录与 REST；前端代理负责监控面板；OPC UA 代理负责浏览回归与扫描 UI。共同工作区按文件边界协作，dotnet 构建串行。
