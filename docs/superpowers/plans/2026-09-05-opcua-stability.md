# OPC UA 性能与稳定性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 完成用户已批准的两批六项优化，减少同 PLC 无效读取和重复建连，保留原有读写、订阅、数组与采集周期语义。

**Architecture:** 运行时按规范化端点、认证、安全、超时及网卡绑定配置共享 OPC UA 连接资源，逻辑设备各自拥有可释放的租约和订阅；同一资源串行建连并统一退避，受限并发调度读写。浏览使用独立的短期会话池，避免长浏览占用采集会话；类型解析失败按节点列出，保留可导入项。单独的无效点策略维护持久节点错误的探测时刻，协议计时区分排队与实际请求。

**Tech Stack:** .NET 10 / OPC Foundation UA SDK / Vue 3 / TypeScript / xUnit / Vitest / Inno Setup。

## Global Constraints

- 用户已经明确授权第一批和第二批全部修改；不再询问是否继续。
- 保留工作区现有改动；不提交、不清理用户文件，不改现场工程。
- 不自动猜测或替换 NodeId，不自动改变配置的采集周期，不把缓存坏值冒充正常值。
- 仅同端点、身份、安全和网卡绑定配置共享连接；不同账号、密码、信任模式、来源网卡严格隔离。
- 释放一个设备不得断开其他租约或订阅；取消一个等待者不得取消其他设备的连接或请求。
- 所有队列、历史和缓存有界，清理取消注册；持续失败统一退避，跨 PLC 互不阻塞。
- 成功采集不增加逐点网络请求；写入、回读校验和订阅仍可正常运行。
- 无效点仅针对明确且连续的 BadNodeIdUnknown；通信错误和普通 Bad 不作为永久地址故障隔离。
- 无效点保留原始坏质量，定期探测，重新配置和恢复后恢复原周期。
- 浏览中的通信失败和取消正常传播；单点不支持类型可列入失败列表，绝不伪造 Double 或零值。
- .NET 构建由主代理统一串行调度，避免共享输出目录竞争；各任务先添加可复现回归测试。
