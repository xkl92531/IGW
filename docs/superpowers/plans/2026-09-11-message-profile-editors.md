# Message Profile Editors Implementation Plan

> For agentic workers: use executing-plans and dispatching-parallel-agents with explicit ownership. User approved gun receive/send and backend input/response editors. No commits. Refresh existing local Docker preview after verification.

**Goal:** Make Open Protocol receive versions/layouts and outgoing messages inspectable, editable and previewable, and expose structured JSON inspection for backend interfaces.

**Architecture:** Driver-owned validated message profiles are authoritative for wire behavior and offline preview. Preserve default revision1 behavior and confirmation/durable ACK ordering. Runtime exposes metadata and pure preview endpoints without network I/O. Web/WPF configure the same serialized device settings. JSON editors retain existing runtime templates/mappings while improving field inspection and editing.

## Contract
- `settings.resultProfile`: optional JSON object `{revision,payloadLength,fields:[{name,dataType,offset,length,scale,required,fixedValue?}]}`; offsets payload zero-based. Missing profile uses legacy standard layout. Canonical result identity/barcode/status/numeric/time fields retain required typed semantics. Fixed-value slices validate labels, not ordinary output fields.
- `settings.sendProfiles`: optional JSON array `{action,revision,payloadTemplate}` for supported existing semantic actions. Profiles cannot bypass result persistence/ACK, barcode confirmation or command serialization. Unknown actions rejected. Frame length/header/NUL generated by driver.
- Catalog GET `/api/v1/open-protocol/messages` and offline POST `/api/v1/open-protocol/messages/preview` use driver APIs; preview body `{settings,direction,action,sample}`. No controller writes in preview.
- Driver agent publishes final typed API/catalog to UI/root before integration. Preserve old customResultFields and existing project defaults.
