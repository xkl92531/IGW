# MES 画布异常可观测与异常中心

## Why

MES 流程画布目前只能看到"流程走到哪了"(节点样式随状态变化),但产线出异常时,用户最需要的三个答案——**哪里有异常、卡在哪个节点、为什么卡住**——现在都要靠人肉扫画布、翻日志才能拼出来。多任务并发异常时(如一台 PLC 离线波及数十个任务)更是无从下手。引擎侧已有节点级状态快照(`MesNodeStatus`:idle/run/wait/ok/fail + Info + AgeMs + Hits),缺的是把"异常"从数据里定义出来并端到用户面前的一整层。这也是对标 KEPServerEX 的差异化优势点:KEP 没有流程编排,此处体验没有对手。

## What Changes

- **卡住判定**(经两轮现场反馈修订定稿):只判**执行停滞**——节点处于 run(上报/回写执行中)超过"单次执行耗时 P95 × 3"(自学习基线,冷启动保护)或手工阈值即判卡;**等待(wait)永不判卡**——等触发/等复位是产线常态,画布只给灰色信息标注(在等什么、差哪个条件),不报警、不进异常中心。
- **条件表达增强**(等待场景多样化):新操作符 `∈任一`(值命中逗号列表任一,同一点不同工况等不同值)与 `变化`(值变化即满足,锁存不丢);条件节点全分支等待时逐分支归因;触发节点条件可在画布直接编辑;节点标注列出全部未命中条件(≤2 行 + 计数)。
- **条件级归因**:节点异常时展示结构化"期望 vs 实际",替代现在的一句话 Info:
  - 触发/握手等待 → 逐条件列出 TagId、比较符、期望值、当前实际值、是否命中(未命中的即"凶手");
  - HTTP 上报失败 → 状态码 + 响应片段 + 已重试次数;
  - 回写失败 → 哪个点写失败 + 读回确认的期望/实际差异。
- **异常中心**:新增常驻监控视图(非弹出物、非横幅),专业化告警管理设计(参考 ISA-18.2):
  - 按 严重度 × 持续时长 × 波及面 排序,不按时间流水刷屏;
  - **根因折叠**:设备离线等根因事件自动折叠其波及的 N 个任务异常为一条(依赖链:条件 TagId / MesTask.DeviceRef / GroupRef → 设备 → ConnectionState);
  - 搜索直达:按设备名/任务名/点位名直接查;
  - 点击条目跳转对应画布并自动平移聚焦到肇事节点、展开归因面板。
- **总览健康色块**:总览页按通道/产线聚合健康状态(绿/黄/红 + 异常计数),点击下钻。
- **画布内异常导航**:异常节点计数徽章 + "下一个异常"循环跳转(类 IDE 的下一个错误),不靠肉眼扫图找红点。
- **执行轨迹回放**:节点级流转事件环形缓冲 + 画布侧边时间线(本轮/上轮:触发→上报→回写各步时刻、耗时、结果),出事后可回答"刚才发生了什么"。
- **明确不做**:横幅式全局通知(多任务并发异常时是纯噪音,已在探索阶段否决)。

## Capabilities

### New Capabilities

- `mes-stuck-detection`: 执行停滞判定——run 状态 P95 自学习基线 + 手工阈值,等待永不判卡;异常状态的定义、进入与解除。
- `mes-anomaly-attribution`: 条件级归因——wait/fail 节点的结构化"期望 vs 实际"数据(逐条件实际值、HTTP 失败详情、回写失败详情)及其在画布上的呈现(含节点就地标注)。
- `mes-flow-conditions`: 条件表达——∈任一(多值)、变化(锁存)操作符,条件节点全分支等待归因,触发条件画布编辑。
- `mes-anomaly-center`: 异常中心——常驻监控视图的排序、根因折叠、搜索直达、跳转聚焦画布。
- `mes-overview-health`: 总览健康聚合——通道/产线级健康色块与下钻导航、画布内异常徽章与循环跳转。
- `mes-flow-timeline`: 执行轨迹回放——节点流转事件采集(环形缓冲)与画布侧边时间线展示。

### Modified Capabilities

(无——本仓库尚无既有 spec,全部为新增能力。)

## Impact

- **后端 `IGW.Northbound.Mes`**:`MesUploadEngine` 的 `NodeRun`/`Mark` 扩展(耗时统计、结构化归因载荷、流转事件环形缓冲);`MesNodeStatus` 快照结构扩展(REST 兼容:新增字段,不破坏现有字段)。
- **后端 `IGW.Northbound.RestApi`**:新增/扩展端点——节点状态快照(含归因)、异常中心聚合查询、流转事件时间线。
- **后端 `IGW.Core`/`IGW.Abstractions`**:根因折叠需要读取设备 `ConnectionState`/`DeviceStats`(已有,只读引用);`MesNode` 可能新增手工阈值字段(序列化进 .igwproj,向后兼容)。
- **前端 `IGW.WebUi`**:`MesFlow.vue` 画布(异常高亮、归因面板、徽章与循环跳转、侧边时间线);新增异常中心视图;`Overview.vue` 健康色块。
- **不影响**:采集引擎热路径、DataHub、驱动层、工程文件既有字段。
