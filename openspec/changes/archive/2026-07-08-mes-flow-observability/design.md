# 设计:MES 画布异常可观测与异常中心

## Context

- 引擎侧 `MesUploadEngine` 已按节点记录运行状态:`NodeRun { State(idle/run/wait/ok/fail), Info(一句话), AtTick, Hits }`,经 `Snapshot()` 输出 `MesNodeStatus(Id, State, Info, AgeMs, Hits)` 供 REST 轮询;`Mark()` 是唯一状态写入口。
- 触发条件求值(`EvalCond`)在任务循环内直接读 `IDataHub` 缓存,逐条件的"当前实际值"在求值现场天然可得,只是现在没被留下来。
- 上报日志已有 SQLite(`MesLog`),但只记上报结果,不记节点级流转。
- 前端 Vue3 + Element Plus;画布在 `MesFlow.vue`(自绘 SVG 画布,节点按状态已有样式差异);`Overview.vue` 为总览页;REST 轮询是既有取数模式。
- 依赖链素材齐备:`MesTask.DeviceRef`/`GroupRef` 指向设备;条件 `TagId` 前缀即 `通道.设备`;`RuntimeEngine.DeviceStatuses()` 给出每设备 `ConnectionState` + `DeviceStats`。

## Goals / Non-Goals

**Goals:**

- 产线异常时,用户在 30 秒内完成:发现(异常中心/总览)→ 定位(跳画布聚焦节点)→ 归因(期望 vs 实际)→ 回溯(时间线)。
- "卡住"有可解释的判定规则:自学习基线打底,手工阈值兜底。
- 多任务并发异常不刷屏:根因折叠,严重度排序。
- 全部向后兼容:REST 只增字段/端点;`.igwproj` 只增可选字段;旧工程无感。

**Non-Goals:**

- 不做横幅/弹窗式全局通知(已否决:并发异常时是噪音)。
- 不做告警历史持久化与确认/搁置(ISA-18.2 的 ack/shelve 生命周期)——v1 异常是"现在时"的实况视图,时间线仅内存环形缓冲。
- 不做邮件/钉钉/webhook 外发通知(留待后续 change)。
- 不改采集引擎热路径、DataHub、驱动层。

## Decisions

### D1 卡住判定:只判执行停滞(run),等待永不判卡(现场反馈两轮修订后定稿)

- **wait 永不判卡**(现场反馈钉死的语义,两轮收敛):等待触发/等待复位是产线常态——"Flag=0"只是这台机还没做完这一件。第一轮修订曾保留"手工阈值可让等待判卡",现场进一步反馈"等待卡住就不需要了"→ 彻底移除:wait 无论等多久、无论是否配手工阈值,一律 `stuck=false`、`baselineMs=0`(也不产生"慢于基线")。画布上等待节点只给中性灰信息标注(在等什么、差哪个条件)。
- **run 才判**:流程中途停滞(上报 HTTP 挂住、回写挂住)是技术异常——引擎为每节点在线学习"单次执行耗时"P95(P² 算法,O(1) 内存,样本 = run→ok/fail 毫秒数),run 持续超过 `P95 × 3` 判卡;样本 < 20 不生效(冷启动不误报);手工阈值仅作用于 run 且优先。
- 策略收敛在 `StuckMath.Evaluate` 一处(非 run 直接 false),快照层无特判分支。
- 触发间隔(GapP95)照采不判,留给后续"常态节奏"就地展示。
- 手工阈值:`MesNode` 可选字段 `StuckThresholdMs`(0/缺省 = 仅自动),序列化进 `.igwproj`,向后兼容。
- **备选方案**:固定全局超时——被否:注塑 30s 和化成 4h 没有共同常数;触发间隔自动判(初版)——被否:现场明确"等待不是异常";等待手工阈值(第一轮修订)——被否:现场确认连这个都不要,等待语义必须纯粹。

### D2 条件级归因:Mark 增加结构化 Detail,求值现场捕获实际值

- `NodeRun` 增加 `volatile object? Detail`(不可变 record,整体替换,读侧无锁):
  - `WaitDetail { Conds: [{ TagId, Op, Expect, Actual, Met }] }` —— 触发/握手/条件节点 wait 时,求值现场顺手把每条件实际值填进去(`EvalCond` 处已读到值,零额外 Hub 查询);
  - `HttpFailDetail { StatusCode, BodySnippet(≤512字符), Attempt, Url }`;
  - `WriteFailDetail { TagId, Written, ReadBack, Attempt }`(读回确认差异)。
- `MesNodeStatus` 快照增加 `Detail`(JSON 多态,`kind` 字段区分),旧字段不动;前端按 kind 渲染归因面板。
- **备选方案**:把归因塞进 Info 字符串拼接——被否:前端没法结构化渲染"凶手条件高亮",也没法做搜索。

### D3 异常中心:REST 按需聚合,不建持久告警状态机

- 新增 `AnomalyService`(RestApi 层,纯读):每次查询时扫 `MesUploadEngine.Snapshot()` + `RuntimeEngine.DeviceStatuses()`,现算异常清单。1–2s 轮询、任务量级几百,现算成本可忽略;不引入新的常驻状态,不引入新存储。
- **根因折叠**:两遍算法——第一遍收集设备级根因(`ConnectionState != Connected` 的设备);第二遍把任务/节点异常归属到设备(归属键:节点等待条件的 TagId 前缀 → `通道.设备`,以及 `MesTask.DeviceRef`),命中根因设备的折叠为其子项,其余为独立条目。
- **排序键**(高→低):严重度类别(设备离线根因 > 节点 fail > 节点 stuck > 慢趋势)→ 波及任务数 → 持续时长。同类内不按发生时间排——流水序就是刷屏的根源。
- **实现修订(E2E 发现)**:节点失败后进入重试窗口(state=run)期间,快照瞬时状态不是 fail,异常条目会闪烁消失。补充规则:`FailStreak > 0 且 state∈{run,wait}` 视为"仍在失败"(快照新增 FailStreak 字段;重试期间保留上一次失败归因不清空)。
- **严重度颜色语义**(ISA-18.2 精神,全站统一 token):红=已失败/根因离线,橙=卡住,黄=慢于基线,灰=信息。红只留给"需要现在处理"的条目,防告警疲劳。
- 搜索:异常中心顶部单框搜索,后端对 设备名/任务名/节点标题/TagId 做 contains 匹配(数据量小,前端过滤亦可,定后端过滤是为了将来加历史时不用改交互)。
- 跳转聚焦:异常条目携带 `(taskId, nodeId)`,前端路由跳 `MesFlow` 并把画布平移/缩放到该节点、自动展开归因面板。
- **备选方案**:后台常驻告警评估器 + 事件表——被否:v1 不需要 ack/历史,常驻状态机是把简单事做复杂。

### D4 执行轨迹:每任务内存环形缓冲

- `Mark()` 在写状态的同时追加流转事件 `(nodeId, state, info, tick, durMs)` 到该任务的环形缓冲(固定 256 条,数组 + 头指针,零分配增长)。
- REST 新端点按任务返回最近事件;前端画布侧边栏渲染成时间线(按轮次分组:从 Trigger ok 到下一次 Trigger ok 为一轮)。
- 不落 SQLite(v1):内存回放已覆盖"刚才发生了什么";持久化留给引入告警历史的后续 change 一起做。

### D5 前端信息架构:三层入口,一套颜色

```
监控中心 /monitor(顶部=通道健康色块条,下方=异常工作队列)
   色块点击 → 按通道过滤异常清单(同页下钻)
   条目点击 → MesFlow 画布(自动聚焦肇事节点 + 归因面板 + 侧边时间线)
画布内:右上角异常徽章(N),点击在异常节点间循环跳转(类 IDE F2)
```

- **实现修订**:原方案的 Overview 页在当前路由中已下线(/overview 重定向到 /project),健康色块改放监控中心视图顶部——同一屏完成"扫一眼 → 下钻",少一次跳转,行为满足 mes-overview-health 规格。
- 异常中心为独立路由视图(非抽屉/弹窗),可常驻大屏。
- 色 token 定义在全局样式一处,画布节点态、色块、异常中心行、徽章共用——"专业化"的第一要义是全站语义一致。

## Risks / Trade-offs

- [P95 自学习在节奏多变的产线误报] → 阈值取 P95×3 放宽 + 手工阈值优先 + 黄色"慢于基线"与橙色"卡住"分级,误报先落黄色不惊扰。
- [触发间隔基线对本来就稀疏的任务(一天触发一次)无意义] → 样本 < 20 不生效;此类任务只认手工阈值;文档明示。
- [Detail 结构化载荷增大快照体积] → BodySnippet 截断 512 字符;Detail 只在非 ok 状态携带;任务×节点量级(百级)下 JSON 尺寸无虞。
- [根因归属推理错误(TagId 前缀不规范/跨设备条件)] → 归属不到设备的异常独立展示,宁可不折叠也不折错;折叠条目展开后仍可见全部子项。
- [环形缓冲重启即失(内存态)] → v1 接受;界面标注"最近 256 条(自启动)";持久化在后续 change。
- [MesFlow.vue 已 57KB,再堆功能可维护性恶化] → 归因面板/时间线/异常中心拆为独立组件文件,画布只留挂载点。

## Migration Plan

1. 后端先行(基线统计、Detail、环形缓冲、REST 端点)——全部增量,REST 旧字段不动,可独立发版;
2. 前端随后(异常中心视图 → 画布聚焦/徽章/面板/时间线 → Overview 色块),逐视图合入;
3. 回滚:前端视图可整体隐藏;后端新字段无消费者时是死代码,无需数据迁移。
