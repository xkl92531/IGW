# 设备模板化配置与批量实例化

## Why

IGW 对标 KEPServerEX 并以"人性化 + 支撑单机百万点"为目标。现场的真实形态是:一个项目里有大量"大同小异"的设备(同机型 PLC 程序相同、少数点位有差异),而当前配置方式只有逐设备手工建点。这带来两个天花板:配置 2000 台设备是不可能完成的人工任务;点定义在 `.igwproj` 里逐点展开,规模上去后工程文件与浏览器端都会被体积压垮。KEP 的"复制设备/CSV 导入"复制完即与源断开关系,改一处要改全场——"模板-实例保持关联"正是拉开差距的机会。

## What Changes

- **提取模板**:任意已配好的设备可一键"提取为模板"(带走点位、分组、扫描率、缩放等全部定义);模板由项目工程师自己"长"出来,产品不预置、不强制。
- **套用模板**:新建设备 = 选模板 + 填端点(IP/站号等),立即可用;一个模板可套用到任意多台设备,模板与实例保持关联。
- **自动匹配验证**:套用后立即自动验证并出报告——可浏览驱动(OPC UA/EtherNet-IP)连真机浏览地址空间、按点名/路径匹配(✔已对上 / ⚠真机缺失 / ✚真机多出可一键收编);不可浏览驱动(Modbus/三菱等)按模板地址发起一轮试读(✔读通 / ✘超时或异常,失败点高亮可当场改)。
- **实例差异(delta)管理**:实例相对模板支持 覆盖(地址/扫描率/缩放)、追加专有点、屏蔽模板点;修改模板全体实例跟进且不冲掉各自差异;实例带"与模板差异 N 处"徽章,可查看 diff、可一键还原。
- **Excel/CSV 批量实例化**:导入设备清单(设备名/端点/模板名/可选差异列)一次生成成百上千台设备。
- **运行时展开**:工程文件只存 模板 + 实例引用 + 差异,点位在加载/热重载时于内存展开——工程文件体积与设备数解耦(百万点工程文件仍是 MB 级),这是后续单机 1M 数据面的前置地基。
- **手工路径不变**:不使用模板的设备照旧逐点手工配置,两种方式在同一工程内共存。

## Capabilities

### New Capabilities

- `template-extract`: 从已配置设备提取模板(内容范围、命名、与源设备的关系)。
- `template-apply-match`: 套用模板建设备与套用后的自动匹配/试读验证报告。
- `template-instance-delta`: 实例差异模型(覆盖/追加/屏蔽)、模板修改传播、diff 展示与还原。
- `template-bulk-instantiate`: Excel/CSV 设备清单批量实例化(格式、校验、错误报告)。
- `template-storage-expansion`: 模板与实例引用的工程文件存储、运行时点位展开与热重载语义。

### Modified Capabilities

(无——本仓库尚无既有 spec,全部为新增能力。)

## Impact

- **`IGW.Abstractions` 工程模型**:`IgwProject` 新增 `Templates`;`DeviceDef` 新增模板引用与差异(全部可选字段,旧工程兼容)。
- **`IGW.Core`**:`ProjectStore.Validate` 扩展(模板名唯一、引用存在、差异指向的模板点存在);运行时展开器(模板+差异 → 有效 DeviceDef);`RuntimeEngine.DeviceSig` 必须把所引用模板内容纳入签名(改模板 → 相关实例热重载)。
- **`IGW.Northbound.RestApi`**:新增 提取模板/套用/匹配报告/试读报告/清单导入 端点。
- **`IGW.WebUi`**:`Project.vue` 增加模板管理、套用向导、差异徽章与 diff 视图、导入向导(新逻辑拆独立组件,避免继续膨胀单文件)。
- **引擎复用**:自动匹配复用现有 `IBrowsableDriver.BrowseAsync`;试读复用现有设备读路径,不新增驱动接口。
- **不影响**:采集热路径、DataHub、驱动实现、既有手工配置流程。
