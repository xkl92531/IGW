# 设计:设备模板化配置与批量实例化

## Context

- 工程模型:`IgwProject → Channels → Devices → Tags/Groups`(`IGW.Abstractions/ProjectModel.cs`),整棵树 JSON 序列化为 `.igwproj`(`ProjectStore`),经 `PUT /project` 全量提交、`RuntimeEngine.ApplyAsync` 按设备签名(`DeviceSig` = 驱动+通道设置+设备完整定义 的哈希)增量热重载。
- 点位绑定在设备启动时完成(`BindDevice`:遍历 DeviceDef 的 Tags/Groups → `TagBinding`),下游(DataHub 注册、扫描组、写映射)只认展开后的绑定,不关心点定义从哪来——这是"运行时展开"能低侵入落地的关键。
- 浏览能力已有:`IBrowsableDriver.BrowseAsync`(OPC UA / EtherNet-IP);一次性读一组点的能力也已有(设备读路径)。
- 前端 `Project.vue` 已 133KB(通道/设备/点位树全在一个文件),本 change 新 UI 必须拆组件。
- 本 change 同时是「单机 1M 数据面」的前置:工程文件体积与设备数解耦后,配置层不再是规模墙。

## Goals / Non-Goals

**Goals:**

- 配 2000 台同类设备的工作量 ≈ 配 1 台 + 一张清单;改 2000 台的同一个点 ≈ 改一次模板。
- 套用即验证:套完立刻知道每个点"活没活",不用另开工具逐点戳。
- 差异是一等公民:覆盖/追加/屏蔽,可视、可 diff、可还原,模板更新不冲掉差异。
- 全向后兼容:旧工程零改动可加载;不用模板的用户感知不到模板存在。

**Non-Goals:**

- 不做跨工程共享的"模板市场/中央模板库"(v1 模板随工程文件走;导出/导入单个模板 JSON 作为轻量补充)。
- 不做模板嵌套/继承(模板套模板)——现场需求未证实,先保持一层。
- 不做通道级模板(通道数量少,手工可承受);模板绑定驱动类型,套用时通道需同驱动。
- 不改驱动接口、不改采集热路径。

## Decisions

### D1 数据模型:模板 + 实例引用 + 差异,实例不落全量拷贝

- `IgwProject` 新增 `Templates: List<DeviceTemplate>`;`DeviceTemplate { Name(工程内唯一), DriverId, Tags, Groups, DefaultSettings }`——点位结构复用现有 `TagDef/TagGroupDef`,不引入平行类型。
- `DeviceDef` 新增可选字段:`TemplateRef(模板名)` 与 `Delta`:

```
Delta {
  Overrides: [ { Path("组.子组.点名"), Address?, ScanRateMs?, Scaling?, ... } ]   // 只存改了的字段
  Adds:      [ TagDef/组内追加(带目标组路径) ]
  Masks:     [ Path ]                                                             // 屏蔽模板点
}
```

- **备选方案**:套用时把模板全量拷贝进 DeviceDef 并记 origin 链接——被否:工程文件体积不降(1M 点又回来了),且"模板改动传播"退化成猜 diff;KEP 的复制断链正是要避开的坑。

### D2 运行时展开:纯函数,落在绑定之前

- 新增展开器 `TemplateExpander.Expand(template, device.Delta) → 有效点位集`,顺序:模板点集 → 应用 Overrides → 剔除 Masks → 合入 Adds。
- 接入点:`RuntimeEngine.StartDevice/BindDevice` 之前把"模板引用设备"展开为有效定义;下游一切(绑定、DataHub 注册、扫描组、MES GroupRef 路径)不感知模板存在。TagId 路径规则不变(`通道.设备.组.点`)。
- 校验(`ProjectStore.Validate` 扩展):模板名唯一;`TemplateRef` 指向存在的模板且驱动与通道一致;Override/Mask 的 Path 在模板中存在(不存在 → 校验警告,展开时忽略);Add 与模板点同名 → 校验错误。
- **备选方案**:保存时物化展开进 `.igwproj`——被否:体积不降、模板改动要重写全部实例,失去单一事实源。

### D3 热重载签名:模板内容纳入设备签名

- `DeviceSig` 对模板引用设备改为:`hash(驱动 + 通道设置 + 模板内容 + 实例端点/设置 + Delta)`。改模板 → 所有引用实例签名变化 → `ApplyAsync` 只重启这些设备,且差异保留(Delta 在实例上,不在模板里)。
- 风险应对:改一个 2000 实例的模板会触发 2000 台同时重连,现有连接退避已带 ±30% 抖动;Apply 侧再按批分组启动(如每批 100 台、间隔百毫秒级)防重连风暴。

### D4 套用验证:统一"验证报告"抽象,两种驱动两条实现路径

- 套用(或批量导入)保存并热重载后,针对目标设备发起验证作业,产出统一结构的报告:每点 `{ Path, Address, Result(matched/missing/extra/readOk/readFail), Detail }`。
  - **可浏览驱动**:`BrowseAsync` 拉真机地址空间,按 点名/路径 与模板点匹配:✔matched / ⚠missing(模板有真机无)/ ✚extra(真机有模板无,报告里可勾选一键收编为该实例的 Adds);
  - **不可浏览驱动**:对展开后的全部点做一轮真实试读(复用设备读路径,块合并天然生效):✔readOk / ✘readFail(带错误摘要)。
- 验证是异步作业(设备多、点多时耗时秒级~分钟级):REST 发起 + 轮询进度/结果;报告不持久化,内存保留最近 N 份。
- **备选方案**:套用前(设备未入工程)临时建连接验证——被否:要为"临时设备"另造一条驱动生命周期,复杂度高;先套用后验证与"试读报告当场改"的交互天然契合。

### D5 批量导入:CSV 先行,原子提交

- v1 支持 CSV(UTF-8,提供可下载的样例模板文件),列:`设备名, 通道, 模板名, 端点, [设备设置列...]`;Excel 用户可另存 CSV,xlsx 解析(引第三方库)留待需求证实。
- 服务器端解析+全量校验(重名/通道存在/模板存在/端点格式),**全部通过才写入工程**(原子);任何行失败返回逐行错误报告(行号+原因),不做半截导入。
- 导入产物 = 普通的模板引用设备,后续差异/验证与手工套用完全一致。

### D6 前端信息架构:模板是 Project 视图的平级板块,新 UI 全部拆组件

```
Project 视图
 ├─ 通道/设备树(现有)
 │    └─ 设备节点:「与模板差异 N 处」徽章 → diff 面板(逐条 覆盖/追加/屏蔽,可单条还原/整体还原)
 │    └─ 设备右键:「提取为模板」
 ├─ 模板管理板块(新):模板列表、编辑(复用点位编辑组件)、导出/导入单模板 JSON
 └─ 「批量导入」入口:上传 CSV → 校验报告 → 确认 → 验证作业进度 → 验证报告
套用向导(新建设备时):选模板 → 填端点/设置 → 保存并验证 → 报告页(missing/extra/readFail 高亮,extra 可勾选收编)
```

- 所有新界面为独立 `.vue` 组件文件,`Project.vue` 只加挂载点——不再向 133KB 单文件堆代码。

## Risks / Trade-offs

- [模板点重命名会使实例 Delta 的 Path 悬空] → 语义定为"改名 = 删旧加新";校验把悬空 Override/Mask 报为警告并在展开时忽略;diff 面板明示"已失效差异"供用户清理。
- [改模板批量重启引发重连风暴] → Apply 分批启动 + 既有退避抖动;UI 在应用前提示"将重启 N 台设备"。
- [试读验证对大实例(500 点)耗时] → 复用块合并整块读,单设备一轮通常亚秒~数秒;作业异步化+进度上报,不阻塞保存。
- [CSV 编码/方言(逗号、分号、BOM)踩坑] → 只承诺 UTF-8 + 样例模板;解析失败给行级错误而非整体拒绝无说明。
- [模板功能让小项目界面变复杂] → 模板板块无模板时呈折叠空态;不建模板时所有既有流程零变化(Goals 兜底)。
- [`PUT /project` 全量提交模式在模板场景放大并发覆盖风险(两人同时编辑)] → v1 沿用现状不解决多人并发,风险记录在案;工程文件体积已解耦,提交体积不再随设备数增长。

## Migration Plan

1. 模型与展开器先行(Abstractions/Core:字段、Validate、Expander、DeviceSig),旧工程无新字段走原路径,可独立发版;
2. REST 端点(提取/套用/验证作业/导入)随后;
3. 前端最后(模板管理 → 套用向导+验证报告 → diff 徽章 → CSV 导入),逐组件合入;
4. 回滚:新字段无消费者即死数据;含模板的工程文件降级到旧版本会丢模板语义——发版说明明示"用了模板的工程不可回退旧版打开",这是唯一的单向门。

## Open Questions

- xlsx 直接解析是否必要(引 ClosedXML 之类依赖)?——等第一批现场反馈,CSV 若够用则不引。
- 模板导出/导入 JSON 是否要带版本号与兼容校验?v1 先做最简(原样 JSON),跨版本兼容留给模板库需求一起考虑。
- 「一键收编 extra 点」收进 Delta.Adds 还是提示"更新模板本体"?v1 收进实例 Adds(保守,不波及他机);"反向合入模板"作为 diff 面板的后续增强。
